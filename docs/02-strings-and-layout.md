# 机械层 · 字符串表与数据段布局

> 由 `tools/rich4strings.py` 从 `../Rich4/rich4.exe` 机械生成，**不含推断**。
> 重建：`python3 tools/rich4strings.py build`

## 一、为什么字符串表是重要证据

原版把**全部 UI 文本、角色台词、事件名、卡片与道具说明**以 Big5 字符串
内嵌在 **DGROUP** 里（代码段的那 4,031 条是假阳性，见 §二）。它们有两个不可替代的用途：

1. **语义定位**：一条字符串被哪个函数引用，基本就说明了那个函数的用途。
   实测样例（`gen/string-xrefs.json`）：

   | 函数 | 引用的字符串 | 由此可判定 |
   |---|---|---|
   | `0x0042b58f` | 持有股數表 / 股價表 / 股票名稱 / 成交價 | **股市屏绘制** |
   | `0x004284be` | 股票名稱 / 持有張數 / 總市價 / 類型： | **持股明细屏** |
   | `0x00417e26` | 現金 / 存款 / 總資產 / 土地 | **总资产汇总** |
   | `0x0041e345` | 個性 / 資金運用比例 / 使用卡片 / 乖寶寶 | **AI 個性设置屏** |
   | `0x00437e34` | 本月悲情人物 / 獲獎原因 / 本月意外損失 | **月度颁奖** |
   | `0x0045011a` | 錯誤 / 找不到光碟機！ / DATA.MKF | **资源加载失败提示** |

   ⚠️ 这些判定仍属 **B 级**（由字符串推断语义），但比纯猜测强得多，
   且给出了**验证入口**：去 `0x42b58f` 反汇编即可确认是不是股市屏。

2. **逐字对齐**：复刻时 UI 文本必须与原文一致，字符串表给出了权威来源。

## 二、规模（实测）

| 项 | 数量 |
|---|---|
| 字符串总数 | **7,146** |
| 其中含中文 | **6,388** |
| 代码段（`AUTO`）内 | **4,031** —— ⚠️ **不可信，见下** |
| 数据段（`DGROUP`）内 | **3,115** —— ✅ 游戏真字符串 |
| **被指令直接引用** | **342**（重建后计数） |

### ★★ 必读陷阱：`AUTO` 段的 `text` **不是文本真值**

`gen/strings.json` 的每一条都带一个 **`trusted`** 字段，**用之前必须先看它**：

| `sec` | `trusted` | 含义 |
|---|---|---|
| `DGROUP` | ✅ `true`（3,115 条） | 数据段里的 NUL 结尾串 —— **就是游戏真字符串** |
| `AUTO` | ❌ `false`（4,031 条） | **代码段**里「一段以 NUL 结尾、恰好能被 Big5 解码的字节」——**绝大多数是乱码** |

**实测**：`AUTO` 的 4,031 条里有 **3,209 条含 CJK**，但它们是这种噪声：

```
0x00401061  '9黷!鷖'
0x004010c9  '諿1骼︾qI'
0x00401107  '$鷖'
0x00401496  '鱹F'
```

它们只是**机器码字节被动解成 Big5**，与游戏文本毫无关系。

> ⚠️ **把 `AUTO` 段的 `text` 当文本真值，会直接往规格里灌乱码。**
> 本项目的 UI 标签表、台词表、卡名表**全部**在 `DGROUP`（`0x463000..0x489bff`），
> 指针也都在 `DGROUP`，所以**只取 `trusted == true` 的条目**永远不会漏掉真字符串。
>
> 复现判据（`tools/rich4strings.py` 的 `extract_strings`）：
> `"trusted": name == "DGROUP"`。**不要**用「能不能被 Big5 解码」当有效性判据 ——
> 代码段的字节几乎总能被 Big5 解码（双字节范围很宽）。

### ⚠️ 为什么只有 342 条被"直接引用"

字符串的传址方式有三种，只有前两种能被静态追溯：

| 方式 | 可追溯 | 例子 |
|---|---|---|
| 立即数传址 | ✅ | `push 0x4630f4` |
| 绝对内存寻址 | ✅ | `mov eax, [0x4630f4]` |
| **基址 + 偏移 / 指针表间接** | ❌ | `lea eax, [ebx + ecx*4]`，基址来自别处 |

第三类是**指针表**（如 `card_functions` 旁边的名字指针表）：表里存的是
字符串 VA，代码通过表间接取用，静态无法把「哪个函数用了哪条串」关联起来。

> 这意味着：**"没被引用"不等于"死字符串"**。剩余 6,806 条多数通过指针表使用。

### 已定位的字符串表（可交叉验证）

| 字符串 | VA | 说明 |
|---|---|---|
| `均富卡` | `0x465f53` 与 `0x466ac2` | **两份表**（卡片数据表 + 帮助表） |
| `免罪卡` | `0x465f45`、`0x466b4e` | 同上 |
| `免罪卡生效！` | `0x4653a1` | 台词/提示，独立一条 |

## 三、数据段布局

`gen/layout.json` 把 `DGROUP`(158,720 字节) 与 `.bss`(64,512 字节)
切成 **2,349 个区间**，每段标注类型：

| 类型 | 区间数 | 判据 |
|---|---|---|
| `data` | 1,270 | 其余非零数据 |
| `string` | 910 | 落在字符串字节范围内 |
| `table:data` | 104 | 连续 ≥2 个 dword，值指向**数据段** |
| `table:code` | 64 | 连续 ≥2 个 dword，值指向**代码段**（跳表/函数指针表） |
| `bss` | 1 | `.bss` 未初始化区 |

> **注意**：`table:code` 有 64 段，其中大部分是**栈上的跳转表引用**或
> 函数指针表。这与 `gen/jumptables.json` 的 69 个跳表**不是同一集合**——
> 前者是"内存里看着像指针表的连续 dword"，后者是"被 `jmp [reg*4+table]`
> 实际引用的表"。两者**互相印证但不重合**，交叉比对可发现遗漏。

## 四、产出文件

| 文件 | 内容 |
|---|---|
| `gen/strings.json` | 7,146 条：VA、所在节、文本、字节数 |
| `gen/string-xrefs.json` | 342 条被引用字符串 → 引用它的函数与指令 |
| `gen/layout.json` | 2,349 个数据段区间：VA、大小、类型、表项数 |

### 用法

```bash
python3 tools/rich4strings.py find 均富        # 按文本搜索
python3 tools/rich4strings.py refs 0x465f53    # 谁引用了这条串
```

```python
# 用字符串表反查某函数的用途
import json, collections
x = json.load(open("gen/string-xrefs.json"))
s = {d["va"]: d["text"] for d in json.load(open("gen/strings.json"))}
target = 0x42b58f
print([s[int(va)] for va, refs in x.items()
       if any(r["func"] == target for r in refs)])
# → ['持有股數表', '股 價 表', '股票名稱', '成交價', ...]  即股市屏
```

## 五、已知局限

1. **基址+偏移 / 指针表间接的字符串引用无法静态关联**（剩余 6,806 条），
   这是本文件的**主要局限**。要覆盖它们需模拟指针表解引用，
   或在实际运行时插桩观察。
2. 纯 ASCII 短串（<4 字符）已过滤，可能漏掉个别有意义的短标签。
3. `layout.json` 的区间切分是**启发式**（见上表判据），
   边界处的 `data`/`table` 判定可能有 ±1 项的偏差，使用前应抽查。
