## 二、三条铁律

1. **凡 Logic 类结论，必须给 `@source VA`（原版虚拟地址）**，不接受只写「见某 C 文件」。
   本目录的 `gen/functions.json` 提供了全部 3212 个函数的地址索引，可直接引用。
2. **C 与汇编冲突时，一律以汇编/exe 为准。**
3. **数值表必须以 exe 二进制为基准做常驻测试**，不允许人工转录后无校验
   （历史上正是转录引入了错误）。

## 三、诚实边界：汇编能给什么，给不了什么

写规格必须区分下面两类问题。**混淆二者是本项目最大的方法论风险。**

### ✅ 可从汇编精确得到（本目录负责）

- 精确公式、整数除法与取整语义、x87 浮点精度路径
- 条件判定的**顺序**（顺序常常改变结果）
- 全部常量与查找表、跳表结构
- 数据结构布局、字段读写者（xref）
- PRNG 算法（位级可复现）
- 分支可达性

### ❌ 汇编给不了（必须靠实机观测）

- **表现层观感**：动画时序、连续插值、blit 合成顺序、鼠标反馈。
  汇编只给出**参数**，不给观感。这类问题一律以 `../rich4-remake/docs/original-screens.md`
  的实机截图与自动化截图比对为准。
- **语义命名**：指令只说明「做了什么」，不说明「为什么」。
  已踩过的坑：`0x44ef41` 形如 `update_hostility`，实为 `player_say`（查表取台词指针）。
  **凡「查表 + push + call」的形状，必须解引用验证后再下结论。**

### 子代理的结论要分级对待（本轮的经验）

并行子代理产出的结论**不是同等可靠**。本轮实测：

| 类型 | 实例 | 结果 |
|---|---|---|
| **表结构/地址类** | 「魔法屋记录基址是 `0x47571C`，不是 `0x475724`」 | ✅ **对**，已改正（我原先按错基址得出"11 项"，实为 12 项） |
| **"上游 asm 有错"类** | 「`0x44760f` 漏指令」 | ✅ **对**（该 VA 不是指令边界） |
| **"本工具算错了"类** | 「`rich4dis.py` 把 `0x40ea90` 的 `jne` 渲染成 `0x40ea92`，真值 `0x40ea97`」 | ❌ **错** —— 实测我的工具在 `0x40ea90` 正确渲染 `0x40ea97`；子代理把 `0x40ea8b`（目标 `0x40ea92`）与 `0x40ea90`（目标 `0x40ea97`）两条 `jne` 弄混了 |

**规律**：子代理在**它逐字节读过的东西**上很可靠（表内容、指令边界）；
但在**转述工具行为**时容易出错，因为它把"我读到的"与"工具输出的"混在一起。

**纪律**：凡子代理报告"上游/工具/文档有错"，**先按其给出的 VA 亲自复核一遍**
再决定是否改。改动机械层尤其要这样 —— 机械层是下游一切的基准。

## 四、工具

```bash
# 机械层：递归遍历反汇编器（本目录）
python3 tools/rich4dis.py info               # 段信息 + 函数指针表
python3 tools/rich4dis.py func 0x40df69      # 反汇编一个函数
python3 tools/rich4dis.py build --orphans    # 重建 gen/*.json
python3 tools/rich4dis.py boundaries         # 覆盖率与边界冲突体检
python3 tools/rich4dis.py gaprefs            # 未覆盖区「有没有指令指向」
python3 tools/rich4dis.py tail --orphans     # 剩余部分的精确归因（填充/不可达/数据）

# 按需裁决（沿用 ../rich4-remake/tools/disasm.py，方法正确）
python3 ../rich4-remake/tools/disasm.py callers 0x40df69   # 谁调用了它
python3 ../rich4-remake/tools/disasm.py xref cash          # 谁读了/写了 player.cash
python3 ../rich4-remake/tools/disasm.py card 1             # 第 N 张卡的全部状态写入
```

两个工具是**互补**关系：`disasm.py` 按需裁决、每条查询独立对齐；
`rich4dis.py` 全量建图、产出索引。后者解决「这东西在哪」，前者解决「这条具体怎么算」。

## 五、规格文档模板

```markdown
### <机制名>

**结论**：一句话说清行为。

**精确规则**：公式 / 分段 / 查表，逐条列出，含取整与溢出语义。

**边界情况**：表格列出所有特殊分支与优先级顺序。

**@source**：`VA 0x00442f4d`（证据级别 A/B）+ 关键指令摘录。

**未决**：明确写「未知」，不要用推测填充。
```

## 六、为什么不做「逐条读完再写一份大文档」

那是**无界**的：永远还剩边界情况，且人工转录会引入错误（已 8 例）。
本项目的做法是：

1. **机械层**产出可机械校验的索引（函数清单/调用图/xref/跳表）——
   这一步**不含任何推断**，因此不会错。
2. **语义层**只写**稳定契约**（公式、表、优先级），每句带 VA。
3. **剩余未知**不靠文档消灭，而靠**两条廉价通道**回答：
   查索引定位，或跑差分测试比对原版。
   见 `docs/verification.md`。
