### 诚实边界

- 汇编能给出：公式、取整方向、判定顺序、常量、表、字段读写者。

  以及某些字段的**业务命名**（例如 `player+0x4c` 的成对表到底叫「敌意」还是「欠款」，本文件标为线索而非结论）。

## 一、前置：玩家结构、日期、回合、金钱（四节共用）

### 1.1 玩家结构 `player[8]` @ `0x496b68`，步长 `0x68`

### 1.2 两个 8 字节旗标数组

| 全局 | 含义 | 证据 |
|---|---|---|
| `0x496b30 + player` | `in_prison_flag[8]`（0..7，含 NPC） | `0x43d674` 置 1、`0x43d577` 清 0、`0x43d318` 扫描 |
| `0x496b60 + player` | `in_hospital_flag[8]` | `0x43ed20` 置 1、`0x43ec23` 清 0、`0x43eb3d` 扫描 |

两个数组都是**按玩家编号直接索引**（NPC 4..7 落在 0x496b34 / 0x496b64 起，
即「`0x496b30+4`」＝同一数组的高 4 项；`0x43d7b3 mov byte [eax+0x496b34],1` 就是 NPC 情形 `eax = player-4`）。

### 1.3 日期 `0x497160` 与「天/月」推进

- 日期打包 = `(year<<16) | (month<<8) | day`：
  `0x452117` 拆包（`shr ebx,0x10` / `shr ecx,8; and 0xff` / `and edi,0xff`），
  并用 `[ecx+0x47638f]` 的表取当月天数（闰年 2 月特判 `idiv 4` → `0x1d`＝29）。
- 推进：`0x41cf9c push 0x497160; call 0x452117`（`date++`，返回值＝1 表示**跨日/跨月**）。
- `0x497160` 在开新档时由系统时间或一个日期回调写入：
  `0x411a7c`（来自 `Wait_0402_Message(0,0x410ac3)` 的返回值）、`0x411acf`（打包系统时间，`0x458331`→`[0x4623b0]`）。
- **回合 ↔ 天**：`0x418ebd`（换人）在轮到玩家 0 时置 `ebx=1`（`0x418fc3`），
  然后 `0x41902e test ebx,ebx; je …; call 0x41cf67` → **每个玩家各行动一次（一整圈）＝游戏日期 +1 天**。

### 1.4 每月两个固定结算日（本文件的时间轴支点）

`0x41cf67`（每日推进函数，唯一调用点 `0x41902e`）内：

| 触发条件 | 汇编 | 结论 |
|---|---|---|
| 日期跨到 1 号（`date_increment` 返回 1） | `0x41d099 cmp edi,1; 0x41d09c jne 0x41d0ff; 0x41d09e call 0x439bfa` | **每月 1 日：银行结算（含存款利息）** |
| `(date & 0xff) == 15` | `0x41d085 and eax,0xff; 0x41d08a cmp eax,0xf; 0x41d08d jne; 0x41d08f call 0x42ba97; 0x41d094 call 0x431712` | **每月 15 日：上市公司分红 `0x42ba97` ＋ 乐透开奖 `0x431712`** |

- `0x439bfa` 是每月银行结算的入口（加载面板 `0x19`，把在场玩家填进 `0x48c418/0x48c420`，
  字串 `0x464d58`「各位客戶辛苦了！又到了每月銀行結算的日子。」）。
- `0x42ba97` 是「上市公司分紅」结算（列名 `0x464168`「上市公司分紅」、`0x464103`「本月盈餘」、
  `0x46417f`「紅　利」、`0x464190`「%d張」＝持股张数），把企业盈余按持股比例打入**银行存款**。

### 1.5 金钱原语（银行/乐透/保释都用）

| 函数 | 签名（实参顺序） | 语义 | 证据 |
|---|---|---|---|
| `0x41d2c6` | `(payer, payee, amount, flags)` | 转账。`payer > 0x64` ⇒ 企业（索引＝`payer-0x64`，扣 `+0x28/+0x2c`）；否则玩家：`flags&4`＝从存款扣，否则从现金扣（不足则互转、再不足 ⇒ `0x40cd87` 破产）。`payee == -1` ⇒ 金额进全局池 `0x499080`；`payee > 0x64` ⇒ 企业收；否则玩家收（`flags&1`＝现金，否则存款），并累计 `+0x60` | A `0x41d2d6`…`0x41d3d0` |
| `0x41d3f4` | `(player, amount, flags)` | 给钱。`flags&1` ⇒ `cash += amount`，否则 `bank += amount`；`+0x60 += amount`；当前玩家则刷新面板 | A `0x41d400`…`0x41d42e` |
| `0x41d2c6` 的 payer 侧 | — | 现金不足自动从存款补、再不足按 `ebx` 破产 | A `0x41d33d`…`0x41d376` |
| `0x40cd87` | `(player)` | **破产/退场**：`who_plays(0x15)==0` 则直接返回；否则把 `player+0x1c` 起共 `0x68-0x1c` 字节**清零**，置 `who_plays=0`，并对 `[char+0x4990f4]=2` | A `0x40cd9b`…`0x40cf2f` |
| `0x40df69` | `(a, b, delta)` | 成对表 `a*0x68 + b*4 + 0x496bb4` `+= delta`，结果负数夹 0（`0x40df83` 若原值为 0 则跳过；`0x40dfad` 夹 0） | A `0x40df77`…`0x40dfd7` |
| `0x440cac` | `(msg, duration_ms)` | **纯展示**：弹提示框，显示 `msg` 与时长 `duration_ms` 毫秒后关闭。**不扣钱**（时长经 `0x4528b9`＝延时循环确认） | A `0x440de7`→`0x4528b9`（内部两次 `[0x46246c]` 取时并循环） |

> ⚠️ 上游把 `0x440cac` 的第二个实参当成「金额」。**它是毫秒**。
> 因此「保釋＝1500 元」「銀行拒絕往來＝1000 元」这类读法都是错的：
> 金额若出现，是写在 `msg` 文本里的（如 `0x464af5`「%s\n\n償還銀行貸款\n\n%d元」）。

### 1.6 「这一回合能不能操作」

回合相位由 `0x418c55`（人类相位分派）驱动：

```asm
00418d6e  push 0
00418d70  call 0x40c912              ; ★ 返回「相位」：0=受困/只能看訊息，1=人类，2=电脑，-1=跳過
00418d78  cmp  eax, 5
00418d7b  ja   0x418e7a              ; >5 → 直接返回（不動作）
00418d81  jmp  dword ptr [eax*4 + 0x418c3d]   ; 跳表 6 項
```

跳表 `0x418c3d`＝`{0x418d88, 0x418d99, 0x418dc6, 0x418e7a, 0x418e7a, 0x418dc6}`：
相位 **0 → `0x418d88`**（`call 0x418e7f` 设置「受困」动画相位 `0x83`，并置回合结束标志 `0x46cafb=1`）、
相位 1 → `0x418d99`（人类输入）、相位 2/5 → `0x418dc6`（AI 行动）、3/4 → 返回。

判定「受困」的闸门在 `0x40c912`：

```asm
0040c94c  cmp  dword ptr [eax + 0x496b9a], 0   ; ★ dword！0x32..0x35 四个 byte 一起比
0040c953  jne  0x40c962                        ; 住宿|消失|坐牢|住院 任一非 0 → 走訊息分支（返回 0）
0040c955  cmp  byte  ptr [eax + 0x496b9e], 0   ; 冬眠
0040c95c  je   0x40cba5
...
0040cba5  cmp  byte  ptr [eax + 0x496b9f], 0   ; 夢遊 → 0xffffffff（跳過）
0040cbba  mov  bl, byte ptr [eax + 0x496b7d]   ; 否則返回 who_plays（1/2）
```

**结论：坐牢中 / 住院中 → 相位 0 → 整个落点与行动解析被跳过（只显示提示文字），
既不能掷骰、不能买地、也不能用卡。** 提示文字由同一函数生成：
`0x46320a`「%s坐牢中\n\n還剩%d天！」、`0x46321f`「%s住院中\n\n還剩%d天！」，
天数显示为 `(byte & 0x7f) + 1`（`0x40ca60`、`0x40cad9`）。

#### ★★ `0x40c912` 全分支已整段差分（2026-09-19 第 92 条，`tests/test_turn_start.py` 51/51）

`@source VA 0x40c912`（约 780 字节）、`VA 0x40cbdd`（actor 分支）、`VA 0x40cbc2`（quiet 路径）。

```asm
0040c92d  ch = [player + 0x15] ; if (ch == 0) ⇒ 返回 0        ; 不在场
0040c93e  if (arg0(quiet) != 0) goto 0x40cbc2                 ; ── quiet 路径 ──
0040c969  if (who & 0x30) { call 0x40dd1f ; ⇒ 返回 0 }        ; ★★ 受困者「自动走子」：
                                                             ;    不印状态栏文字，只走画面
0040c97c  …被阻碍的其余情形：显示状态文字（见下）⇒ 返回 0…
0040cba5  if ([player + 0x37] != 0) { call 0x40dd1f ; ⇒ -1 }  ; 夢遊
0040cbba  否则 ⇒ 返回 who_plays（1/2/5）
; ── quiet 路径（0x40cbc2）：只判定、不说话、**不查 +0x37** ──
0040cbc2  if (who & 0x30) ⇒ 0 ; if (dword[+0x32] != 0) ⇒ 0 ; if ([+0x36] != 0) ⇒ 0
0040cbd9  ⇒ 返回 who_plays
; ── actor 分支（0x40cbdd，`[0x49910c]` = 4..7）──
0040cbe3  if ([slot + 0x0a] != 0) ⇒ 返回 0        ; place：不在棋盘（監獄/醫院）
0040cbf4  if (arg0(quiet) != 0) ⇒ 返回 0
0040cbf6  if ([slot + 0x0c] != 0) ⇒ 返回 0        ; ★★ 冬眠（hibernating）
0040cc06  if ([slot + 0x0e] != 0) ⇒ 返回 0        ; 停留（halted）
0040cc08  否则 ⇒ 返回 **2**（= 交给 AI 行动）
```

状态文字那一段（`0x40c9a4`..`0x40cb84`）逐支：

| 状态 | 字节 | 格式串 | 掷 `rand()`？ | 头像 `0x44ef41` |
|---|---|---|---|---|
| 住宿中 | `+0x32` | `0x4631e0` | 否 | 不摆 |
| 消失中 | `+0x33` | `0x4631f5`（`& 0x3f`）| 否 | 不摆 |
| 坐牢中 | `+0x34` | `0x46320a` | **是**（`rand() & 1`）| `kind = 2`、台词表 `0x480896` |
| 住院中 | `+0x35` | `0x46321f` | **是** | `kind = 2`、台词表 `0x48089a` |
| 冬眠中 | `+0x36` | `0x463234` | **是** | `kind = 1`、台词表 `0x48089e` |

★ 冬眠那一支还有**前置条件** `dword[+0x32..+0x35] == 0`（`0x40cb12 jne 0x40cb84`）
⇒ 与其它四种状态同时存在时**不显示**，也因此最多只掷 **2** 次 `rand()`
（坐牢 + 住院；住宿/消失不掷、冬眠被 dword 挡住）。
文字末尾用 `cmp byte [esp], 0` 判「这段文字非空才 `0x440cac` 收框」。

★★ 两条**规则可见**的差别（都进复刻）：
① `who & 0x30`（走回棋盘 / 被外力挪过）**不印状态栏文字**，改走 `0x40dd1f`（auto_move）；
② **替身的冬眠闸门**在 `[slot + 0x0c]`，而**夢遊（`+0x0d`）与龜行（`+0x0f`）都不是闸门**。
复刻侧 `rules/special-actors.ts` 的 `npcTurnSteps` 原先只查 `halted`，第 92 条补上了
`hibernating`（两条都不掷随机数），并订正了一条把错行为钉死的旧测试。

### 1.7 地图节点 → 地点分派（监狱/医院/乐透都在这里）

节点结构：指针 `0x498e80`，步长 `0x28`（`node*5*8`）。取型别与参数：

```asm
0041983c  mov  dx, word ptr [eax + 0x20]      ; 节點参数（word）
00419844  mov  ebx, dword ptr [eax + 0x24]    ; 旗標 dword
```

### 2.1 入狱入口 `add_player_days_in_prison` @ `0x43d593`

签名（实参顺序）：`(int player, int days)`。入函数后 4 个 `push`，故 `[esp+0x14]=player`、`[esp+0x18]=days`。

```asm
0043d597  mov  cl,  byte ptr [esp + 0x14]   ; player
0043d59b  mov  edi, 0x100
0043d5a0  shl  edi, cl
0043d5a2  not  edi                          ; ★ edi = ~(0x100 << player)：地圖節點「本玩家佔用」位元的清除遮罩
0043d5a4  mov  edx, dword ptr [esp + 0x14]
0043d5a8  cmp  edx, 4
0043d5ab  jge  0x43d760                     ; player>=4 → NPC 分支（不看 days）
0043d5d4  mov  dh, byte ptr [ebx + 0x496b9c]  ; days_in_prison
0043d5da  test dh, dh
0043d5dc  jne  0x43d6bd                     ; ★ 已在獄 → 累加分支
```

**首次入狱（`days_in_prison == 0`）**——`0x43d5e2`…`0x43d674`：

1. `0x43d5e7 call 0x40d761(player)`：清空该玩家的**监狱/医院/旅馆**状态
   （`0x40d772` 清 `in_prison_flag`、`0x40d793` 清 `in_hospital_flag`、`0x40d7a9` 把 `dword[+0x32]=0` 一次清掉住宿/消失/坐牢/住院四个字节）。**不写天数字节。**

★★ **`0x40d761(player)` 全貌（2026 本轮通道 2 差分，`tests/test_confinement_release.py` 15/15）**：

```asm
0040d769  if ([player+0x34] == 0) goto 看医院     ; +0x34 = inPrison
0040d774      [player + 0x496b30] = 0            ; ★ 监狱占用表：**按玩家号**索引（步长 1）
0040d77d      call 0x40bf93(player, 1)           ; 换图标（MKF，纯表现）
0040d78b  if ([player+0x35] == 0) goto 收尾        ; +0x35 = inHospital
0040d793      [player + 0x496b60] = 0            ; ★ 医院占用表
0040d79c      call 0x40bf93(player, 0)
0040d7a9  dword [player + 0x496b9a] = 0          ; ★ 四个计数器一起清
```

三条容易做错的：
1. 占用表**按玩家号**索引（`[ebx + 0x496b30]`，`ebx` = 玩家下标，**不是** `*0x68`）；
2. 最后那句是 **dword** 清零 —— 把**刚刚用来做判据的** `+0x34`/`+0x35` 也一并抹掉；
3. "只清当前非 0 的那一张表"（两道闸各管一张），不是无脑清两张。

**四个调用点**（自扫）：

| VA | 归属 | 依据 |

| `0x41a7c5` | ★ **卡牌入狱**（`0x41a3be` = 过路费/事件阶梯内）：先 `update_hostility(当前玩家, 地主, **20 × 天 × 物价指数**)`，再清关押，最后按 `edi == 当前玩家` 决定是否播「被关 N 天」台词（`0x44f2c2`） | A（本轮读通） |

**累加分支（已在狱中）**——`0x43d6bd`…`0x43d6d0`：

```asm
0043d6bd  mov  al, byte ptr [esp + 0x18]   ; days
0043d6c1  mov  cl, dh                      ; 舊值
0043d6c3  add  cl, al                      ; ★ 舊 + 新
0043d6c5  mov  byte ptr [ebx + 0x496b9c], cl
0043d6cb  mov  ch, cl
0043d6cd  and  ch, 0x7f                    ; ★ 遮掉 bit7
0043d6d0  mov  byte ptr [ebx + 0x496b9c], ch
```

**`& 0x7f` 的意义**：`+0x34/+0x35` 同时承载「剩余天数」与「bit7＝待释放」标志（见 §2.3），
累加时必须遮掉 bit7，否则会把「待释放」当成 128 天。
副作用（原版行为）：**若旧值已带 `0x80`（正在等待释放），再判一次刑会把释放取消**
（`0x80+days` 的 bit7 被清掉，变成一个小天数）。

**NPC 分支（player = 4..7）**——`0x43d760`…`0x43d7ba`：
只做「清节点占用位 / 置槽状态＝1（监狱） / 清 `+0x0b..+0x0f` / `in_prison_flag[player]=1`」，
**完全不读 `days`，不传送，不播报，不理赔**。
NPC 槽结构：`slot = 0x498e28 + (player-4)*0x10`，状态字节在 `slot+0x0a`（`0x43d788 mov byte [ebx+0x498e32],1`）。
玩家 ≥ 8 时 `0x43d763 jge 0x43d7ba` 直接返回。

### 2.3 天数递减时机与出狱判定 @ `0x41c84f`

`0x41c84f` 是「玩家回合开始处理」，**唯一调用点 `0x419039`**（在换人函数 `0x418ebd` 内，
选定新玩家之后立刻调用）→ **轮到该玩家自己的回合开始时 tick 一次**（不是月初，也不是每人每回合都 tick）。

前置：`0x41c875 cmp byte [eax+0x496b7d],0; je skip`（已出局不处理）、`0x41c882 cmp byte [0x46caf8],0; jne skip`。

```asm
0041c8f6  mov  dl, byte ptr [eax + 0x496b9c]   ; days_in_prison
0041c8fc  test dl, 0x80
0041c8ff  je   0x41c90c
0041c901  push ebx
0041c902  call 0x43d7bf                        ; ★ bit7 已置 ⇒ 出獄處理
0041c90a  jmp  0x41c927
0041c90c  test dl, dl
0041c90e  je   0x41c927                        ; 0 ⇒ 什麼都不做
0041c910  mov  cl, dl
0041c912  dec  cl                              ; ★ days_in_prison -= 1
0041c914  mov  byte ptr [eax + 0x496b9c], cl
0041c91a  jne  0x41c927
0041c91c  mov  dl, cl
0041c91e  or   dl, 0x80
0041c921  mov  byte ptr [eax + 0x496b9c], dl   ; ★ 剛好減到 0 ⇒ 置 bit7（下回合才釋放）
```

住院 `0x41c92a`…`0x41c955` 完全同构（`0x43ee6e` / bit7 / `dec`）。

**因此：**
- 出狱判定条件是 **`days_in_prison & 0x80 != 0`**，不是 `== 0`。
- `days = 3` 实际占用 **4 个自己的回合**（2026-09-18 第 84 条把逐回合的账目核清）：

  | 自己的第几个回合 | 回合**开始**时 tick 做什么 | 这一回合 |
  |---|---|---|
  | T1 | `3 → 2` | 被阻碍，跳过 |
  | T2 | `2 → 1` | 被阻碍，跳过 |
  | T3 | `1 → 0` 并置 `0x80` | 被阻碍，跳过 |
  | T4 | 见到 `0x80` → `call 0x43d7bf` 释放；计数**不写**（仍 0x80）| ★ **「走回棋盘」那一回合**：`0x40d6be` 置 `+0x15 \|= 0x10`，`0x418ebd` 见到 0x30 ⇒ 整回合不掷骰；四个计数由走路例程 `0x40c3cf` 一次清光 |
  | T5 | 计数 0、无标记 | 自由 |

  ⇒ 状态栏「還剩 `(byte & 0x7f) + 1` 天」（`0x40ca60`）显示的正是**会丢掉几个回合**
  （计数 3 显示 4 天）。通道 2 证据：`rich4-spec/tests/test_day_tick.py`（28/28）。
- ★ **递减发生在回合「开始」而不是「结束」**：`0x418ebd` 在 `0x418f95` 就 `inc` 了游标，
  `0x419039` 才用 `[0x49910c]` ⇒ 参数是**即将行动的那位**。复刻把这一步放在
  `endTurn`（上一位结束、下一位开始之前），等价。
- 天数只在**自己回合**递减，与物价指数、难度、卡片均无关（物價只进 §2.5 的保险理赔）。

`days_in_prison` 的**全部写入点**（机械扫描 `0x496b9c` 得出，可复核）：
`0x41c914`(dec)、`0x41c921`(or 0x80)、`0x43cf69`(=0x80，监狱画面保释)、`0x43d56e`(=0x80，监狱格保释)、
`0x43d65d`(=days 首次)、`0x43d6c5`+`0x43d6d0`(累加＋遮罩)、`0x448f31`(=0x80，新闻事件 0「獄中囚犯無罪開釋」)、
`0x40d7a9`(dword `[+0x32]=0`，一次清四个字节)、`0x40c3cf`(到达处理时清 → **释放后残留的 0x80 在此归零**)。

### 2.5 入狱/入院的金额：保险理赔（**收入**，不是罚款）

`0x43d593` 与 `0x43ec3f` 的公共尾段都会调用 `0x44ba63(player, amount)`，其中

```asm
0043d726  mov  eax, dword ptr [esp + 0x1c]   ; = days
0043d72a  mov  ebx, eax
0043d72c  shl  ebx, 2                        ; 4d
0043d72f  sub  ebx, eax                      ; 3d
0043d731  shl  ebx, 3                        ; 24d
0043d734  add  ebx, eax                      ; 25d
0043d736  shl  ebx, 4                        ; 400d
0043d739  mov  eax, ebx
0043d73b  shl  ebx, 2                        ; 1600d
0043d73e  add  ebx, eax                      ; ★ 2000 × days
0043d740  imul ebx, dword ptr [0x4990e8]     ; ★ × price_index
0043d748  push ebp                           ; player
0043d749  call 0x44ba63
```

`0x44ba63(player, amount)` 的语义（`0x44ba6c`…`0x44bae9`，仅 44 条指令，可全文核）：

```asm
0044ba6c  imul eax, dword ptr [esp + 0x90], 0x68
0044ba74  cmp  byte ptr [eax + 0x496ba6], 0   ; ★ days_assurance（保險期）
0044ba7b  je   0x44bae0                      ; 無保險 → 不理賠
0044ba82  mov  edx, dword ptr [0x498e7c]      ; 企業/商用土地表
0044ba88  cmp  ebx, dword ptr [0x498e90]      ; 掃描第一家 +0x1a == 4（行業別 4＝保險公司）
0044ba93  cmp  byte ptr [edx + eax + 0x1a], 4
0044baa4  push esi                            ; amount
0044baa5  push 0x4658fa                       ; "保險期間\n\n得到理賠金\n\n%d元"
0044bab7  push 0x7d0                          ; 2000（＝顯示毫秒，不是錢）
0044bac0  call 0x440cac
0044bac9  push 1
0044bacb  push esi                            ; amount
0044bacc  mov  ebp, dword ptr [esp + 0x98]    ; player
0044bad3  push ebp
0044bad4  add  ebx, 0x64                      ; 企業索引 + 0x64
0044bad7  push ebx
0044bad8  call 0x41d2c6                       ; (保險公司, player, amount, 1)
```

在 `0x41d2c6` 内：`payer = 企業索引+0x64 > 0x64` ⇒ 保险公司账上 `+0x28/+0x2c -= amount`；
`payee = player` ⇒ `flags&1` ⇒ `0x41d3b9 add dword [eax+0x496b84], ebx` **现金增加**，
并 `0x41d3ca add [eax+0x496bc8]`（`monthly_received`）。

**结论：`days × 2000 × price_index` 是「有保险期（`player+0x3e != 0`）时的理赔金，玩家收钱」，
不是罚款，也不扣玩家任何钱。**

已知原版缺陷（与既有记录一致）：若地图上没有保险公司，
扫描结束时 `ebx = num_commercial + 1`，`ebx + 0x64` 会作为企业索引写到企业表之外
（`0x44ba88` 的循环无「未找到」处理）。

机械普查见 `tests/test_points_field.py`（23/23）。

顺带把随机消耗**逐拍**钉住了：`0x43d3d8` 那一次「管不管」的 `rand() & 1` 是**第一掷**，
風格 1 的 `%3` 是**第二掷**、挑候选是**第三掷**（風格 0/2 只有两掷）；

现金侧完全没有扣款指令，`0x43cf3b` 的 `100 × days × price_index` 只是喂给 `0x40df69`
（成对表增减，负数夹 0）。人类路径与 AI 路径的差异（人类走 `0x40df69` 数值、AI 不走）
**未决**。

### 3.3 住院天数是否与医院等级 / 物价指数相关？——**否**

- `0x43ec3f` 全文**没有读取任何「医院等级」字段**（医院设施表在 `0x498e88`，
  其等级字段为 `+0x1a`；该函数不引用它）。传入的 `days` 全部是调用点的**立即数 0/3/5**
  或命运表的全局 `[0x48c5b4]`（3，特定情况下 ×2＝6）。
- 物价指数 `0x4990e8` 在该函数与 `0x43d593` 里**只出现在保险理赔的乘法**（`0x43edef`、`0x43d740`）。
- 因此：**住院天数与医院等级、物价指数均无关；物价只影响理赔金额。**
  （是否有某个调用点先按医院等级算天数再传入——在全部 10 个调用点上未发现，标为**未决**的只有
  #1 `0x41b77e` 的**触发场景**，其天数 5 是立即数。）

## 四、银行

银行的界面/交互有三个入口：

| 入口 | VA | 说明 |
|---|---|---|
| 银行格（型别 14） | `0x41b396`：先 `call 0x4379c9`（ATM），若 `[0x46caf8]==0` 再 `call 0x436668`（柜台事件） | 落地银行格的完整链路 |
| ATM / 提款卡 | 入口 `0x4379c9`；窗口过程 `0x436ef8`（界面逻辑在同函数的 `0x437161` 段） | **存取款只在这里**（手动输入金额）；AI 走 **cashRatio 重分配** |
| 银行柜台 | 事件 `0x436668`；窗口过程 `0x435062`（`hwnd`→`0x48c3c0`） | 只有 **申請貸款 `0x435d48` / 償還貸款 `0x435da4` / 特別融資 `0x435ddb`（限银行经营者）/ 离开** 四个按钮，**没有存取款** |
| 每月结算 | `0x439bfa`（由 `0x41cf67` 在每月 1 日调用）→ 窗口过程 `0x437e61` | 存款利息（每月 1 日）+ 月结排行榜 |

### 4.1 存款 / 取款（精确规则）

银行格（节点型别 14）先走 **ATM/提款卡入口 `0x4379c9`**，窗口过程为 `0x436ef8`；
金额来自窗口自己的输入缓冲 `0x48c3f8`（数字键盘表 `0x475914` / 拖动条 34 档），确认后执行 `0x4377e6` 区块。
（金额输入对话框 `0x453544` 只用于**贷款 / 特别融资**路径，ATM 不使用它。）

```asm
004377e6  push ref_0048c3f8
004377f3  call 0x4584db                 ; atoi(輸入框)
004377f8  mov  ebx, eax
004377fd  test ebx, ebx
00437801  je   0x437774                 ; 0 ⇒ 不動作
0043780f  imul eax, edx, 0x68
00437812  cmp  dword ptr [0x48c3f0], 0  ; 0＝取款，1＝存款
00437819  jne  0x437856
0043781b  sub  dword ptr [eax + 0x496b88], ebx   ; 取款：存款 -= amount
00437821  add  dword ptr [eax + 0x496b84], ebx   ;       現金 += amount
...
00437856  add  dword ptr [eax + 0x496b88], ebx   ; 存款：存款 += amount
00437864  mov  edi, dword ptr [eax + 0x496b84]
0043786a  sub  edi, ebx
0043786c  mov  dword ptr [eax + 0x496b84], edi   ;       現金 -= amount
```

- **无手续费、无税**。上限是**就地夹取**的，用的是窗口过程自己的输入缓冲 `0x48c3f8` 与上限变量 `0x48c3ec`
  （**不是** `0x453544`；`0x453544` 的 12 个调用点全在贷款/特别融资路径上）：

```asm
004378c6  push 0x48c3f8
004378cb  call 0x4584db                    ; atoi(輸入)
004378d3  mov  edi, dword ptr [0x48c3ec]   ; 上限（存款模式＝現金、取款模式＝存款）
004378d9  cmp  eax, edi
004378db  jle  0x4378ed
004378dd  push 0xa / push 0x48c3f8 / push edi
004378e5  call 0x457d61                    ; ★ 超過上限 ⇒ 把輸入改寫成上限（itoa）
```

  ⇒ **ATM 无法透支**（超限输入被改写成上限后执行；拖动条 `0x437413`/`0x437463` 同样夹取）。
  上限在进入界面时按模式设定（`0x436fdd`：暂停放款时只给存款模式）。
- 取款分支末尾会 `push 1; call 0x436b0a`（银行资金/特别融资结算，§4.5）。

### 4.2 贷款（精确规则）

**额度基准＝当前玩家总资产**，不是银行资金：

```asm
00436674  imul eax, dword ptr [0x49910c], 0x68
0043667b  cmp  byte ptr [eax + 0x496ba3], 0   ; ★ 被拒絕往來 ⇒ 整個銀行不服務
00436682  jne  0x436953
0043668f  call 0x4239b9                       ; ★ calculate_player_wealth(player)
00436697  mov  dword ptr [0x48c3b0], eax      ; = 總資產
```

**按钮入口**：`0x435d48`（申請貸款，门禁见 §4.8）→ 提示 `0x47583c`「請輸入您要貸款的金額！」→ 状态 5 → `0x409` → `0x435228`；
`0x435da4`（償還貸款，要求 `loan != 0`）→ `0x435360`；`0x435ddb`（特別融資，仅当 `[0x48c3e0] != 0` 即银行经营者）→ 子窗口 `0x434492`。
按钮派发＝`0x435cc3 jmp dword ptr [eax*4 + 0x435052]`（4 项）。

**申请贷款**（人类 UI 的确认块，`0x435228`）：

```asm
00435228  mov  eax, dword ptr [ebx + 0x496b8c]   ; loan
0043522e  mov  edi, dword ptr [0x48c3b0]         ; 總資產
00435236  jge  0x435354                          ; loan >= 總資產 ⇒ 拒絕（狀態 8）
0043523c  mov  eax, edi
0043523e  sub  eax, dword ptr [ebx + 0x496b8c]   ; 可貸上限 = 總資產 - loan
00435244  push eax
00435245  call 0x453544                          ; 輸入金額（預設值＝上限；★ 此對話框不做上限夾取）
0043524f  test eax, eax; je 0x435354
00435260  add  dword ptr [eax + 0x496b88], edx   ; ★ 存入「存款」
00435266  add  dword ptr [eax + 0x496b8c], edx   ; ★ loan += amount
0043526d  call 0x433b7e                          ; 設/滾動還款到期日（見下）
```

**AI/自动贷款**（`0x4368fc`，触发：`who_plays != 1`，先 `rand()%10 != 0 || 总资产 < 30000`）：

```asm
004368db  mov  bh, byte ptr [ecx + 0x496b80]  ; player+0x18（額度百分比）
004368e3  je   0x436953
004368e9  imul edx, dword ptr [0x48c3b0]      ; × 總資產
004368f0  mov  ebx, 0x64
004368fa  idiv ebx                            ; ÷ 100
004368fc  mov  dword ptr [ecx + 0x496b8c], eax ; loan = 額度% × 總資產 / 100
00436906  add  dword ptr [ecx + 0x496b88], eax ; 存款 += loan
00436912  call 0x433b7e                        ; 設到期日
0043692f  push 0x464b0c                        ; "%s\n\n向銀行貸款\n\n%d元"
```

> ⚠️ `player+0x18`（`0x496b80`，上式里的「额度百分比」）**在 exe 里没有任何写入指令**
> （机械扫描：`0x496b80` 的全部出现中没有任何 store 形态；唯一引用是 `0x4368db` 的读）。
> ⇒ 新开局该值为 0 ⇒ `loan = 0`，该 AI 自动贷款分支**很可能是死代码**。列为**未决**。

**还款期限＝90 天**。`0x433b7e(player)`：

```asm
00433ba6  cmp  dword ptr [ebx + 0x496b94], 0   ; 到期日（packed date）
00433bad  jne  0x433bab
00433bb0  push 0x5a                            ; ★ 90
00433bb2  push ecx                             ; 當前日期 [0x497160]
00433bb3  call 0x45218f                        ; date + 90 天
00433bb8  mov  dword ptr [ebx + 0x496b94], eax
```

**到期处理**在 `0x436a5a`（每个玩家回合开始时由 `0x41c86d call 0x436a5a` 调用）：
`0x4521aa(player+0x2c, 当前日期)` 得到剩余天数，>3 不处理，否则跳表 `0x436a4a` 4 项：

| 剩余 | 行为 | @source |
|---|---|---|
| 0 | **强制偿还**：`0x433bd8(player, loan)`（从存款扣，不足转现金，再不足破产），随后 `loan=0`、到期日 `0x496b94=0` | `0x436a9b`、`0x436acf`、`0x436ad5` |
| 1 | 显示 `0x464b43`「距貸款到期日\n\n還剩１天！」 | `0x436adf` |
| 2 | 显示 `0x464b5c`「距貸款到期日\n\n還剩２天！」 | `0x436af5` |
| 3 | 无动作 | `0x436b01` |

文本 `0x464b24` 附近另有「距離貸款到期日\n\n強制執行！」（`0x464b2a` 起）。
提前自动还款条件（AI，`0x43680e`）：`loan*2 < 存款` **或** `(距到期 ≤ 6 天 && 现金+存款 ≥ loan*1.1)`；
否则不动作——「可负担」标志只在 `0x4367c8 cmp eax,6; jg 0x43680e` 成立（剩余 ≤6 天）时才可能被置 1（`0x43680e`…`0x436815`）。

### 4.3 利息（公式、结算时点、利率来源）

| 项 | 结论 | @source |
|---|---|---|
| **存款利息** | **每月结算一次，且只发给「贷款已清」的玩家：`if (loan == 0) money_in_bank = trunc(money_in_bank × 1.1)`**（＋10%） | 条件 `0x4381f8 cmp dword ptr [eax + 0x496b8c], 0; jne 0x438218`（有贷款者跳过）；乘数 `0x438207 fmul qword ptr [0x464e88]`；截断 `0x43820d call 0x457dbc`（向零取整）；写回 `0x438212 fistp dword ptr [eax + 0x496b88]` |
| 利率常量 | 数据段 double `1.1`＝`9a9999999999f13f`，VA **`0x464e88`**（全 exe 唯一使用点就是 `0x438209`） | 机械扫描确认 |
| 结算时点 | **每月 1 日**：`0x41cf67` 在 `date_increment` 返回 1 时 `0x41d09e call 0x439bfa` → 银行结算流程（`0x437e34` 状态机，其中 `0x43814a` 区块执行上式） | `0x41d099`、`0x439bfa` |

| **贷款利息** | **未发现任何实际收取利息的代码**：手动还款 `0x4353a3`…`0x4353ce`、AI/到期强偿 `0x43682d`→`0x433bd8(player, loan)` 都只扣**本金**，随后 `loan = 0` | `0x435360`、`0x43680e` |
| 唯一的 1.1 系数（贷款侧） | double `1.1` @ **`0x464b24`**，**只用于 AI 的「能否负担」判定** `0x4367fc fmul qword ptr [0x464b24]` + `0x436802 fcompp`（比较 `loan*1.1` 与 `现金+存款`）。全 exe 唯一使用点 | 机械扫描确认 |

| **一次性 +10% 紅利事件** | 機會/命運 `0x46570b`「#0172銀行加發１０％儲金紅利」：**同样只给 `loan == 0`** 的玩家，`bonus = trunc(存款 × 0.1)`（double 常量 **`0x465734` = 0.1**，字节 dump 已核），再 `0x41d3f4(player, bonus, flags=0)` ⇒ **进存款** | `0x44af3c`（`test ebp,ebp; jne` 跳过有贷款者）、`0x44af4a fmul qword ptr [0x465734]`、`0x44af66 call 0x41d3f4` |
| ↑ 验证 | **乘法 + 向零截断已通道 2 差分**（`tests/test_inline_formulas.py`：`trunc(99×0.1)=9` 排除四舍五入、`trunc(-99×0.1)=-9` 排除向下取整）；`loan != 0` 跳过是**静态 A 级**（`0x44af3c` 无条件分支），不在被测区块内 | `0x44af44`..`0x44af5c` |

> `loan*1.1` 只影响 AI 是否主动还款。这一点与常见攻略说法不同，以 exe 为准。

### 4.4 `cashRatio`（`player+0x19`）重分配机制

只在 **ATM `0x4379c9`** 里被执行（`0x496b81` 的运行时读者只有 `0x4379c9`；`0x41e345` 是初始化）：

```asm
00437acd  mov  ecx, dword ptr [0x497160]      ; 遊戲日期
00437ad5  and  ecx, 0xff                      ; ★ day
00437adb  mov  ebx, dword ptr [edx + 0x496b84]
00437ae1  add  ebx, dword ptr [edx + 0x496b88] ; total = cash + bank
00437ae7  fild dword ptr [edx + 0x496b84]
00437aed  mov  dword ptr [esp + 0x90], ebx
00437af4  fild dword ptr [esp + 0x90]
00437afb  fdivp st(1)                          ; ratio_cash = cash / total
00437afd  fstp dword ptr [esp + 0x8c]
00437b02  mov  al, byte ptr [edx + 0x496b81]   ; ★ cashRatio
00437b0a  fild word ptr [esp + 0x94]
00437b11  fdiv dword ptr [0x464c08]            ; ÷ 100.0f
00437b17  fstp dword ptr [esp + 0x88]          ; ratio_want
00437b1d  cmp  ecx, 7
00437b20  jg   0x437b3c
00437b22  fld  dword ptr [esp + 0x88]
00437b26  fmul qword ptr [0x464c10]            ; day <= 7  ⇒ × 1.5
00437b2c  fstp dword ptr [esp + 0x88]
00437b3c  cmp  ecx, 0x1a
00437b3f  jl   0x437b55
00437b41  fld  dword ptr [esp + 0x88]
00437b45  fmul qword ptr [0x464c18]            ; day >= 26 ⇒ × 0.5
00437b4b  fstp dword ptr [esp + 0x88]
00437b55  cmp  dword ptr [esp + 0x88], 0x3f800000   ; >= 1.0f
00437b5c  jl   0x437b6f
00437b5e  mov  dword ptr [esp + 0x88], 0x3f666666   ; clamp 0.9f
00437b6f  fldz
00437b71  fcomp dword ptr [esp + 0x88]
00437b78  jb   0x437b88
00437b7a  mov  dword ptr [esp + 0x88], 0x3dcccccd   ; clamp 0.1f
00437b88  fld  dword ptr [esp + 0x8c]
00437b8c  fsub dword ptr [esp + 0x88]
00437b90  fst  qword ptr [esp + 0x80]          ; diff = ratio_cash - ratio_want
00437b94  fcomp qword ptr [0x464c20]           ; 0.25
...
00437ba5  fcomp qword ptr [0x464c28]           ; -0.25
...
00437bbb  cmp  dword ptr [eax + 0x496b84], 0   ; 差額在 ±0.25 內且現金非 0 ⇒ 不重分配
00437bc2  jne  0x437c1c
00437bca  fild dword ptr [esp + 0x90]          ; total
00437bd1  fmul dword ptr [esp + 0x88]          ; × ratio_want
00437bd8  call 0x457dbc                        ; 截斷（向零）
00437bdd  fistp dword ptr [esp + 0x90]

00437bfd  sub  ebx, eax
00437bff  mov  dword ptr [edx + 0x496b88], ebx ; bank = total - cash
```

**精确公式**（`@source 0x437acd`…`0x437c14`）：

```
total      = cash + bank
ratio_cash = cash / total                                (float，32 位)
ratio_want = cashRatio / 100.0
if (day <=  7) ratio_want *= 1.5      ; 常數 double 0x464c10 = 1.5
if (day >= 26) ratio_want *= 0.5      ; 常數 double 0x464c18 = 0.5
if (ratio_want >= 1.0) ratio_want = 0.9   ; 立即數 0x3f666666
if (ratio_want <= 0.0) ratio_want = 0.1   ; 立即數 0x3dcccccd
diff = ratio_cash - ratio_want
if (diff < 0.25 && diff > -0.25) { if (cash != 0) return; }   ; 常數 0x464c20 / 0x464c28 = ±0.25
cash = trunc(total * ratio_want)
bank = total - cash
```

常量位置（可直接 dump 复核）：`0x464c08`＝float `100.0`（`0000c842`）、
`0x464c10`＝double `1.5`、`0x464c18`＝double `0.5`、`0x464c20`＝double `0.25`、`0x464c28`＝double `-0.25`。

### 4.5 特别融资 `special_finance`（`player+0x28`）与银行经营

UI 文本：`0x464aae`「客戶存款總額」、`0x464abb`「目前融資金額」、`0x464ac8`「尚可融資金額」、
`0x464a93`「特別融資」、`0x464a9c`「週轉現金」、`0x464aa5`「歸還款項」。

`0x436b0a(arg)`（银行资金结算）：

- 先找**银行**：企业表 `0x498e7c`（数量 `0x498e90`）中 `[+0x1a] == 7` 且 `[+0x18] != 0` → 经营者 `edi`。
- `arg != 0`（提款/存款后调用）：若经营者的 `special_finance(0x496b90) > 其他玩家存款总额`
  → 经营者必须**自掏腰包垫付差额**：显示 `0x464b75`「銀行資金準備\n\n不足%d元\n\n由經營者%s墊付！」，
  `0x433bd8(经营者, 差额)`（可能破产），`special_finance -= 差额`（夹 0）。
- 经营者子窗口 `0x434492` 的两个动作：`0x434665`（週轉現金：`存款 += x; special_finance += x`，默认值＝`其他玩家存款总额(0x48c3c8) − 我的特别融资`，**输入无上限校验**）、
  `0x4346bb`（歸還款項：先扣存款再补现金，**有**上限校验）。可用性门禁在 `0x434e73`/`0x434f09`（`特别融资 >= 其他玩家存款总额` 时不能借；`== 0` 时不能还）。
- `arg == 0`：对每个 `special_finance != 0` 的玩家 → 显示 `0x464b9e`「銀行經營權易主！」
  与 `0x464baf`「%s\n\n強制償還%d元\n\n銀行特別融資！」，`0x433bd8(player, special_finance)` 强制偿还，
  然后清零。

### 4.6 `days_rejected_by_bank`（`player+0x3b`）

```asm
0044c2b3  imul eax, dword ptr [0x49910c], 0x68
0044c2ba  add  byte ptr [eax + 0x496ba3], 0x1e   ; ★ +30（一個月）
```

- **写入点**：`0x44c2ba`，字串 `0x465959`「#0188支票跳票\n銀行拒絕往來一個月」——即**支票跳票**事件
  （`0x44c229`/`0x44c2c2` 所在的拍卖/结算界面族）。
- **门禁**：银行柜台 `0x43667b cmp byte [eax+0x496ba3], 0; jne 0x436953` ⇒ **整个银行流程直接返回**；
  ATM `0x4379da` 同样判定；提示文本 `0x464bed`「銀行拒絕往來\n\n還剩%d天！」，
  显示天数＝`(值 & 0x7f) + 1`（`0x437a00`…`0x437a12`）。
- **递减**：在每回合处理 `0x41cba2`/`0x41cbaf`（`dec`；减到 0 置 bit7；下一回合 `0x41caa6` 只清标志、无其它动作）
  ⇒ 有效期为 30 个**自己的回合**。

### 4.7 破产与贷款的关系

- 破产入口 `0x40cd87(player)`（调用者：`0x411ae9`（回合/退场判定）、`0x41d376`（付款不足）、`0x433bd8`（取款不足）、
  `0x436beb`（银行垫付）等）：
  `0x40cd99 mov dl,[eax+0x496b7d]; test dl,dl; je 0x40d288`（已出局则不重复处理）；
  随后 `0x40cf1c`…`0x40cf25` 用 `memset(&player+0x1c, 0, 0x68-0x1c)` **把现金/存款/贷款/特别融资/点数/所有状态一次清零**，
  即**破产会连带清掉 loan**（不再追偿）。
- 触发破产的直接原因是**付款/取款后账上不足**：`0x433bd8`（存款 → 现金 → 不足则 `0x40cd87`）、
  `0x41d2c6`（现金 → 存款 → 不足则 `0x40cd87`）。
- `0x40cd87` 另有一小段（`0x40ce86`…`0x40cefd`）把破产玩家名下的 NPC 送回监狱/医院（§2.2 #7、§3.2 #9）。

### 4.8 「暫停放款」`days_bank_no_loans`（`player+0x3c`）

文本 `0x464ad5`「銀行暫停放款\n\n還剩%d天！」（`0x436fdd`、`0x437098`、`0x4371e5`、`0x435d4f` 读取）。

**唯一写入点＝新闻事件 `0x4656ef`「#0171銀行擠兌停止放款１５天」**（处理函数 `0x44ae89`）：

```asm
0044aeb6  mov  bh, 0xf                          ; ★ 15 天
0044aebe  cmp  edx, dword ptr [0x499114]        ; 掃描全部玩家
0044aec9  cmp  byte ptr [eax + 0x496b7d], 0

0044aed2  mov  byte ptr [eax + 0x496ba4], bh    ; ★ 對每位在場玩家設 15
```

效果：AI 不放款（`0x4368ce`）、柜台贷款按钮无响应（`0x435d4f`）、ATM 初始只给存款模式（`0x436fdd`）。

### 4.9 银行边界情况

| 情况 | 行为 | @source |
|---|---|---|
| 被拒绝往来 | 银行柜台与 ATM 全部直接返回（不弹主界面） | `0x43667b`、`0x4379da` |
| `loan >= 总资产` | 申请贷款被拒（状态 8，文本 `0x475830`） | `0x435236` |
| 贷款额度 | `总资产 - loan`（人类输入）／`额度% × 总资产 / 100`（AI） | `0x43523e`、`0x4368fa` |
| 存款/取款金额为 0 | 不动作 | `0x437801` |
| 存款/取款超过上限 | **输入被就地改写成上限**（不会透支） | `0x4378d9` → `0x457d61`(itoa) |
| 贷款输入超过许可额度 | **无校验**：`0x453544` 返回值直接 `loan += x; bank += x`，不与 `wealth − loan` 比较 ⇒ **可超贷** | `0x435228`…`0x435266` |
| 取款后 | `0x436b0a(1)` 检查银行资金是否够特别融资 | `0x43784f` |
| 贷款到期 | 强制偿还，不足则破产并清空全部字段 | `0x436a9b`、`0x40cd87` |
| 无保险公司 | 理赔时企业索引越界（原版 bug） | `0x44ba88`、`0x44bad4` |

### 5.1 数据结构

| 全局 | 类型 | 含义 | 证据 |
|---|---|---|---|
| `0x4990b8` | byte × **0x24 ＝ 36** | **号码槽**：0＝未售；否则＝持有者玩家编号 + 1 | 扫 36 格 `0x430b08 cmp eax,0x24`；`0x4315cc` 写入 |
| `0x499080` | dword | **累積獎金（jackpot）**：投注款与其它「钱消失」金额的累计 | UI 文本 `0x4645d9`「累積獎金」＋`0x4f…` 显示；`0x4315cc` `+0x3e8`；UI 读取 `0x42f6c3`、`0x42fa9b`、`0x430485` |

### 5.2 投注规则与金额（入口 `0x4315cc`）

触发：落在**型别 9** 的节点（`0x41b17a call 0x4315cc`，跳表 `0x4197e9[9]`）。

```asm
004315d3  imul eax, dword ptr [0x49910c], 0x68
004315da  cmp  byte ptr [eax + 0x496b7d], 1
004315e1  jne  0x43169e                     ; ★ 非人類（AI/出局）→ 自動買一張
...                                          ; 人類：載入面板 0xc/0xd/0xe 後跑投注視窗（回呼 0x42f7fc）

; —— AI／自動投注 ——
0043169e  cmp  dword ptr [eax + 0x496b84], 0x3e8   ; 現金
004316a5  jle  0x43170a                            ; ★ 現金 <= 1000 ⇒ 不買
004316b0  inc  eax; 004316b2 cmp eax,0x24; jge 0x4316c5
004316b6  cmp  byte ptr [eax + 0x4990b8], 0       ; 收集全部空槽
004316be  mov  byte ptr [esp + ebx], al; inc ebx
004316c9  test ebx, ebx; je 0x43170a               ; 沒有空槽 → 不買
004316cf  mov  al, byte ptr [0x49910c]; inc al
004316d6  mov  byte ptr [esp + 0x24], al           ; = 玩家編號 + 1
004316db  call 0x456f2d                            ; rand()
004316e8  idiv ebx                                 ; % 空槽數
004316f0  mov  al, byte ptr [esp + edx]            ; 隨機挑一個空槽
004316f4  mov  dl, byte ptr [esp + 0x24]
004316fa  mov  byte ptr [eax + 0x4990b8], dl       ; ★ 槽 = 玩家+1
004316ff  imul eax, dword ptr [0x49910c], 0x68
00431707  sub  dword ptr [eax + 0x496b84], 0x3e8   ; ★ 現金 -= 1000
00431711  add  dword ptr [0x499080], 0x3e8         ; ★ 獎金池 += 1000
```

**投注金额＝1000 元/张**（立即数 `0x3e8`，`@0x4315cc` 内出现 2 次）。
**准入条件：现金 > 1000**（`jle` 跳过 ⇒ 1000 整不入场）。

**人类投注界面**（窗口过程 `0x42f7fc`，点击处理 `0x42fe8c`）：
号码是 **4 行 × 9 列 ＝ 36 格**（行距 0x40、列距 0x30、原点 (0x1e,0x10f)）：

```asm
0042feef  lea  edx, [esi - 0x1e]        ; x - 30
0042fefc  sar  eax, 6                   ; col = (x-30)/64      ∈ 0..8
0042ff01  lea  edx, [ecx - 0x10f]       ; y - 271
0042ff11  idiv ecx                      ; row = (y-271)/48     ∈ 0..3
0042ff15  shl  eax, 3
0042ff18  add  eax, ecx
0042ff1a  lea  ebx, [eax + esi]         ; ★ slot = row*9 + col ∈ 0..35
0042ff1d  cmp  byte ptr [ebx + 0x4990b8], 0
0042ff24  jne  0x42f924                 ; 已售出 ⇒ 忽略點擊
...
0042fff0  mov  al, byte ptr [0x49910c]; inc al
0042fff7  mov  byte ptr [ebx + 0x4990b8], al   ; 槽 = 玩家+1
0043000e  sub  dword ptr [eax + 0x496b84], 0x3e8   ; 現金 -= 1000
00430018  add  dword ptr [0x499080], 0x3e8         ; 獎金池 += 1000
```

⚠️ **点击处理器内没有任何现金判定**：进场只要求 `现金 > 1000`，
此后每点一个空格子都无条件 `现金 -= 1000` ⇒ **连续投注可把现金打到 0 甚至负数**（原版行为）。
输入区域被限定为 `x ∈ [0x1e,0x25e]`、`y ∈ [0x10f,0x1cf]`（`0x42fec2`…`0x42fee9`）。

### 5.3 开奖时点与随机数调用点

- **时点：每月 15 日**。`0x41cf67` 在推进日期后：

```asm
0041d080  mov  eax, dword ptr [0x497160]   ; 遊戲日期
0041d085  and  eax, 0xff                    ; day
0041d08a  cmp  eax, 0xf                     ; ★ == 15
0041d08d  jne  0x41d099
0041d08f  call 0x42ba97                     ; 上市公司分紅（同日先算）
0041d094  call 0x431712                     ; ★ 樂透開獎
```

- **开奖入口 `0x431712`** 先扫 36 槽，全空则直接返回（`0x43171a`…`0x431725` 循环，`0x431729 cmp eax,0x24; je 0x43180d`），
  否则载入面板 `0xf/0xd/0x10/0x11` 并跑开奖视窗（回呼 `0x43010c`）。
- **随机数调用点**（全部经 `0x456f2d`＝`rand`）：

| 位置 | 用途 |
|---|---|
| `0x430b52`（开奖状态 6，`loc_00430b52`） | `rand() % 已售张数` → 从「已售号码表」里取一个 |
| `0x430b66` | `rand() % 0x24` → 号码 `= rand()%36 + 1` |
| `0x4316db`（投注：AI） | `rand() % 空槽数` → 挑一个空槽 |
| `0x42f…`（投注界面若干处） | 掷骰/表现用（未逐一归类） |

- 开奖动画由 `SetTimer`（间隔 `0x32`）驱动，计数器 `0x48c37c`，视窗状态机 `0x48c37b`
  （0=初始，3=转动，5/6=揭晓，7/8=无奖，9/10=结束）。

### 5.4 奖级与赔率表——**只有一档：独得全部累積獎金**

开奖号码的选取（`0x430b0d`…`0x430b7a`，**exe 原文**）：

```asm
00430b0d  mov  cl, byte ptr [eax + 0x4990b8]   ; 逐格掃描 36 格
00430b13  test cl, cl; je next
00430b19  mov  dl, cl
00430b1b  inc  byte ptr [esp + edx + 0x7f]     ; 每玩家持有張數計數（esp+0x80..0x83）
00430b1f  mov  dl, al
00430b21  inc  dl
00430b23  mov  byte ptr [esp + ebx + 0x40], dl ; 已售號碼表（1-based）
00430b27  inc  ebx                             ; ebx = 已售張數 n
...
00430b2a  cmp  byte ptr [esp + 0x80], 0xa
00430b32  ja   0x430b52                        ; ★ 任一玩家持有 > 10 張 → 走「必中」分支
00430b34  cmp  byte ptr [esp + 0x81], 0xa
00430b3c  ja   0x430b52
00430b3e  cmp  byte ptr [esp + 0x82], 0xa
00430b46  ja   0x430b52
00430b48  cmp  byte ptr [esp + 0x83], 0xa
00430b50  jbe  0x430b66                        ; 全部 <= 10 張 → 走「可能空開」分支

; 分支 A（有人持有 >10 張）：在已售號碼中均勻抽一個 ⇒ 一定有得主
00430b52  call 0x456f2d
00430b5c  idiv ebx                             ; % n
00430b60  mov  bl, byte ptr [esp + edx + 0x40] ; = 已售號碼（1..36）

; 分支 B（每人 <=10 張）：在 36 個號碼中均勻抽一個
00430b66  call 0x456f2d
00430b6d  mov  ebx, 0x24
00430b75  idiv ebx
00430b77  lea  ebx, [edx + 1]                  ; ★ 開獎號碼 = rand()%36 + 1 ∈ 1..36
```

**因此「中奖」＝开出的号码（1..36）对应的槽 `0x4990b8[号码-1]` 属于某人**：

```asm
00430d91  cmp  byte ptr [ebx + 0x4990b7], 0    ; 0x4990b7 + 號碼 = &槽[號碼-1]
00430d98  je   0x430d85                        ; 該號碼無人買 ⇒ 無人中獎
00430da0  mov  byte ptr [0x48c37b], 4
00430db0  mov  al, byte ptr [ebx + 0x4990b7]   ; 槽值 = 玩家+1
00430dbb  mov  dword ptr [0x48c377], eax       ; 得主 = 玩家+1
```

结算（状态 0xa `0x430ab5`）：

```asm
00430ab5  call KillTimer
00430ac0  mov  ebx, dword ptr [0x48c377]       ; 得主（0=無人得獎）
00430ac7  test ebx, ebx
00430ac9  je   0x430afb                        ; ★ 無人中獎 ⇒ 跳過派彩、且不清空
00430acb  push 1
00430acd  mov  edi, dword ptr [0x499080]       ; ★ 獎金池全額
00430ad4  push edi
00430ad5  lea  eax, [ebx - 1]
00430ad8  push eax
00430ad9  call 0x41d3f4                         ; (player, pool, flags=1) ⇒ 現金 += 獎金池
00430ade  xor  ebp, ebp
00430ae0  mov  dword ptr [0x499080], ebp        ; 獎金池歸零
00430ae7  push 0x24
00430ae9  push ebp
00430aea  push 0x4990b8
00430aef  call 0x456f60                         ; memset(票槽, 0, 36)
```

- **奖级：单档**。中奖者独得 `[0x499080]`（**全部**累積獎金），`flags=1` ⇒ **进现金**（不是存款），
  并累计 `monthly_received`（`0x41d3ca`）。
- **不存在**「二等奖/固定赔率表」之类的结构：代码里没有任何赔率表，派彩金额只有 `[0x499080]` 一处。
- **中奖率**（由上面两支分支决定）：设某玩家持有 `k` 张、全场共售 `n` 张：
  - 若所有玩家持有 ≤ 10 张：开出号均匀分布在 1..36，**该玩家中奖概率 = k/36**，
    全場空开概率 = `(36-n)/36`；
  - 若任一玩家持有 > 10 张：从已售号码中均匀抽一个，**该玩家中奖概率 = k/n**，**必有人中奖**。

### 5.5 未中奖处理——**奖金与票全部结转**

`0x430ac9 je 0x430afb` 直接跳过派彩、`memset` 与池归零 ⇒ **无人中奖时：
累積獎金保留、36 个号码槽全部保留**（已买票者下个月仍持有同样的号码）。
这正是 `0x4645d9`「累積獎金」会越滚越大的原因。

### 5.6 `0x499080`（累積獎金）为什么会滚得很大

`0x499080` 是全局的「钱离开游戏」计数器：`0x41d2c6` 在 `payee == -1` 时
`0x41d38c add dword ptr [0x499080], ebx`（罚款、无人接收的支出等都会累进来），
投注也 `+1000`。它唯一的**读取者**就是乐透界面（`0x42f6c3`、`0x42fa9b`、`0x430485` 显示
`0x4645d9`「累積獎金」），唯一的清零点是派彩（`0x430ae0`）与存档初始化（`0x406de7`/`0x448544`）。
⇒ **奖金池 = 所有「钱消失」事件的累计 + 全部票款**。

### 5.7 乐透的边界情况

| 情况 | 行为 | @source |
|---|---|---|
| 现金 ≤ 1000 | 不能进入投注（人类）/AI 不买 | `0x43169e` |
| 无空槽（36 张售罄） | AI 不买；人类点击被忽略 | `0x4316c9`、`0x42ff24` |
| 点击已售号码 | 忽略 | `0x42ff24` |
| 连续点击 | 每点一次扣 1000，**无现金复核**（可负） | `0x430004`、`0x42fff7` |
| 开奖时全无票 | 开奖视窗不显示（直接返回） | `0x431729` |
| 开奖号码无人买 | 无派彩、奖金与票**全部结转** | `0x430ac9`、`0x430afb` |
| 同一号码多人想买 | 结构上不可能（一格一个持有者） | 槽语义 |
| 玩家出局（`who_plays=0`） | 仍会被当作 AI 分支处理，但需 `现金 > 1000`（出局者现金已清 0 ⇒ 通常不触发） | `0x4315cc`、`0x40cd87` |

## 五之二、★ 乞丐：**破产者留在地图上的棋子**（`@source VA 0x0041b5fd`）`[A]`

> ★ 2026-09-16 補：本節此前**整段缺失**。本文件 §1.8 寫了 NPC（玩家編號 4..7 =
> 小偷/強盜/流氓/間諜），但**破產者留下的棋子**是另一回事 ——
> 全規格只在資料表裡出現過「乞丐」這個**名字**（`ui-labels.md` 第 38 項、
> `data-tables.md` 的類別 5），**沒有一處寫它的規則**。
> 是逐函式覆蓋審計（`tools/audit_spec_coverage.py`）翻出來的；
> remake 的 `rules/beggar.ts` 早已逐條譯好，本節在 exe 裡重核。

### 5b.1 一句話

**破產不會把棋子從地圖上收走。** `who_plays` 清成 0 之後，那顆棋子仍站在出局的那一格上，
成了**乞丐**：誰**停在**同一格，誰就得掏一筆施捨（進公庫），
然後乞丐**換個地方待著**。

### 5b.2 觸發條件（全部要滿足，逐條實測 `0x41b5fd..0x41b638`）

```asm
0041b5fd  cl = byte [0x49910c]              ; 當前玩家
0041b603  eax = 1 << cl / not eax
0041b60c  edi = [esp + 0x98]                ; ★ 該格的**玩家佔用位圖**（node+0x24 的 bits 8..11）
0041b613  edi &= eax                        ;   去掉我自己
0041b616  call 0x40d293                     ; ★ ctz = 最低置位的那一位
0041b61b  ebp = eax                         ;   同格的其他玩家下標
0041b620  if (ebp == -1) goto 尾            ; ① 同格沒別人 → 跳過
0041b628  cmp byte [ebp*0x68 + 0x496b7d], 0 ; = who_plays
0041b62f  jne 尾                            ; ② ★ **只有在場狀態為 0（出局者）才算乞丐**
0041b631  cmp dword [0x48baf8], 0
0041b638  jne 尾                            ; ③ ★ **路過不算**（必須停在這一格）
```

★ **只看下標最小的那一個**（`0x40d293` 返回位圖最低位）：兩個出局者站在同一格時，
**只有下標小的那個**能收到錢，另一個永遠收不到 —— 照搬原版即可，不必「公平輪流」。

### 5b.3 金額與付款

```asm
0041b63a  eax = priceIndex ; ebx = eax
0041b641  shl ebx,2 / sub ebx,eax           ; 3p
0041b646  shl ebx,3 / add ebx,eax           ; 25p
0041b64b  shl ebx,3                          ; 200p
0041b650  shl ebx,2 / add ebx,eax           ; ★ 800p + 200p = **1000 × 物價指數**
0041b656  sprintf(buf, "施捨給乞丐%d元")     ; 字串 @ VA 0x463ab1
0041b672  call 0x440cac(buf, 0x5dc)         ; 顯示提示（0x5dc = 1500）
0041b67a  push 0 / push ebx / push -1 / push 我
0041b686  call 0x41d2c6                     ; ★ pay_money(我, −1, 金額, 0) —— 收款方 −1 = **公庫**
0041b68f  call 0x40cc56(乞丐)               ; ★ 乞丐換地方
```

⇒ **`金額 = 1000 × 物價指數`**，付給**公庫**（不是給那個出局玩家 —— 他已出局，錢沒有意義）。

### 5b.4 乞丐換位 `0x40cc56(beggar)`（全函式 55 條，逐條讀過）

它其實是一支**通用的「把一個玩家（棋子）挪到隨機空格」原語**：

```asm
0040cc5d  edi = 0x100 << beggar             ; ★ 該玩家的佔用位（bits 8..11）
0040cc6b  cur = word [player + 0x0c]        ; 他現在的節點號
0040cc88  and dword [node[cur] + 0x24], ~edi   ; ★ 清掉舊格的佔用位
0040cc95  call 0x40aa6c(cur)                ; ★ **挑一格**（= pick_object_node，同物件投放那個挑法）
0040cca7  newNode = nodes[挑中的號]
0040ccb9  找 newNode 第一個非 0 的鄰接槽 → edx
0040ccd0  player.x(+0x08) = word [newNode + 0]      ; 位置三元組一起更新
0040ccdb  player.y(+0x0a) = word [newNode + 2]
0040cce2  player.node(+0x0c) = newNode 號
0040cce9  player.lastNode(+0x0e) = edx      ; ★ 記成「剛從那個鄰格走過來」
0040ccf2  call 0x407a8c(cur, edx)           ; 算朝向
0040ccfa  player+0x10 = al                  ; ★ 記朝向
0040cd00  or dword [newNode + 0x24], edi    ; ★ 在新格上置該玩家的佔用位
```

★ 兩點對複刻要緊：

1. **`0x40aa6c` 就是物件投放用的那個挑格器**（`object-landing.ts` 的
   `objectNodeCandidates`/`pickObjectNode` 那條線）—— 乞丐落點與神明/寶箱**同一套規則**；
2. 節點的 `+0x24` **bits 8..11 是「哪個玩家站在這格」**。
   本引擎**不鏡像**這份狀態（改成反查玩家的 `nodeId`），
   所以「乞丐落點不要壓到別人」這一條要**自己用玩家位置再過一遍** ——
   否則落點會與原版不同（`0x40aa6c` 的候選篩選裡含 `test [node+0x24], 0x80ffff00`）。

**呼叫者**：只有 `0x0041b68f` 這一處（施捨之後立刻換位）。

#### ★ 挑格器的边界（2026-09-18 通道 2 实测补）

`0x40aa6c` 与它的「远距重抽」版 `0x40aadf` 起那段，本轮用 Unicorn 逐条跑过
（`tests/test_object_remove.py`，31/31）：

| 事实 | 依据 |
|---|---|
| 候选判据 = `(node+0x24 & 0x80ffff00)==0` ∧ (**`node+0x18` 或 `node+0x1c` 非 0**) | `0x40aac3`..`0x40aad8`。★ 后一条就是「四个 `adjacent` u16 里至少一个非 0」（见 `map-format.md` §节点记录），**与「该格可走」等价** |
| 挑法 = `rand15() % 候选数`，**会用掉一个随机数** | `0x40aadf` |
| 参照点非 0 时：`|dx| ≥ 300` 或 `|dy| ≥ 300` 才收，否则**重掷** | `0x40ab08`..`0x40ab3b`（`_abs` 用 CRT 的 `0x458276`）|
| 参照点 = 0 ⇒ 一次都不重抽 | `0x40ab10 je` |
| ★★ **候选数为 0 时原版直接 `idiv 0` 崩** | `0x40aae9 idiv ebx`：`ebx` 就是候选计数 |

★ 最后一条是**原版的可崩点**（本轮测试真撞到了：把所有节点的 `+0x26` 物件字节
设成非 0 就一个候选都不剩）。复刻 `pickObjectNodeDistant` 在
`candidates.length === 0` 时直接返回 0 —— 属**有意偏离**（原版此刻已经崩了，
没有可观测的「正确行为」可对齐）。

★ 同族的 `_rich4_remove_object 0x40e14d`（物件收回）也已有通道 2 差分：
`tests/test_object_remove.py` 31 例（库存回归 / 神明修正回滚 / 节点占用 /
前 12 个物件的「搭档登场」）。

## 五之三、★ 公佈欄（玩家二级市场）：挂牌表的结构与存档块（`@source 0x4967e0`）`[A]`

> ★ 2026-09-16 補：本節此前**整段缺失** —— 全規格只在資料表/標籤表裡出現過
> 「公佈欄」這個**名字**（`ui-labels.md`、`data-tables.md`），
> **規則、槽結構、存檔塊都沒有**。是第 51 條的鏡像審計
> （`tools/audit_unimplemented.py`）把它牽出來的：remake 的
> `places/notice-board.ts` 早已逐條譯好，PRD 沒有對應章節。
> 下面每一條都在 exe 裡重核過。

### 5c.1 一句話

**公佈欄是玩家之間的二级市场**：把自己的**股票／地產／設施／道具／卡片**
挂上去标价出售，别人（或 AI）来买。整套机制挂在**一张 4 玩家 × 7 槽 × 12 字节**
的表上，運行時基址 `0x4967e0`（**步長 `0x54` = 7 × 12**），
存檔塊 `+0x2526`（336 字节）。

```asm
; ★ 步長 0x54 的來歷（每格 12 字节、每人 7 格）
00427edf  imul eax, dword [0x49910c], 0x54   ; 當前玩家 × 0x54
00427ee6  cmp  byte [eax + 0x496828], 0      ; 0x496828 = 0x4967e0 + 0x48 ⇒ **第 7 格**
```

### 5c.2 單格 12 字节的佈局（逐條實測 `0x004246c5`）

| 偏移 | 型別 | 語義 | `@source` |
|---|---|---|---|
| `+0x00` | u8 | **類型**：0 = 空、1 = 股票、2 = 地產/設施、3 = 道具、4 = 卡片 | `0x424725 mov byte [eax+0x4967e0], bl` |
| `+0x01` | u8 | **挂牌天龄**（見 §5c.4，**只寫不讀**） | `0x42472d mov byte [eax+0x4967e1], bh` |
| `+0x02` | **u16** | 物品編號（含義隨類型） | `0x424733 mov word [eax+0x4967e2], si` |
| `+0x04` | **u32** | **標價**（買家用**現金**付） | `0x42473e mov dword [eax+0x4967e4], ecx` |
| `+0x08` | **u16** | **股數** —— 只有類型 1（股票）用 | `0x424751 mov word [eax+0x4967e8], dx` |
| `+0x0a` | u8 | 只有類型 2 用：地產/設施的 `+0x18`（住宅/商業） | `0x424785 mov byte [eax+0x4967ea], bl` |
| `+0x0b` | u8 | 只有類型 2 用：地產/設施的 `+0x1a`（**等級**） | `0x42478f mov byte [eax+0x4967eb], dl` |

★ **三個易錯點**：
1. `+8` 是 **word**、`+a`/`+b` 是**兩個 byte** —— 12 字节**不是**三個 u32；
2. `+a`/`+b` 是**挂牌那一刻**的地產快照（類型與等級），不是現值；
3. 槽是靠「`+0 == 0`」判空的，別用 `+2`（編號可以合法地是 0）。

### 5c.3 挂牌 / 撤件 / 「板滿」

- **挂牌**（`@source 0x004246c5`）：從頭找**第一個空槽**；途中若遇到
  **同類型同編號**的已挂項就**覆蓋那一格**（不新占一格）；七格都占滿且沒有同項 ⇒
  挂不上（「公佈欄已滿，請先撤件！」）。
- **撤件**（`@source 0x004247d5`）：
  ```asm
  ebx = player*0x54 + 0x4967e0
  memmove(槽[slot], 槽[slot+1], (6 − slot) * 12)   ; 後面的往前挪
  memset(ebx + 0x48, 0, 0xc)                      ; 最後一格清零
  ```
  ⇒ **活槽永遠packed在前面**，空槽在後面。
- **板滿判定**只看最後一格：`cmp byte [player*0x54 + 0x496828], 0`（`0x427ee6`）。

### 5c.4 `+0x01` 那个字节：挂牌天龄（**只写不读**的死数据）

```
① 挂牌那一刻清零   0x00424712  mov byte [eax + 0x4967e1], 0
② 每**天** +1      0x00428475（唯一调用点在 0x0041cfc4，日期推进那一支）
     loop 玩家 (0 .. [0x499114]):
       if (player+0x15 == 0) continue    ; ★ 只跳过**出局者**
       loop 槽 (0..6):
         if (槽.+0 == 0) continue
         槽.+1 += 1
```

★ **两处订正**（remake 注释先前写的）：
1. 调用点不是 `0x0041cfb5`（那是前一条 `call 0x41d89e` 的**末字节**），
   实际 `call 0x428475` 在 **`0x0041cfc4`**；
2. 「只给**真人**记龄」**不准确** —— 闸门是 `whoPlays != 0`，
   **电脑玩家也照样 +1**，只是这一格**全 exe 没有一处读**（同 `f6` 那一列）。

⇒ 本欄位屬「表裡有、代碼不用」的數據，複刻**不建模**（`places/notice-board.ts` 有註釋
與回歸斷言），故存檔塊裡**每槽那一個 `+1` 字節**（28 個）仍走 `carry`。
槽裡其餘 11 個字節（`+0`/`+2`/`+4`/`+8`/`+a`/`+b`）**都已由 `state.noticeBoard` 寫出**
（第 52/53 條）：`+a`/`+b` 是**掛牌那一刻**的地產類型與等級，由
`Listing.estateType`/`estateLevel` 帶（掛牌時從地產/設施記錄快照），
公佈欄屏顯示的也是這兩格而不是現值 —— 掛完之後地主加蓋或改建，板子上不跟著變。

### 5c.4b ✅ 本節已由差分測試驗證

`tests/test_notice_board.py` 用 Unicorn 跑原版 `0x4246c5`（掛牌）/ `0x4247d5`（撤件），
把整張 4×7×12 的板**逐字節**與本節的規則比對 —— **11/11 通過**：
槽佈局（`+0/+1/+2/+4/+8/+a/+b`）、「先找第一個空槽、途中遇到**同類型同編號**
就**覆蓋那一格**」、七格滿則掛不上、撤件 = **前移 + 末格清零**、
地產/設施的快照取自各自表的 `+0x18`/`+0x1a`、以及每個玩家的欄互不影響。

⚠️ 測試台限制（見 `docs/verification.md` 通道 2）：原版 CRT `memcpy`
（`0x456de8`）用了 `mov es, ds` 的段寄存器技巧，本仿真器跑不了，
故測試把它**打樁成等價的 `rep movsb`** —— 被測的是撤件的**參數與順序**。

### 5c.5 存檔塊 `+0x2526`（336 字节）

## 七、未决清单（**不得**当作结论使用）

1. **`player+0x4c` 成对表的语义**：`0x40df69` 只证明它是「`(a,b)` 索引 + 下限夹 0 的 dword 表」；
   2018 头文件称 `hostility`（B 级线索），本文件不作为结论。保释时写入的
   `100×days×price_index` 到底代表「敌意降低」还是「欠款」未决。
2. **`player+0x17`（0x496b7f）的命名**：已确认它由设定表 `0x48be34+idx*6+3` 写入（`0x41e277`），
   并被监狱/医院保释当作目标组选择器使用；其界面含义未决。
3. **`0x40ceb6` / `0x40cef3` 的单实参调用**：days 取自调用者堆栈残值。NPC 分支不读 days 所以不崩，
   但这是否原版 bug 未决。
4. **命运文本 `0x465a7c`「#0198騎機車摔傷住院%d天」的调用点**未找到（命运表里应有对应条目）。
   监狱/医院公告板事件 `0x475e24[0]..[4]` 的文本与行为均已核实（§2.2 末尾表）。
5. **`player+0x18`（`0x496b80`，AI 自动贷款额度%）的写入者**：机械扫描未发现写指令 ⇒ 该分支可能是死代码（未决）。
6. **`0x453544` 金额输入框内部是否限制输入长度/非数字**未逐条核对；已确认它**不做「与上限比较后夹取」**，
   因此唯一使用它的贷款路径**可以输入超过许可额度的金额**（`0x435228` 之后无任何比较）。
7. **`+0x42`（0x496baa）天数字段的用途**：已确认入狱/入院时 `+= days` 且**无 `&0x7f`**；语义未决。
8. **假日表 `0x47ff4a` 的具体内容**（哪几天算假日）未逐条 dump；但**判定逻辑已确认**：
   `0x4523d5` → `0x4520a6(date)` 算出 `(日期序号 + 4) % 7`（**0 = 星期日**，`0x4520d5 idiv 7`），
   星期日返回 1；否则再查假日表 `0x47ff4a`（按 `[0x4991b6]`/`[0x4991b8]` + 日期索引，步长 12）非 0 也返回 1。
   故 **贷款到期日 = 放款日 + 90 天，并逐日顺延跳过星期日与假日表标记的日期**（`0x433b7e` 的循环）。
9. **`0x42ba97`（上市公司分红）的完整分配公式**：已确认「按持股比例 × 本月盈餘，进银行存款」骨架，
   以及持股表 `0x4971a0`（每玩家 96 字节 = 12 家公司 × 8 字节）与 `>10`/溢出等细节**未逐条核算**。
10. **乐透投注屏的号码↔美术对应（Q-LAYOUT-7）**：代码只给出 4×9 的点击几何、
    号码为 1..36、以及数字精灵索引 `= ASCII − 0x0b`（`0x430b8d`）；**背景号码图来自
    MKF 面板 `0xc/0xd/0xe`，代码无法证明每个格子显示哪个数字**。规则部分本文件已给全，
    布局/美术部分**未决**（需实机截图比对）。
11. **`0x44f2c2` 的台词选择逻辑**（按 `days > 6 / > 3 / …` 选哪一条）只确认了表地址与步长 108，
    各分支对应文本未逐条 dump。
12. **`0x40fc00`、`0x41d476`、`0x40d6be`、`0x40bf93`、`0x41906a` 的函数名**沿用上游符号（B 级），
    本文件只保证其**调用位置与实参**（A 级）。
