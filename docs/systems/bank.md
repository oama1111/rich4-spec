# 《大富翁4》(v3.11, 2001, 大宇) 银行系统 逆向规格笔记

- 真值：`Rich4/rich4.exe`（ImageBase 0x400000，32 位 PE，代码段 0x401000 起）
- 方法：`tools/rich4dis.py`（递归遍历全量建图）+ `../rich4-remake/tools/disasm.py`（按需裁决）+ capstone 线性复核。
  所有结论均已用「从函数入口线性反汇编 + 原始字节核对」复核过；`rich4-re/asm/*.asm` 只作为入口线索，未直接采信。
- 字符串编码：Big5/CP950。本文所有中文字符串均按 CP950 解码（`rich4-re` 里的 GBK 解出来的乱码是错的，例如
  `0x464af5` 真值是 `'%s\n\n償還銀行貸款\n\n%d元'`，不是 `'%s\n\n纕临蝗︽禪蹿\n\n%d元'`）。
- 玩家结构：基址 `0x496b68`，步长 `0x68`。字段（偏移/绝对地址）：
  - `0x15`/`0x496b7d` 状态标志字节（bit0=1 → 人类玩家，会开 UI；bit1=0x2、bit2=0x4、bit4=0x10、bit5=0x20、bit6=0x40 另有含义，见 §7/未决）
  - `0x18`/`0x496b80` 自动贷款比例（%，**只被读一次，exe 内无任何写入**，见 §2.5）
  - `0x19`/`0x496b81` `cashRatio`（现金比例 0..100，来自"玩家设定表"）
  - `0x1c`/`0x496b84` cash（现金）
  - `0x20`/`0x496b88` money_in_bank（存款）
  - `0x24`/`0x496b8c` loan（贷款）
  - `0x28`/`0x496b90` special_finance（= 银行经营者对客户的"特别融资"负债，见 §2.4）
  - `0x2c`/`0x496b94` loan_due_date（贷款到期日，打包日期，见 §2.3）
  - `0x32`/`0x496b9a` 忙碌/阻塞计数器（!=0 时部分天计数器不递减）
  - `0x34`/`0x496b9c` days_in_prison，`0x35`/`0x496b9d` days_in_hospital
  - `0x3b`/`0x496ba3` days_rejected_by_bank（银行拒绝往来天数，bit7=刚到期标志）
  - `0x3c`/`0x496ba4` bank_suspend_lending（银行暂停放款天数，bit7=刚到期标志）
  - `0x5c`/`0x496bc4` monthly_paid，`0x60`/`0x496bc8` monthly_received
- 日期全局 `0x497160`：`byte0 = 日`、`byte1 = 月`、`word[2] = 年`（证据：`0x451f8c` 拆包：`>>0x10`=年、`(>>8)&0xff`=月、`&0xff`=日）。
  日期推进 = `0x452117(&date)`（+1 天，月跨回时返回 1）；`0x451f8c(date)` = 自 1998-01-01 起的天数；`0x45218f(date,n)` = date+n 天；`0x4521aa(a,b)` = 天数差 **b − a**。
- x87 取整：`0x457dbc` 把 FPU 控制字高字节写成 `0x1f`（RC=11）再 `frndint` → **向零截断**。本文所有 `call 0x457dbc` 都是截断。

## §1 存款 / 取款（ATM 界面）

### 结论一句话
> ⚠️ **函数归属澄清（本轮修正机械层边界后新增）**：``0x437161`` **不是独立函数**，
> 它是 ``0x436ef8`（ATM 窗口过程）` 的**同函数基本块** —— 唯一引用它的是 ``0x436ef8`（ATM 窗口过程）` 内的条件跳转
> （`@source 0x00436f5f` 的 `je 0x437161`），且它**不是任何 `call` 的目标**。
> 下文为便于叙述把它称作"ATM 界面逻辑"，指的是**同一函数内的一段逻辑**，不是另一个函数。
> 判据与全量清单见 `../../01-mechanical-layer.md` §四之二 缺陷 3 与
> `gen/function-boundary-candidates.json`。

存款/取款**只在 ATM 界面**（`0x436ef8` 窗口过程，其界面逻辑段在同函数的 `0x437161` 处）进行；**无手续费、无税、无单向利息**；
金额由玩家手动输入（拖动条或数字键盘），取值范围 `[0, 上限]`，上限 = 存款时可动用的现金 / 取款时可动用的存款；
`0` 或取消 = 什么都不做；**取款上限就是存款余额，存款上限就是现金余额，不存在负数路径**。

### 精确规则（公式 / 表 / 取整语义）

**入口链**：落地银行格（格子事件 id 14，由行为反推：该 case 同时调 ATM 入口与银行格入口）→ `0x41b396` → `call 0x4379c9`（银行/ATM 入口）→
人类玩家（`[p+0x496b7d] == 1`）→ `0x437a2d..0x437a3c` 建窗口 `[0x48c3f4]` → `0x4018e7(0, 0x436ef8)` 进入 ATM 窗口过程。

**ATM 初始模式**（`0x436ef8` 的 `WM_USER+1 = 0x401` 分支）：

```
00436fd6  imul eax,[0x49910c],0x68
00436fdd  cmp byte ptr [eax+0x496ba4], 0     ; 银行暂停放款？
00436fe4  je 0x437041
; ---- 放款被暂停时：只给「存款」模式 ----
00437028  mov dword ptr [0x48c3f0], 1        ; mode=1 存款
00437039  mov eax,[eax+0x496b84]             ; 现金
00437072  mov [0x48c3ec], eax                ; 上限 = 现金
; ---- 正常时：默认「取款」模式 ----
0043705f  mov dword ptr [0x48c3f0], 0        ; mode=0 取款
0043706c  mov eax,[eax+0x496b88]             ; 存款
00437072  mov [0x48c3ec], eax                ; 上限 = 存款
```

**两个按钮**（`0x437161`，按格位表 `0x475888` 的按钮 1/2）：

| 按钮 | 代码 | 效果 |
|---|---|---|
| 按钮 1 | `0x4373ab`：`[0x48c3f0]=0`，`[0x48c3ec]=[p+0x496b88]`（存款余额） | 进入**取款**：上限=存款 |
| 按钮 2 | `0x4373eb`：`[0x48c3f0]=1`，`[0x48c3ec]=[p+0x496b84]`（现金） | 进入**存款**：上限=现金 |

**金额选择（拖动条）** `0x437413`（按钮 4）：

```
00437422  sub esi, 0x3a            ; esi = 鼠标 x - 0x3a
00437425  test esi,esi ; jge next
00437429  ebx = 0                  ; x < 0x3a → 金额 0
0043742d  cmp esi, 0xcc ; jl 0x43743d
00437435  ebx = [0x48c3ec]         ; x >= 0x3a+0xcc → 满额
0043743d  ecx = 6; idiv ecx        ; ebx = (x-0x3a) / 6
0043744d  ecx = 0x22 (34)
00437452  eax = [0x48c3ec]; idiv ecx   ; eax = 上限 / 34
0043745e  inc ebx ; inc eax
00437460  imul ebx, eax            ; ebx = (step+1) * (max/34 + 1)
00437463  if (ebx > max) ebx = max ; 夹到上限
0043746f  push 0xa; push 0x48c3f8; push ebx; call 0x457d61   ; itoa → 输入缓冲
00437481  push 1; call 0x436d3a    ; 重画指示条
```
→ 横条 0xcc=204 px，分 34 档（`0x464bd0 = 34.0f` 也正是 `0x436d3a` 画条用的系数），每档 6 px。

**数字键盘**（`0x4378b8`，字符表 `0x475914`）：最多 10 位（`0x43788d cmp eax,0xa; jge 跳过`），
输入后 `atoi`（`0x4584db`），若 `输入 > [0x48c3ec]` 则**直接把输入改写为上限**：

```
004378d3  mov edi,[0x48c3ec]        ; 上限
004378d9  cmp eax, edi ; jle 0x4378ed
004378dd  push 0xa; push 0x48c3f8; push edi; call 0x457d61   ; 改写为上限
```
→ 这是**超限保护（不是拒绝，而是夹到上限）**。`0x48c3f0`/`0x48c3ec` 之外的按键：`0x10`=全额（`0x4377ce` 把上限写进输入框），`0xf`=退格/清零（`0x43778c`），`0x11`=确认（`0x4377e6`），`2`=离开（`0x43775c`）。

**确认执行** `0x4377e6`：

```
004377e6  push 0x48c3f8; call 0x4584db    ; ebx = atoi(输入)
0043780d  test ebx,ebx ; je 0x437774      ; 0 → 直接关窗，什么也不做
00437815  edx = [0x49910c]
0043781b  imul eax, edx, 0x68
0043781e  cmp dword ptr [0x48c3f0], 0
00437825  jne 0x437856
; ---- mode 0：取款 ----
00437827  sub [eax+0x496b88], ebx          ; 存款 -= x
0043782d  add [eax+0x496b84], ebx          ; 现金 += x
00437833  mov eax,[eax+0x496b88]
00437839  mov [0x48c3ec], eax              ; 上限刷新为新的存款
00437845  call 0x41d433                    ; 刷新玩家信息窗
0043784d  push 1; call 0x436b0a            ; ★ 银行结算（见 §2.4）
00437854  jmp 0x437876
; ---- mode 1：存款 ----
00437856  add [eax+0x496b88], ebx          ; 存款 += x
0043785c  mov edi,[eax+0x496b84]
00437862  sub edi, ebx
00437864  mov [eax+0x496b84], edi          ; 现金 -= x
0043786a  mov [0x48c3ec], edi
00437870  push edx; call 0x41d433
00437876  ...（关窗）
```
注意：**取款路径会调用 `0x436b0a(1)`（银行资金对账），存款路径不会。**

### 边界情况表

| 情况 | 行为 | @source |
|---|---|---|
| 输入 0 | 关窗，不动钱 | `0x43780d je 0x437774` |
| 取款 > 存款 | 不可能：输入时被夹到上限 | `0x4378d9` |
| 存款 > 现金 | 不可能：同上 | `0x4378d9` |
| 负数 | 不可能：数字键盘只有 0-9 | `0x475914` 字符表 |

| 手续费/税 | **无**（全 exe 无任何对 deposit 的扣减逻辑） | — |
| 银行拒绝往来中 | ATM 入口直接拒绝并提示，见 §7 | `0x4379da` |
| 暂停放款中 | ATM 仍可存/取，只是默认模式变成"存款" | `0x436fdd` |

## §2 贷款

### §2.1 结论一句话
银行贷款**无利息**（全 exe 只找到一处 `1.1` 系数，用途是"提前还款的偿付能力门槛"，不是利率）；
贷款额度的**实际约束只有 `贷款总额 ≤ 净资产`**（`0x48c3b0`），且这个约束只用来**拒绝开框 / 给出默认值**，
玩家在数字键盘里**可以输入超过额度的金额（无夹取、无二次校验）**；
贷款期满 = 放款日 + 90 天（并按假日表顺延），到期日当天强制扣款，扣不满就破产。

### §2.2 手动贷款（银行窗口"申請貸款"按钮）

入口：`0x435d48`（银行窗口 `0x435062` 的按钮 2）→ 输入框 `0x435228`：

```
00435d48  imul eax, dword ptr [0x49910c], 0x68
00435d4f  cmp byte ptr [eax+0x496ba4], 0     ; 暂停放款中 → 直接返回
00435d56  jne 0x43518a
00435d5c  mov [0x48c3d5], 0x280
00435d66  mov [0x48c3d9], 0xffffffd8
00435d70  mov byte ptr [0x48c3dd], 5         ; 窗口状态 5
00435d77  mov eax, [eax+0x496b8c]            ; loan
00435d7d  cmp eax, dword ptr [0x48c3b0]      ; 对比 净资产(0x4239b9 的结果)
00435d83  jl 0x435d99
00435d85  mov edi, [0x475848]                ; '很抱歉！\n金額已超過\n許可額度。'
00435d8b  push edi; call 0x44ecb6            ; 弹提示后返回
00435d99  mov esi, [0x47583c]                ; '請輸入您要貸款\n的金額！'
00435d9f  jmp 0x435216                       ; → 状态 5 → 发 0x409 消息（输入框）
```

状态 5（`0x4356e5`）画框并 `SendMessage(hwnd, 0x409, 0, &rect)`；`0x409` 由 `0x435228` 处理：

```
00435228  mov eax, [ebx+0x496b8c]            ; loan
0043522e  mov edi, [0x48c3b0]                ; 净资产
00435234  cmp eax, edi
00435236  jge 0x435354                       ; loan >= 净资产 → 状态 8（放弃，什么都不做）
0043523c  mov eax, edi
0043523e  sub eax, [ebx+0x496b8c]            ; 默认值 = 净资产 − 已有贷款
00435244  push eax; call 0x453544            ; 数字键盘输入框（返回输入值）
0043524a  mov edx, eax
0043524f  test eax,eax ; je 0x435354         ; 0 → 放弃
00435257  mov ecx, [0x49910c]
0043525d  imul eax, ecx, 0x68
00435260  add [eax+0x496b88], edx            ; ★ 存款 += 贷款额
00435266  add [eax+0x496b8c], edx            ; ★ 贷款 += 贷款额
0043526d  call 0x433b7e                      ; 计算/刷新还款日（见 §2.3）
00435275  call 0x433d6e                      ; 重画 現金/存款/貸款 面板
0043527a  call 0x433f24                      ; 重画 玩家列表/還款日面板
```

**关键点：贷款金额不是进现金，而是进"存款"（`0x496b88`）**，要用 ATM 取款才能变成现金。
`0x453544`（数字键盘输入框）内部只 `0x48ca98 = 默认值` 并按比例画条（`0x45297e`/`0x453437` 里 `fild [0x48ca98]` 用于画比例），
**没有任何把输入夹到 `0x48ca98` 的代码**（`0x48ca98` 的读取点只有那两处画条代码 + 写入点 `0x4535fc`），
窗口过程 `0x452bc9` 也不读它 → **额度只是"建议默认值"**。

**贷款上限公式**：
```
上限(默认值) = wealth(player) − loan(player)
可开框条件  = loan(player) <  wealth(player)
```
其中 `wealth = 0x4239b9(player)`：

```
004239c7  mov edx, [eax+0x496b84]      ; cash
004239cd  add edx, [eax+0x496b88]      ; + deposit
004239d3  mov esi, [eax+0x496b8c]      ; loan
004239d9  sub edx, esi                 ; − loan
... 再累加： Σ_{s=0..11} trunc( 持股表 0x4971a0[player][s] × 股价表 0x496994[s] )   （12 只股票固定循环）
... 再累加： 住宅地 [0x498e84](步长0x34, 条数[0x498e98]) 与 商業用地 [0x498e88](步长0x38, 条数[0x498e8c]) 中 owner==player+1 的价值
```
（股票部分是 x87：`fild [ecx+eax*8+0x4971a0]` → `fmul [eax*4+0x496994]` → `call 0x457dbc` 截断 → `fistp`。
股价表步长是 **0x24** 而不是 4：`eax = 9*idx; fmul [eax*4+0x496994]`。
`0x48c3b0` 是 `0x436668` 进银行时算好快照并存的，所以窗口里的"额度"是**落地那一刻**的净资产。
**本节与 `docs/systems/economy.md`（同目录、由另一路逆向产出）完全一致**；该文档还带 `tests/test_wealth.py` 12/12 验证，
两边对 `0x457dbc` 的"向零截断"结论也一致。**唯一补充**：`0x496b90`（special_finance）**不计入** wealth
（`0x4239c7..0x423ace` 的读取列表里没有 `0x496b90`），与 economy.md 的未决 #2 相同——本笔记 §2.6 给出了它的语义。）

**注意与 rich4-re 的冲突**：字符串 `0x475838 '#0077您的貸款額度\n為一百萬元。'`（"额度为一百万元"）**在整个 exe 里没有任何引用**
（`xr 0x475838` = 0 处），是**死字符串**。真正的额度公式就是上面的 `wealth − loan`，不是固定 1,000,000。

### §2.3 还款日 / 期限

`0x433b7e(player)`（贷款成功、以及 AI 放款时都会调用）：

```
00433b88  cmp dword ptr [ebx+0x496b94], 0     ; 已有还款日就不重算
00433b8f  jne 0x433bd4
00433b91  push 0x5a                           ; 90
00433b93  mov ecx, [0x497160]                 ; 今天
00433b99  push ecx
00433b9a  call 0x45218f                       ; = 今天 + 90 天（打包日期）
00433ba2  mov [ebx+0x496b94], eax             ; 存入 0x2c
00433bab  mov edi, [ebx+0x496b94]
00433bb2  call 0x4523d5                       ; 该日期是否"非营业日"？
00433bba  cmp eax, 1 ; jne 0x433bd4
00433bbf  lea eax, [player_struct + 0x2c]     ; &loan_due_date
00433bca  call 0x452117                       ; +1 天，循环直到是营业日
```
- `0x4523d5(&date)`：`0x4520a6(date)` 算出 `(daynum+4)%7`（0 = 星期日）→ 星期日返回 1；
  再查假日表 `0x47ff4a`（按 `[0x4991b6],[0x4991b8]` 索引 + 日期索引，步长 12）非 0 也返回 1。
  → **还款日 = 放款日+90 天，并逐日顺延跳过星期日与假日表标记的假日**。
- 界面上"距還款日%d天"来自 `0x433f24`：`0x4521aa([0x497160], [p+0x496b94])`（= 到期日 − 今天），格式串 `0x464a74 '距還款日%d天'`。

### §2.4 手动还款（"償還貸款"按钮）

`0x435da4` → 状态 9 → `0x435360`：

```

00435db2  je 0x43518a
00435dd3  mov edi, [0x47584c]             ; '請輸入您預備\n還款的金額！'
...
00435360  mov edi, [ebx+0x496b8c]         ; 默认值 = 当前贷款
00435367  call 0x453544                   ; 输入框
00435373  test eax,eax ; je 0x435354      ; 0 → 放弃
0043537e  mov ecx, [eax+0x496b84]         ; cash
00435384  mov edi, [eax+0x496b88]         ; deposit
0043538a  add ecx, edi
0043538c  cmp edx, ecx
```

## §3 利息结算

### 结论一句话
**只有存款有利息，且只有月结（每月 1 日）时结算一次：`存款 = trunc(存款 × 1.1)`（即 +10%），
且只有"当前无贷款(`loan == 0`)"的玩家才能拿到；贷款完全无利息。**
利率 `1.1` 是数据段 double 常量 `0x464e88`；物价指数 `0x4990e8` **不参与任何银行计算**。

### §3.1 结算时点（精确链）

### §3.3 贷款利息
**不存在。** 证据：
- `0x496b8c`（loan）的全部 21 条指令级引用（`gx 0x496b8c`）：写入点只有手动贷款 `0x435266`、
  手动还款 `0x4353ce`、AI 放款 `0x4368fc`、AI 还款/强执 `0x436acf`/`0x436888`、机会事件加贷 `0x44c1fa`、
  玩家设定初始化 `0x416652`/`0x42c7e3` 等；**没有任何"按比例增大 loan"的写入**。
- 强制到期（`0x436a9b`）与 AI 提前还款（`0x43682d`）都是 `0x433bd8(player, loan)` —— 还**本金原值**。
- exe 里唯一的 `1.1` double `0x464b24` 只被 `0x4367fe` 引用，用途是 `loan*1.1 > cash+deposit` 的**偿付能力判定**（§2.5）。
- 银行窗口/经营者窗口的所有提示串里没有任何"利息/利率"字样。

## §4 破产与贷款

### 结论一句话
破产条件是"**要付钱时，存款+现金扣完仍不够**"（`0x433bd8` / `0x41d2c6` 里负余额检测）；
**贷款到期强制扣款是导致破产的主要路径之一**；破产时该玩家的
**0x1c..0x67 全部字段（含存款、贷款、特别融资、点数、各种天计数）被一次性 `memset` 清零**，
玩家状态置为出局，其地块（含银行经营权）被释放。

> 证据级别 **A**（逐条反汇编 `rich4.exe`，VA 与指令均可在 `gen/db.txt` 复核）。

#### 结论一句话

破产清算在**非终局**路径上依次做五件事：释放地产与設施（归属清 0、**地契到期日清 0**、
等级保留）→ 清企業归属 → 卖掉全部持股（进公库）→ 变卖道具与手牌 →
**释放超过 3 处地产时，随机挑 3 处当场开拍**（卖方席位空着，成交款进公库）。
**终局路径整个跳过**（只剩 1 人或 0 人时，地产原样留着）。

**三条最容易做错的**：
1. **只有释放 > 3 处才拍**，而且**只拍 3 场** —— 不是把释放的地全拍掉；
2. 候选表里**地块与設施混在一条**，`rand() % esi` 的分母是两者之和；
3. 每抽一场就把它划掉，**重复抽到空槽要重新掷**（`0x40d20a je 0x40d1f7`）——
   这一步真的消耗随机数，不能用「洗牌取前 3」代替，否则后续随机序列错位。

★ 这几场拍卖的**随机数消费**见 `magic-house.md` §5.2.1：
每场开拍按「可出价的电脑座位数 N」消费 `2N` 个 `_libc_rand`，
故下線拍卖把全局随机流推进了 `2×(三场各自 N 之和 + 被抽中的候选顺序所耗)`。
抽签本身（`0x40d1f7` 的 `rand() % esi`，含空槽重抽）也在这条链上，
两者都要建模才谈得上轨迹可复现。

**`0x43bde5` 的实参约定**（六个调用点比对得出）：

| 调用点 | arg1（卖方） | arg2（实体号） | arg3（横幅） |
|---|---|---|---|
| 拍賣卡 地块 `0x44334f` | 行动者 | 地块号 + 2000 | 1 |
| 拍賣卡 設施 `0x443476` | 行动者 | 設施号 + 4000 | 1 |
| 魔法屋 `0x4324d5` | 中签者 | 他脚下那格的实体 | 1 |
| 新聞 7 `0x4498a1` | **−1** | 随机无主地 | 1 |
| 破产清算 `0x40d1e3` | **−1** | 候选表里那一处 | **0** |

`arg1 = -1` ⇒ 没有卖方席位，成交款走 `pay(中标者, −1, 成交价, 0)` 进**公库**
（`0x43c844` 处 `push ecx` 传的就是 arg1）。

## §5 `cashRatio`（`0x496b81`，偏移 0x19）重分机制 —— **复核结果：与 rich4-re 说法冲突**

### 结论一句话
`0x496b81` 是**玩家设定画面里的"现金比例（0..100）"**，它有两个用途：
1. **开局**：`cash = trunc(cashRatio × 初始资金 / 100)`，`存款 = 初始资金 − cash`；
2. **AI 玩家用 ATM 时**按比例自动重分现金/存款（并按"今天几号"做 1.5× / 0.5× 调整）。
★★ **2026-09-19 订正（第 97 条，通道 2：`tests/test_bank_square.py` 29/29）**：
本段原先写「银行格的代码**完全不读** `0x496b81`」——**与它自己列的 xref 矛盾**：
三条读指令里的 **`0x437b02` 就在銀行格处理函数 `0x4379c9` 里**（`0x437acd` 起的**电脑分支**）。
准确的划分是：

| 分支 | 读 `cashRatio`？ | 做什么 |
|---|---|---|
| 真人（`[p+0x15] == 1`）| **否** | 开 ATM 模态屏，**手动**存取（§1）|
| 电脑（其余）| **是**（`0x437b02`）| 按比例把現金/存款**重分**一次（见 §5.1）|

（`0x436668`/`0x435062`/`0x434492` 那几个函数确实不读它 —— 它们是**手动的**存取款屏。）

### §5.1 电脑在銀行格的「按比例重分」—— 完整规则（通道 2 已驱动）

`@source VA 0x437acd`..`0x437c24`（`0x4379c9` 的电脑分支）。顺序：

```asm
00437ada  ah = [player + 0x3b]                 ; ★ 先看「銀行拒絕往來」剩余天数
00437ae0  if (ah != 0) { printf("銀行拒絕往來\n\n還剩%d天！", (ah & 0x7f)+1) ; 显示 1000ms ; 返回 }
00437acd  ecx = [0x497160] & 0xff              ; 今天（低字节 = 日）
00437ad9  ebx = 現金(+0x1c) + 存款(+0x20)       ; 总资产
00437ae5  ratio  = f32(現金 / 总资产)
00437b02  target = f32(f32([player+0x19]) / 100.0f)   ; ★ 就是 cashRatio
00437b23  if (日 <= 7)  target = f32(target × 1.5)    ; 月初多留现金
00437b3c  if (日 >= 26) target = f32(target × 0.5)    ; 月末少留现金
00437b55  if (target >= 1.0f) target = 0.9f ；else if (target <= 0f) target = 0.1f
00437b88  diff = ratio − target
00437ba6  if (diff >= +0.25 || diff <= −0.25) 重分
00437bc1  else if (現金 == 0) 重分                  ; ★ 恰好没钱时必须给
00437bca  新現金 = trunc(总资产 × target) ; 存款 = 总资产 − 新現金
00437c0a  重绘 ; call 0x436b0a(1)（存取款动画）
```

★ **两个容易算错的点**（都已被差分钉住）：

1. 两端夹取写的是 **f32 常量** `0x3f666666`/`0x3dcccccd` ⇒ `trunc(10000 × f32(0.9)) = 8999`
   （不是 9000）；同理 `f32(0.63) < 0.63` ⇒ `10000 × 0.63 ⇒ 6299`。
2. `±0.25` **带内不动**（`diff` 的两次比较是 double 的 `0x464c20`/`0x464c28`），
   但**現金恰好为 0 时例外**（那一支必须给钱，否则永远取不出钱）。

⚠️ **总资产 = 0 的数值事故**：原版这时 `0/0 = NaN`，NaN 比较全为「无序」⇒ 落进重分那一支，
`fistp` 把 NaN 写成 `0x80000000`，現金与存款**双双变成 −2147483648**。那是数值事故不是规则，
复刻**有意不同**（原样返回），登记在 `rich4-remake/docs/known-deviations.md` 的 Q-BANK-3。

### 精确规则（公式 / 表 / 取整语义）

**(a) 谁会写它** —— 只有"玩家设定表 ↔ 玩家结构"的搬运：
```
0x41e25f  mov byte ptr [ecx+0x496b7d], bl   ; [eax+0x48be35]
0x41e26b  mov byte ptr [ecx+0x496b7e], bl   ; [eax+0x48be36]
0x41e277  mov byte ptr [ecx+0x496b7f], bl   ; [eax+0x48be37]
0x41e283  mov byte ptr [ecx+0x496b81], bl   ; ★ [eax+0x48be38] → cashRatio
0x41e28f  mov byte ptr [ecx+0x496b82], al   ; [eax+0x48be39]
   （eax = 6*i，表 0x48be34；ecx = (表[0]==0 ? 跳过 : (表[0]-1)*0x68)）
反向搬运在 0x41e345：0x41e608 mov dl,[ebx+0x496b81] → [eax*2+0x48be38]
```
注意：这次搬运**跳过了偏移 0x18（`0x496b80`）**，印证 §2.5 的"0x18 无人写"。
设定画面 `0x41da61` 把它画成 0..100、步长 10 的十格红条：
```
0041dacf  edx = [0x48be4c]（当前玩家槽）
0041dadc  al = [eax*2 + 0x48be38]           ; cashRatio 0..100
0041dae8  cmp eax, ebx（ebx=0,10,...,90）; jle 跳过
0041daec  push 0xff0000 ...                 ; 高于该段的格子涂红
```

**(b) 开局分配（唯一"按比例重分"的初始化）**
```
004071d4  xor eax,eax
004071d6  mov al, [esi + 0x496b81]          ; cashRatio
004071e0  fild dword ptr [esp+0xc]          ; （capstone 误报 word；原字节 DF 44 24 0C = fild m32）
004071e4  fild dword ptr [0x49908c]         ; 初始资金
004071ea  fdiv dword ptr [0x463190]         ; ★ 0x463190 = float 100.0
004071f0  fmulp st(1), st                   ; = cashRatio * 初始资金 / 100
004071f2  call 0x457dbc                     ; 向零截断
004071f7  fistp dword ptr [esp]
004071fa  mov eax, [esp]
004071fd  mov [esi + 0x496b84], eax         ; ★ cash = trunc(cashRatio * 初始资金 / 100)
00407203  mov eax, [0x49908c]
00407208  mov edx, [esi + 0x496b84]
0040720e  sub eax, edx
00407210  mov [esi + 0x496b88], eax         ; ★ 存款 = 初始资金 − cash
```
（`0x49908c` = 初始资金，来自 `0x40717e mov [0x49908c], [eax*4+0x46cb94]`；`0x463190 = 100.0f`，
下一个常量 `0x463194 = 10.0f`。）

**(c) AI 用 ATM 时的按比例重分**（`0x4379c9` 的"非人类"分支，`0x437acd`..`0x437c03`）
```
00437acd  ecx = [0x497160] & 0xff                 ; ★ 日（byte0 = 日）
00437ad9  ebx = [p+0x496b84] + [p+0x496b88]       ; 总资产
00437ae5  fild [p+0x496b84]; fild [esp+0x90](总资产); fdivp  → [esp+0x8c] = 现金占比 cf
00437b02  mov al, [p + 0x496b81]                  ; ★ cashRatio
00437b0f  fild ...（m32）
00437b16  fdiv dword ptr [0x464c08]               ; ★ 0x464c08 = float 100.0 → r = cashRatio/100
00437b23  cmp ecx, 7 ; jg 0x437b3c
00437b28  fmul qword ptr [0x464c10]               ; ★ 0x464c10 = double 1.5  （日 <= 7）
00437b3c  cmp ecx, 0x1a ; jl 0x437b55
00437b41  fmul qword ptr [0x464c18]               ; ★ 0x464c18 = double 0.5  （日 >= 26）
00437b55  cmp dword [esp+0x88], 0x3f800000 ; jl 0x437b6f
00437b62  mov dword [esp+0x88], 0x3f666666        ; r >= 1.0 → r = 0.9f
00437b6f  fldz; fcomp [esp+0x88]; ... jb 0x437b88
00437b7d  mov dword [esp+0x88], 0x3dcccccd        ; r <= 0.0 → r = 0.1f
; 是否需要动手
00437b88  fld [esp+0x88]; fsub [esp+0x8c]         ; r − cf
00437b96  fst qword [esp+0x80]
00437b9d  fcomp qword ptr [0x464c20]              ; ★ 0x464c20 = double 0.25
00437ba6  jae 0x437bca                            ; r−cf >= 0.25 → 动手
00437ba8  fld qword [esp+0x80]
00437baf  fcomp qword ptr [0x464c28]              ; ★ 0x464c28 = double -0.25
00437bb8  jbe 0x437bca                            ; r−cf <= -0.25 → 动手
00437bba  cmp dword ptr [p+0x496b84], 0
00437bc8  jne 0x437c1c                            ; 现金 != 0 → 什么都不做
; 执行
00437bd1  fild 总资产; fmul dword [esp+0x88]; call 0x457dbc; fistp → 新现金
00437bfb  mov [p+0x496b84], 新现金
00437c01  sub ebx, 新现金
00437c03  mov [p+0x496b88], ebx                   ; 存款 = 总资产 − 新现金
00437c0a  call 0x41d433(player)
00437c14  push 1; call 0x436b0a                   ; 银行对账
```
**公式**：`r = clamp(cashRatio/100 × f(日), 0.1, 0.9)`，其中 `f = 1.5 (日≤7) / 1.0 / 0.5 (日≥26)`；
触发条件 `|r − 现金占比| ≥ 0.25` 或 `现金 == 0`；执行 `现金 = trunc(总资产 × r)`、`存款 = 总资产 − 现金`。
clamp 用的是 `float` 立即数：`0.9f = 0x3f666666`、`0.1f = 0x3dcccccd`。

### 边界情况表

| 情况 | 行为 | @source |
|---|---|---|
| 新开局 | `cash = trunc(ratio×初始资金/100)`，存款拿余数 | `0x4071fd`/`0x407210` |
| 人类玩家到银行 | **完全不读 0x496b81**（只有 `0x4071d6`/`0x41e602`/`0x437b02` 三处读） | `gx 0x496b81` |
| 人类玩家用 ATM | 手动输入金额（§1） | `0x437161` |
| AI 用 ATM | 按比例重分（上式） | `0x437acd` |
| 日 ≤ 7 | `r ×= 1.5` | `0x464c10` |
| 日 ≥ 26 | `r ×= 0.5` | `0x464c18` |
| `r` 越界 | 夹到 `[0.1, 0.9]` | `0x3dcccccd`/`0x3f666666` |
| 占比差 < 0.25 且现金 != 0 | 不动 | `0x437bba`/`0x437bc8` |

- `cashRatio` 的**取值范围**由设定画面限制为 0..100、步长 10（红条 10 格），但字节本身没有掩码；
  存档若塞入 >100 的值，`(c)` 路径会先算 `r` 再被 clamp 到 0.9，`(b)` 路径会算出 > 初始资金的现金

- `0x41dadc` 画红条时 `[0x48be4c]` 的槽位语义（当前设定中的玩家槽）**未决**。

## §6 `days_rejected_by_bank`（`0x496ba3`，偏移 0x3b）的用途

### 结论一句话
它是**"銀行拒絕往來"剩余天数**：非 0 时**银行格事件整体被跳过**、**ATM 入口直接拒绝并公告**；
只有"機會/命運：銀行拒絕往來一個月"这一个事件会 `+= 30`；它**每个该玩家的回合减 1**（不是每天减 1），
减到 0 的那一回合会被置成 `0x80`（"刚到期"标志），下一回合再清 0。

### 精确规则

**写入点（全 exe 只有 3 类指令）**：`gx 0x496ba3` 给出 8 条，其中写入只有 3 条，全部在 `0x41c84f` 的递减/清标志逻辑里 + 事件 `+30`：

```
; ★ 唯一的"设置"：機會/命運 事件（0x44c229 分支内的 0x44c2ba）
0044c27c  push 1; push 0; call 0x44b896        ; 抽事件
0044c28d  cmp eax, 1 ; jne 0x44c2b3
0044c292  ... 弹 0x48c5b8（事件文本缓冲）
0044c2b2  ret
0044c2b3  imul eax, dword ptr [0x49910c], 0x68
0044c2ba  add byte ptr [eax + 0x496ba3], 0x1e  ; ★★ +30 天
0044c2c1  ret
```
对应字符串：`0x465967 '銀行拒絕往來一個月'`（该串在 exe 内**无绝对地址引用**，说明它是被整块拷进 `0x48c5b8` 文本缓冲的，
归属的事件文本表**未决**）。同一族的事件还有 `0x44c2c2` 分支：`[0x48c5b0]=10`，
`sprintf(0x46597a '#0189侵入銀行電腦', 10)`，然后对每个"其他活跃玩家且存款 != 0"的玩家
`trunc(存款 × 10/100)` 从对方**存款**转到我方**存款**（`0x41d2c6(victim, me, amount, flags=4)`，见 §附A）。

**递减/清标志**（`0x41c84f(player)`，每个玩家回合开始时由 `0x419039` 调用一次）：
```
; 清"刚到期"标志
0041caa6  test byte ptr [eax+0x496ba3], 0x80
0041caad  je 0x41cab7
0041caaf  xor dl,dl
0041cab1  mov byte ptr [eax+0x496ba3], dl      ; 0x80 → 0
; 递减（注意：这一段不在 0x496b9a 的门控里）
0041cb94  mov cl, byte ptr [eax+0x496ba3]
0041cb9a  test cl,cl ; je 0x41cbb5
0041cb9e  mov ch, cl
0041cba0  dec ch
0041cba2  mov byte ptr [eax+0x496ba3], ch
0041cba8  jne 0x41cbb5
0041cbaa  mov dh, ch
0041cbac  or  dh, 0x80
0041cbaf  mov byte ptr [eax+0x496ba3], dh      ; 递减到 0 → 存 0x80
```
**递减粒度**：`0x41c84f` 每个玩家回合调用一次；而"日期 +1 天"只在整轮绕回时发生
（`0x418fbb cmp esi,8; ... 0x418fc3 mov ebx,1` → `0x41902a test ebx,ebx; 0x41902e call 0x41cf67`）。
→ **N 人局里 30 的拒绝值实际只持续约 30/N 天**。这是原版实现，不是理解偏差。

**读点（门禁）**：
```
; (1) 银行格：一切都被跳过
0043667b  cmp byte ptr [eax+0x496ba3], 0
00436682  jne 0x436953                        ; → 函数直接返回，窗口也不开
; (2) ATM 入口：拒绝 + 公告
004379da  mov ah, byte ptr [edx+0x496ba3]
004379e0  test ah,ah ; je 0x437a18
004379e4  mov al, ah
004379e6  and al, 0x7f
004379ed  inc eax                             ; 显示天数 = (value & 0x7f) + 1
004379ef  push 0x464bed                       ; '銀行拒絕往來\n\n還剩%d天！'
004379f9  call 0x457110                       ; sprintf
00437a0b  call 0x440cac                       ; 弹 1000ms
00437a13  jmp 0x437c1c                        ; 返回，不做任何事
```

### 边界情况表

| 情况 | 行为 | @source |
|---|---|---|
| `0x496ba3 != 0`（含 0x80 态） | 银行格事件完全不发生；ATM 弹"拒絕往來" | `0x43667b`、`0x4379e0` |
| 值 = 0x80（刚到期） | 仍视为"拒绝中"（显示天数 = (0x80&0x7f)+1 = 1） | `0x4379e6` |
| 递减粒度 | 每个玩家回合 −1（不是每天） | `0x41cb94` + `0x419039`/`0x41cf67` |
| 事件设置 | `+= 30`（可叠加！同一玩家连续中招会累加） | `0x44c2ba` |
| 是否存在其它写入者 | **不存在**：任务提示里把 `0x436668` 列为写入者是错的——`0x436668` 只**读**它 | `gx 0x496ba3` |

### 未决
- 触发 `+30` 的具体 機會/命運 事件编号 / 文本表入口 **未决**（字符串 `0x465967` 无绝对引用，被整块拷贝到 `0x48c5b8`）。
- 该事件是否**同时**有其它副作用（如罚款）：`0x44c229` 的 `arg != 0` 分支（0x44c27c）看起来只是抽事件 + 显示，
  但 `0x44b896(0,1)` 的返回语义 **未决**。

## §7 银行在什么条件下拒绝服务

### 结论一句话
四个独立门禁：**(A) 拒絕往來（0x496ba3 != 0）→ 格子事件全跳过 + ATM 拒绝**；
**(B) 暫停放款（0x496ba4 != 0）→ 只能存/取款、不能贷款**；
**(C) 贷款额 ≥ 净资产 → 弹"超過許可額度"**；**(D) 还款额 > 现金+存款 → 弹"現金不足"（不扣款）**。

### 精确规则

| 门禁 | 条件 | 读点 | 表现 | 字符串 |
|---|---|---|---|---|
| A 拒絕往來 | `[p+0x496ba3] != 0` | `0x43667b`（格子）、`0x4379da`（ATM） | 格子：什么都不发生；ATM：弹窗后返回 | `0x464bed '銀行拒絕往來\n\n還剩%d天！'` |
| B 暫停放款 | `[p+0x496ba4] != 0` | `0x4368ce`（AI 放款）、`0x435d4f`（貸款按钮）、`0x436fdd`（ATM 默认模式）、`0x4371e5`（ATM 界面）、`0x4341e7`/`0x434313`（经营者窗口盖章） | 不能新贷款；ATM 默认变存款模式；窗口/ATM 弹提示 | `0x464bd4/0x464ad5 '銀行暫停放款\n\n還剩%d天！'` |
| C 超额 | `loan >= wealth(0x48c3b0)` | `0x435d7d` | 不进入输入框，弹提示 | `0x475848 '#0081很抱歉！\n金額已超過\n許可額度。'` |
| D 现金不足 | `输入 > cash + deposit` | `0x4346e9`（经营者归还）、`0x43538c`（还贷） | 弹提示，**不扣款** | `0x475850 '#0083很抱歉！\n您的現金不足。'`、`0x47586c '#0090董事長您別開玩笑了～'` |

**B 的设置者**（唯一）：
```
; 0x44ae89 —— 機會/命運 '#0171銀行擠兌停止放款１５天'
0044ae9e  push 0x4656ef                        ; '#0171銀行擠兌停止放款１５天'
0044aeac  call 0x44fabc                        ; 画提示
0044aeb6  mov bh, 0xf                          ; ★ 15
0044aeb8  mov ecx, [0x499114]
0044aebe  cmp edx, ecx ; jge 结束
0044aec6  imul eax, edx, 0x68
0044aec9  cmp byte ptr [eax+0x496b7d], 0
0044aed0  je 跳过
0044aed2  mov byte ptr [eax+0x496ba4], bh      ; ★★ 全体活跃玩家 = 15 天
```
递减/清标志在 `0x41c84f` 的 `0x41caba`/`0x41cbb8`/`0x41cbd5`（与 §6 同构，粒度也是"每玩家回合 −1"）。

**其它相关门禁**：`0x436668` 开头 `[p+0x496ba3] != 0 → 全跳过`；AI 自动放款还额外要求
`rand()%10 == 0 || cash+deposit < 30000`（`0x4368a4`/`0x4368bb`）。

### 边界情况表
| 情况 | 结果 |
|---|---|
| 拒絕往來 + 暫停放款 同时非 0 | 格子事件先被 A 拦掉，B 无从谈起 |
| 暫停放款中按"申請貸款" | 按钮无响应（`0x435d4f jne 0x43518a`） |
| 暫停放款中开 ATM | 只给"存款"模式（`0x436fdd`） |
| `loan == 0` 按"償還貸款" | 按钮无响应（`0x435db2`） |
| 非经营者 | 银行窗口只有 4 个按钮中的前 3 个可用（第 4 个 `0x435de2 je 0x43518a`） |
| 经营者按"週轉現金"且 特别融资 ≥ 其他玩家存款总额 | 该动作不可用（`0x434e7f jge 0x434fa1`） |

### 未决
- `0x48c3d5`/`0x48c3d9`（窗口滑入动画偏移）与 `0x48c3dd` 各状态的**视觉**含义只做了行为级确认，**像素级未核**。
- `[0x497159]`（控制是否弹问候语，`0x435200`、`0x437f39`、`0x43825b` 等多处）语义疑似"快速/静音模式"，
  写入点 `0x411ee2`，**确切开关来源未决**。

## §附A：金钱原语（银行规则依赖，已确认）

`0x41d2c6(payer, receiver, amount, flags)`（`# 91 insns`，`callers=['0x40ec14','0x40ef1b','0x40efe4','0x442325']` + 事件：

```
0041d2d6  cmp esi, 0x64 ; jle 0x41d2f3     ; payer > 100 → 当作"产业/公司"索引
0041d2f6  test byte ptr [esp+0x20], 4      ; ★ flags bit2 = 从"存款"付款
0041d2fb  je 0x41d33d                      ; 否则从"现金"付款
0041d2fd  mov ecx,[eax+0x496b88]; sub ecx,ebx; mov [eax+0x496b88],ecx   ; 存款 -= amount
0041d30b  test ecx,ecx ; jge 0x41d37e
0041d313  mov edx,ecx
0041d315  add [eax+0x496b84], edx          ; 存款不足 → 现金补
0041d31d  mov [eax+0x496b88], 0
0041d32d  add ebx, edx                     ; 修正可支付额
0041d339  xor ebx,ebx                      ; 现金也不够 → amount 归 0
0041d375  push esi; call 0x40cd87          ; ★ 破产
0041d381  add [eax+0x496bc4], ebx          ; ★ monthly_paid(0x5c) += 实付
0041d387  cmp edi, -1 ; jne ...
0041d38c  add [0x499080], ebx              ; receiver == -1 → 进全局池
0041d3b2  test byte ptr [esp+0x20], 1      ; ★ flags bit0 = 收款进"现金"
0041d3b9  add [eax+0x496b84], ebx          ; 进现金
0041d3c1  add [eax+0x496b88], ebx          ; 否则进存款
0041d3ca  add [eax+0x496bc8], ebx          ; ★ monthly_received(0x60) += 实收
```
`0x41d3f4(player, amount, flags)` = 纯进账版本（`flags bit0=1 → 现金`，否则存款），同样累加 `0x496bc8`。
**银行相关的调用组合**：
- `pay(victim, me, x, flags=4)` → 对方的**存款**减少、我的**存款**增加（`0x44c3a3`，挪用存款事件）；
- `0x41d3f4(player, bonus, 0)` → 直接给玩家**存款**加钱（`0x44af66`，10% 紅利事件）。

`0x43b7e`/`0x433d6e`/`0x433f24`/`0x433c20` 均为**纯 UI**（面板重画），无金钱副作用（已逐条确认无 `0x496b84/88/8c` 写入）。

★★ **通道 2 已差分**（2026 本轮，`tests/test_money_move.py` 29/29，直接 `call` 两个原语）：

| 验到的点 | 结论 |
|---|---|
| `flags & 4` | **存款优先**付款；未置位则现金优先（两条级联各有一份，别合并） |
| `flags & 1` | 收款进**现金**，否则进**存款** |
| 级联顺序 | 现金→存款（或存款→现金）：先抽干一侧，再抽另一侧 |
| **实付额** | 两边都抽干仍不够时，`amount` 被**截断为实有总额**；`+0x5c` 累计的是**实付额**（不是请求额） |
| 破产触发条件 | 只有「两侧都归零**且仍差**」才 `call 0x40cd87`；**恰好付清不触发** |
| 企业付款 | `+0x28`/`+0x2c` 各减；**不累计** `+0x5c`；付款方玩家完全不动 |
| 企业收款 | `+0x28`/`+0x2c` 各加；玩家付款方照常累计 `+0x5c` |
| 公库 | `payee == -1` → `[0x499080] += 实付额`，没有玩家收款记录 |
| 返回值 | `give_money` 的 eax 是残留的 `player*0x68`，**调用方不读** |

> ⚠️ **诚实边界（破产分支）**：真缺口时 `0x40cd87` 会走到 `mkf_read_resource`（读 MKF
> 资源文件），在纯仿真里 `UC_ERR_READ_UNMAPPED @0x450471` —— 用例断言到
> **「`whoPlays` 已被清 0」**为止（该标记在资源加载**之前**就写了），
> 破产处理内部（位置还原 `[0x498e80]` 表、地块标记位、回到 `+0x5c += 实付`
> 这一步）**尚未差分**，仍需原版侧调试器或 MKF 装载桩。

### ⚠ 与 `places.md` §4.1 的冲突（**ATM 到底有没有上限拦截**）

`places.md` 写：「上限由 `0x453544` 的对话框内部决定；该对话框内部的数值校验未逐条核对 → 未决。
因此『存超过现金／取超过存款导致对应账户为负』在代码层面没有拦截。」

**实测结论（本笔记 §1 / §2.2）：这段把两个不同的输入通道混在一起了。**

1. **ATM 窗口（`0x436ef8`/`0x437161`）完全不使用 `0x453544`**（`disasm callers 0x453544` 的 12 个调用点里
   没有一处落在 `0x436ef8`/`0x437161`）。它的金额来自自己的字符串缓冲 `0x48c3f8`（数字键盘 + 拖动条），
   而上限 `0x48c3ec` 是**逐次输入后就地夹取**的：
   ```
   004378d3  mov edi, [0x48c3ec]        ; 上限
   004378d9  cmp eax, edi ; jle 0x4378ed
   004378dd  push 0xa; push 0x48c3f8; push edi; call 0x457d61   ; 输入 > 上限 → 直接改写成上限
   ```
   拖动条那条路径也有夹取（`0x437463 cmp ebx,ebp; jle; mov ebx,ebp`）。
   ⇒ **ATM 存取款不可能把现金/存款弄成负数，取款上限就是存款余额。**
2. **柜台输入框（`0x453544` → 数字键盘窗口 `0x452bc9`）确实没有夹取**：`0x453544` 只把参数写进
   `0x48ca98`（`0x4535fc`），而 `0x48ca98` 的**全部读取点只有两处画进度条**（`0x4529ae`、`0x45347a`），
   窗口过程 `0x452bc9` 根本不读它 ⇒ 玩家可以输入超过「额度默认值」的金额。
   但**柜台三条动作各自有自己的校验**：
   - 貸款（`0x435228`）：开框前拒绝 `loan >= wealth`，**开框后不校验输入**（可超贷）；
   - 還款（`0x435360`）：`输入 > 现金+存款` ⇒ 报「現金不足」且不扣款；
   - 經營者週轉（`0x434665`）：**无上限校验**（可超融）；歸還（`0x4346bb`）有上限校验。
   ⇒ 「存超过现金 / 取超过存款」在**柜台**不存在（柜台没有存取款按钮），
     在 **ATM** 被夹取；真正"没有拦截"的是**贷款额**与**经营者特别融资额**这两处。

合并时建议以本节为准（有 `0x48ca98` 的指令级 xref 与 `0x4378d9` 的原文支持）。
