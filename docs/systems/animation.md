# 动效（Animation）

> @source 全部来自对 `../../Rich4/rich4.exe` 的实际反汇编（`gen/db.txt`）。
>
> **诚实边界先说清**：本文件能给出**帧公式、相位寄存器、精灵表寻址、驱动时机**，
> 这些都是 A 级机械事实。但**观感**（补间、缓动、blit 顺序、残影）**无法从反汇编判定**，

## 一、★ `0x499088` = **地图视角旋转档位（0..7）**，不是动画帧

> ⚠️ **本节两次修正过结论**：早期版本称它为"全局动画相位"并推断"所有物件同步呼吸"
> （**错**）；其后改为"用户可控的 8 值相位，疑为视角"（**方向对但未确证**）。
> 现已由热键表确证为**地图视角旋转**。完整证据链见下。

### 全部写入点（穷举，`gen/db.txt` + 递归建图）

| 写入点 | 所属函数 | 行为 | 触发来源 |
|---|---|---|---|
| `0x00401394` / `0x0040139f` | `0x0040132b` | `dec` 后 `& 7` | **按键绑定链** |
| `0x004013d4` / `0x004013df` | `0x0040132b` | `inc` 后 `& 7` | **按键绑定链** |
| `0x00407e05` | `0x00407ad2` | `= 0`（清零） | 某流程结束时复位 |
| `0x00418717` / `0x00418722` | `0x00417e26` | `dec` 后 `& 7` | 条件 `[0x48be28] == 1` |

**没有任何一处是定时器回调。** 因此 `0x499088` **不会随时间自行变化** ——
它**只由用户输入（与两个复位点）改变**。一个需要随时间变化的"动画帧计数"
不可能如此，故早期结论不成立。

### 按键绑定链（A 级）

`VA 0x00401312`–`0x004013df` 是一条**按键分派链**：把按键值与一组 16 位
全局（`0x497180`、`0x497182`、`0x497184`、`0x497186`、`0x497188`、
`0x49718a`、`0x49718c`、`0x49718e` —— **连续 8 个 u16 = 8 个键位**）
逐一比较，命中则 `push <动作号>` 并跳到 `0x00401321`（→ `0x004017d65`）：

```asm
00401312  xor  edx, edx
00401314  mov  dx, word ptr [0x497180]     ; 键位[0]
0040131b  cmp  eax, edx
0040131d  jne  0x40132b                    ; 不匹配 → 试下一个
0040131f  push 0xa                         ; ★ 动作号 10
00401321  call 0x417d65                    ; ★ 真人专用路由
...
0040138b  jne  0x4013c0
0040138d  mov  edi, dword ptr [0x499088]
00401393  dec  edi                         ; ★ 命中该键 → 相位 −1
0040139c  and  ebp, 7
```

`0x497160` 起是 `RICH4.CFG` 载入的配置区（在 `.bss`，故**文件中无初值**），
`0x497168` 是键盘钩子用的另一个键位。**键位可由玩家重定义。**

### ★ 结论：它就是**地图视角旋转**（已确证，不再是推断）

`0x40132b` 的按键分派链把按键与 `RICH4.CFG` 的**热键表**逐一比较。
该热键表有 **28 项**、位于 `cfg + 0x10`（`cfg` 基址 `0x497158`），
每项 **2 字节**（虚拟键码 + 修饰键，`0x11` = Ctrl）。
上游 `rich4-re/docs/rich4_cfg.txt` 已给出 28 项的功能名。

相位增减恰好绑在**第 18 / 19 项**：

| 热键序号 | 内存地址 | 功能名（上游 cfg 文档） | 对相位的操作 |
|---|---|---|---|
| **18** | `0x49718c` | **地圖向左旋轉** | **`dec` 后 `& 7`** |
| **19** | `0x49718e` | **地圖向右旋轉** | **`inc` 后 `& 7`** |

**实测 `RICH4.CFG`**（本机存档的配置）里这两项是：

```
file offset 0x34 = 0xbc  →  VK_OEM_COMMA  =  '<'
file offset 0x36 = 0xbe  →  VK_OEM_PERIOD =  '>'
```

即**默认就是 `<` 和 `>` 两个键旋转地图** —— 与"8 档视角"完全吻合。

**因此**：`0x499088` 是**地图/棋盘视角旋转档位（0..7）**，
`animate_object` 用它选出"从当前视角看该物件"的精灵帧。
这解释了为什么：
① 它是离散的且只由按键驱动；② 它被存进存档（视角是持久状态）；
③ 每个物件只需一个 `+1` 字段作为相位偏移。

> ✅ 上一轮标为"关键未决（决定动画是自动播放还是手动逐帧）"的这条**已结案**：
> **是手动**，且它根本不是动画，而是视角。

## 二、物件动画：`animate_object`（`VA 0x0040e669`）

被调用 **26 处**（`gen/rel32-calls.json`）；`gen/functions.json` 的 `callers`

### 精灵帧寻址公式（A 级，逐指令可读）

```asm
0040e670  mov  edx, dword ptr [esp + 0x7c]     ; 参数 = 物件序号（1 基）
0040e674  test edx, edx
0040e676  je   0x40e6b9                        ; 0 → 走另一条（用 [0x49697c]）
0040e678  dec  edx                             ; 1 基 → 0 基
0040e679  mov  eax, edx
0040e67b  shl  eax, 2
0040e67e  sub  eax, edx                        ; eax = idx * 3
0040e682  mov  cl, byte ptr [eax*8 + 0x496d09] ; ★ objects_info[idx].+1 = 种类
0040e689  mov  ebp, 8
0040e68e  sub  ebp, dword ptr [0x499088]       ; 8 - 全局相位
0040e694  add  ebp, ecx                        ; ★ + 种类
0040e696  and  ebp, 7                          ; ★ & 7 → 帧号 0..7
0040e699  movzx edi, byte ptr [eax*8 + 0x496d08]  ; objects_info[idx].+0 = 类别
0040e6a1  mov  edi, dword ptr [edi*4 + 0x49692c]  ; ★ 类别 → 精灵表指针
0040e6a8  mov  eax, ebp
0040e6aa  shl  eax, 2                          ; eax = 帧号*4
0040e6ad  sub  eax, ebp                        ; eax = 帧号*3
0040e6af  shl  eax, 2                          ; eax = 帧号*12   ★ 步长 12
0040e6b2  lea  ebx, [edi + 0xc]                ; 表头 12 字节
0040e6b5  add  ebx, eax                        ; ★ 帧记录 = 表 + 0xc + 帧号*12
```

**结论（完整公式）**：

```
帧号     = (8 − [0x499088] + objects_info[idx].type) & 7      // 0..7
帧记录   = sprite_table[kind] + 0xc + 帧号 × 12               // 12 字节/帧
其中
  idx    = 物件序号 − 1                                        // 1 基输入
  记录步长 = 24 字节                          // (idx*3)*8 —— 与 objects_info 一致
  kind   = objects_info[idx].+0              // 类别 → 精灵表下标
  type   = objects_info[idx].+1              // 种类 → 帧相位偏移
  sprite_table[] = 指针数组 @ 0x49692c，按 kind 索引
```

**含义**：每个物件的精灵帧 = `8 − 相位 + objects_info[idx].+1`，再 `& 7`。
即**所有物件共用同一个相位基准**，各自再多一个由 `+1` 字段给出的偏移。

**复刻含义**：不要给每个物件独立计时器 —— 相位是**全局的、用户可控的**，
不是每物件自走的动画时钟。

### 物件记录（`objects_info`）被本函数用到的字段

| 偏移 | 本函数用途 |
|---|---|
| `+0` | **类别 `kind`**（→ `0x49692c[kind]` 精灵表） |
| `+1` | **帧相位偏移**（早期版本称 `type`，语义仍未定；见 `gods.md` 未决 ⑦） |

`objects_info` 基址 `0x496d08`、**46 项 × 24 字节**（见 `tools.md`）。

### 精灵表的写入者

`0x49692c` 只在 **3 处**被引用：`0x408f52`、`0x40e38c`、`0x40e6a1`（本函数）。
即精灵表数组是**运行时填充**的（初值不在文件里），由 `0x408f52` 附近设置。

## 二之二、★ 精灵渲染列表：原版的"动画"其实是一条**每帧重建的列表**

### 列表构建器（`VA 0x00408f10`–`0x00408f72`，在函数 `0x0040829d` 内）

```asm
00408f10  mov  eax, dword ptr [0x48bac8]        ; ★ 列表索引（不是帧计数！）
00408f15  mov  dword ptr [eax*4 + 0x48a44c], edx ; 写坐标（4 字节/项）
00408f1c  mov  eax, dword ptr [0x48bac8]
00408f23  shl  esi, 2 / sub esi, eax             ; esi = 索引*3
00408f2c  mov  word ptr [esi*4 + 0x48a854], ax   ; ★ 写 x（12 字节/项）
00408f38  mov  word ptr [esi*4 + 0x48a856], ax   ; ★ 写 y
00408f4b  mov  al, byte ptr [edi*8 + 0x496d08]   ; objects_info[ebx].+0 = 类别
00408f52  mov  eax, dword ptr [eax*4 + 0x49692c] ; ★ 类别 → 精灵表
00408f59  mov  dword ptr [esi*4 + 0x48a84c], eax ; ★ 存精灵表指针
00408f60  mov  byte ptr [esi*4 + 0x48a852], 0xff
00408f68  inc  dword ptr [0x48bac8]              ; ★ 索引++
00408f6e  inc  ebx
00408f6f  cmp  ebx, 0x2e                          ; ★ 遍历全部 46 个物件
00408f72  jge  0x4090e2
```

**语义**：每帧遍历 **全部 46 个物件**，把**可见**的追加进一条渲染列表。

| 全局 | 语义 |
|---|---|
| `0x48bac8` | **渲染列表项数**（每帧清零，不是时间计数） |
| `0x48a84c + i*12` | 第 i 项的**精灵表指针** |
| `0x48a852 + i*12` | 第 i 项的**标志字节**（`0xff`，初值） |
| `0x48a854 + i*12` | 第 i 项的 **x**（int16） |
| `0x48a856 + i*12` | 第 i 项的 **y**（int16） |
| `0x48a44c + i*4` | 第 i 项的**坐标**（打包 dword） |

**★ 步长 12 字节** —— 与 §二 `animate_object` 里算出的**帧记录步长 12 字节**一致。
两者是同一个结构的两端：**列表项指向"精灵表 + 帧偏移"**。

### 因此：原版的"动画"模型是

```
① 全局视角相位 [0x499088]（0..7，按键驱动，见 §一）
② 每帧重建渲染列表（遍历 46 物件，可见者入列）
③ 每项的精灵 = sprite_table[kind] + 0xc + ((8 − 相位 + 物件.+1) & 7) × 12
④ 按列表顺序 blit
```

**没有"每物件独立动画时钟"**。观感上的"动"来自：
- **视角旋转**（相位）；
- 物件**位置变化**（移动）；
- **特定场景**自己的定时器（神明的老虎机、小游戏等，见 §四）。

### ⚠️ 对"动画状态机"这一要求的诚实回答

目标的 (2) 要求「动画状态机」。本轮**穷举搜索**了"计数器 + 与帧数比较"这一
典型形态（`inc dword [全局]` 后紧跟 `cmp ..., 小立即数`），
**全工程只命中 1 处**，而它经查是**渲染列表索引**（`0x48bac8`），不是动画帧计数。

**结论**：原版**不存在**一个统一的、时间驱动的"动画状态机"。
动画是**"全局视角相位 + 逐帧重建列表"**，外加若干**场景各自的定时器**。

> 若"动画状态机"指的是**具体某个演出**（如神明老虎机的四轮 `rand()%10`），
> 那它的状态机在**该演出自己的函数里**，而不是一个通用机制。
> 本轮未逐个演出拆解（**未决**）。

## 四、定时器：动效的节拍来源

⚠️ **先纠正一个可能的误解**：`0x499088` 相位**不**由定时器推进（见 §一）。

定时器驱动的是**别的东西**（界面刷新、过场、光标动画等）。`SetTimer` 的分布是：
`game-loop.md` 已登记 **24 处** `SetTimer` 调用点，周期只有五档：

| 周期 (ms) | 处数 | 典型用途 |
|---|---|---|
| **50** | 9 | 最快档 |
| **100** | 10 | 常规 |
| 250 | 1 | 较慢 |
| 1000 | 2 | 低频状态刷新 |

> ⚠️ **定时器与物件精灵相位无关**（相位只由按键驱动）。定时器的用途未逐一确认 ——
> 见 §五 未决 1。

`timeGetTime`（24 处）用于更细的时间判定；`timeSetEvent`（1 处）是多媒体定时器。

> **复刻含义**：把定时器周期改成"每帧 16.7ms"会改变动画速度与输入采样率，
> 属于**行为偏离**而非实现细节。至少要保证 50/100ms 两档的语义。

## 六、观感部分（**必须靠实机截图，不得由本文件推断**）

1. **逐帧的视觉结果**：帧公式给了"取哪一帧"，但那一帧**长什么样**取决于
   `Panel.mkf`/`map.mkf` 的图素，静态不可知。
2. **补间与平滑**：定点坐标（`÷32`）表明存在亚像素平滑，但**缓动曲线**不可知。
3. **blit 顺序与遮挡**：由 COM 表面虚表（`render-api.md` 的 `0x64`/`0x80`）决定，
   静态未定名。
4. **特效与音效的同步点**：见 `sound-effects.md`（151 处播放点已登记）。
5. **过场动画（AVI）**：`Start.avi`/`Jump.mkf`/`Over.avi`/`Thanks.avi` 走 MCI
   （`0x45156f`、`0x451677`），时序不可静态判定。

## 七、复刻要点

1. **`0x499088` 是用户可控的 8 值相位（视角），不是动画时钟**。
   `animate_object` 用它选精灵帧。不要给每个物件独立动画计时器。
2. **帧记录步长 12 字节、首帧在 `表+0xc`**（前 12 字节是表头）。
3. **坐标是 5 位定点**（`÷32`），复刻若直接用整数像素会丢掉平滑。
4. **相位要存进存档**（`0x499088`），否则读档后视角归零。
5. 定时器档位（50/100/250/500/1000 ms）是行为的一部分，不是实现细节。

## ★ 地图视角档位的复刻落点（2026-09-17 补，第 42 条）

本文前面已结案：`<` / `>` 改的是**地图视角档位**（全局 `[0x499088]`，8 档、每步 45°），
不是动画帧计数；它**进存档**（`+0x2743`）。复刻侧的落点：

| 环节 | 位置 |
|---|---|
| 档位算术（8 档取模） | `rich4-remake/packages/core/src/rules/view.ts` 的 `rotateViewBy` |
| 进状态 | `state/actions.ts` 的 `{ type: 'rotateView'; delta }` + `state/reduce.ts` 的 case |
| 精灵换图 | 图号 = `(8 − (朝向 + 视角)) & 7`，`client/assets.ts` 的 `buildingImageIndex` |
| 投影 | `@rich4/data` 的 `projectCell(view, row, col)` / `SUBTILE_MATRIX[view]` |
| 热键 | `RICH4.CFG` 第 18/19 项 → `HOTKEY.rotateLeft/rotateRight`（`client/hotkeys.ts`）|
| 进/出存档 | `+0x2743`，写侧 `@source 0x0040330d`、读侧 `@source 0x00402e6d` |

⚠️ 原版**没有**「地图缩放」与「地图平移」—— 视角旋转是唯一的地图视图操作
（侧栏 200×200 小地图的箭头也调同一支）。复刻里自造的滚轮缩放/拖拽已在 T-086 删除。
