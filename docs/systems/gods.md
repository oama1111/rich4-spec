# 神明系统

> 真值：`../Rich4/rich4.exe`（v3.11, ImageBase 0x400000）。本文件所有 `@source` 均为原版虚拟地址。
> 每一段汇编摘要都是从 exe 字节直接反汇编得到，未引用 `rich4-re` 的任何 C 代码。

## 本文件的验证方式与证据级别

| 级别 | 本文件中的用法 |
|---|---|
| **A** | `rich4.exe` 字节（段表 `AUTO 0x401000..0x45f380`、`DGROUP 0x463000..0x489bff`、`.bss 0x48a000..0x499bff`）。所有表格数值、立即数、跳表内容均为直接 dump。 |
| **A** | 原版窗口/字符串资源中的 Big5 文本（`DGROUP` 内），作为「这条指令到底在讲什么」的语义旁证。 |
| **B** | `gen/functions.json` / `gen/jumptables.json`（本项目机械层索引）。**仅用于定位**，凡结论都已回 exe 复核。 |
| **C** | `rich4-re`（2018/2026 两代）。**未使用**。 |

**本次複核中發現的既有工具缺陷（會改變結論，必須記錄）**：

`tools/rich4dis.py`（沿用 `rich4-remake/tools/disasm.py` 的相對跳轉渲染）在
`0x40ea90` 處把 `jne rel8=0x05` 渲染成 `jne 0x40ea92`，**正確目標是 `0x40ea97`**：

```
0x40ea83..0x40ea9a 原始位元組:
83 f8 0c  7f 05 | 83 f8 0b  75 05 | 83 f8 0f  75 05 | ba 01 00 00 00  89 d0  c3
cmp eax,c  jg +5 | cmp eax,b jne +5 | cmp eax,f jne +5 | mov edx,1  mov eax,edx ret
0x40ea83 的下一条 = 0x40ea88 → +5 = 0x40ea8d
0x40ea88 的下一条 = 0x40ea8d → +5 = 0x40ea92
0x40ea8d 的下一条 = 0x40ea92 → +5 = 0x40ea97   ← 跳過 mov edx,1
```

後果：
- **按正確目標**，`0x40ea62` 回傳 1 的集合恰好是 **{1..10, 12, 15}**——一個乾淨的
  「這個物件是不是神明」判定（見 §三.2 的逐值展開）。
- **按錯誤渲染**，兩條 `jne` 都落到 `0x40ea92`，函式退化成恆為 1（只排除 `idx == 0`），
  於是「神明種類集合 {1..10,12,15}」這個資訊在靜態閱讀時**完全消失**。
  本文件一律按 exe 位元組裁決。

**结论可信度标记**：每条规格后标 `[A]`（逐字节验证）或 `[未决]`。未决项不填推测。

## 三、附身（發威）與離開的完整流程

### 3.1 觸發點

**(a) 遊戲初始化** `@source 0x407d50..0x407dbd`（`0x407d3a` 起）：把種類表寫進 46 個物件槽，然後

```asm
00407d6a  mov  ebx, 1
00407d6f  push 0 / push 0 / push 0 / call 0x40aa6c   ; 取得生成位置
00407d7d  push eax / push ebx / call 0x40e033        ; spawn_object(type=ebx, pos, 0, 0)
00407d87  add  ebx, 2 / cmp ebx, 0xb / jle 0x407d6f ; type = 1,3,5,7,9,11
00407d9e  push 0xd  → 種類 13「禮物」
00407db7  push 0xe  → 種類 14「寶箱」
```
即起始地圖上存在種類 **1,3,5,7,9,11,13,14** 的圖示（大型神 2/4/6/8 不在初始）。

**(b) 接觸神明圖示** `@source 0x41b7ef`：以 `np = objects_info[i].type` 查跳表
`0x41b3e5`（18 項 = 種類 1..18）：

| 種類 | 目標 | 行為 |
|---|---|---|
| 1..10, 12 | `0x41b807` | `god_activate(當前玩家, x, 物件槽位)`（`0x41b82d`） |
| 11 惡犬 | `0x41b837` | 走惡犬流程 |
| 13 禮物 / 14 寶箱 | `0x41b8f9` / `0x41bb0c` | 開箱 |
| 15 死神 | `0x41c164`（預設） | 不在此路徑處理 |
| 16/17/18 | `0x41bceb` / `0x41be5f` / `0x41bfd2` | 路障/地雷/定時炸彈 |

```asm
0041b7ef  mov  eax, dword ptr [esp + 0x9c]     ; 物件種類
0041b7f6  dec  eax
0041b7f7  cmp  eax, 0x11 / ja 0x41c164
0041b800  jmp  dword ptr [eax*4 + 0x41b3e5]
0041b807  mov  edx, dword ptr [0x49910c]       ; 當前玩家
0041b80d  cmp  edx, 4 / jge 0x41c164           ; 只處理 4 位玩家

0041b823  mov  ebx, dword ptr [esp + 0xa4]     ; 物件槽位（1 基）
0041b82a  push ebx / push esi / push edx
```

**(c) 魔法屋召喚死神** `@source 0x411b0a..0x411b3a`（在魔法屋著地處理 `0x411ae0` 內）：

```asm
00411b14  test eax, eax / je 0x411b43
00411b1e  dec  eax / mov [0x49910c], eax   ; 暫時把「當前玩家」換成被害者
00411b2e  push ebx / push 7 / push 0 / push 0xf
```

```asm

0040ea6c  xor  eax, eax / ret                 ; idx == 0 → 0
0040ea77  mov  al, byte ptr [eax*8 + 0x496d08]   ; type
0040ea7e  and  eax, 0xff
0040ea83  cmp  eax, 0xc / jg  0x40ea8d
0040ea88  cmp  eax, 0xb / jne 0x40ea92           ; type ≤ 12 且 ≠ 11 → 1
0040ea8d  cmp  eax, 0xf / jne 0x40ea97           ; type ≠ 15 → 0
0040ea92  mov  edx, 1
0040ea97  mov  eax, edx / ret
```
逐值展開：`type ∉ {11,13,14,16,17,18}` → 1；`type = 15` → 1；
**回傳 0 的只有 `idx = 0`、`type ∈ {11,13,14,16,17,18}`**。
即「可附身的種類」= **{1..10, 12, 15}**（12 種）。

> **與既有結論矛盾**：任务书与旧文档记「與 {5,6,7,8,10,15} 比對」——
> 那是 **`0x444c45`（送神符）內的另一個比對**（見 §五.2），不是附身判定。
> 另外「種類 15（死神）不能附身」的结论来自 §开头记录的工具渲染错误，**不成立**。

### 4.1 金額老虎機（種類 1/2/5/6 共用）`@source 0x440706` + `0x43f23e`

「查表 + push + call」形狀——**已解引用確認**：`0x440706(arg)` 不是查台詞，
而是**開一扇老虎機窗並回傳一個金額**（`eax = 0x43f23e(ebx)`，`0x4408c7..0x440906`）。

```asm
004407b9  mov  ebx, dword ptr [esp + 0xa4]   ; arg
004407c0  and  ebx, 1 / xor bl, 1            ; ★ ebx = !(arg & 1)  ∈ {0,1}
...
00440820  cmp  esi, 5 / ja 0x440873          ; esi = arg，0..5 走名稱分支
0044082a  jmp  dword ptr [eax + 0x4406ee]    ; a = arg*4
00440830  mov  ecx, [eax + 0x47ed7a]         ; ★ 名稱 = 0x47ed7a + 4*arg（= 種類 arg+1）
00440837  push 0x4652a9                      ; "%s附身\n\n向所有對手收..."   (arg=0)
0044083e  ... 0x4652c1 "%s附身\n\n送您..."   (arg=1)
00440873  ... （arg=2,3 不顯示訊息）
0044084c  ... 0x4652d1 "%s附身\n\n付給每個人..."(arg=4)
0044085a  ... 0x4652e7 "%s附身\n\n損失..."   (arg=5)
...
004408c7  push ebx / call 0x43f23e           ; ★ 回傳金額
```

`0x43f23e(arg)`（滾動到停止）的**回傳值**（`0x43f630..0x43f68c`，取出處 `0x43f7a0 mov eax,[esp+0xac]`）：

```asm
0043f630  xor eax, eax / mov al, byte ptr [0x48c506] / sar eax, 1     ; d2
0043f639  mov edx, eax / shl eax, 2 / add edx, eax / add edx, edx     ; edx = 10*d2
0043f644  mov al, byte ptr [0x48c507] / sar eax, 1 / add edx, eax     ; + d3
0043f64f  mov al, byte ptr [0x48c505] / sar eax, 1 / imul eax,0x64    ; + 100*d1
0043f659  add edx, eax
0043f65b  mov dword ptr [esp + 0xac], edx

0043f685  add dword ptr [esp + 0xac], eax

```

```
金額 = 1000*d0 + 100*d1 + 10*d2 + d3  (arg == 0，四位數 < 10000)
```

### 4.3 顯靈：種類 9 / 10 / 12 的落腳效果（`@source 0x40f381`，353 條指令）`[A]`

呼叫點（對全段做 byte-level `e8 rel32` 掃描，全檔只有兩處）：`0x418f59`、`0x41b086`，
兩者都在「玩家落腳於某一格」的處理流程內（第二處緊接著呼叫 `0x448a7e(玩家, 格)`）。

**簽名**：`0x40f381(player /*[esp+0xa8]*/, cell /*[esp+0xac]*/)`

```asm
0040f39e  cmp  byte ptr [ebx + 0x496b9a], 0 / jne 0x40f8b3   ; player+0x32 ≠ 0 → 返回
0040f3ab  cmp  byte ptr [ebx + 0x496b7d], 0 / je 0x40f8b3    ; 未存活 → 返回
0040f3bf  mov  eax, edx / shl eax,2 / add eax,edx            ; 5*cell
0040f3c6  mov  esi, dword ptr [0x498e80]
0040f3cc  mov  si, word ptr [esi + eax*8 + 0x20]             ; ★ esi = 該格土地編號
0040f3d7  mov  al, byte ptr [ebx + 0x496ba7]                 ; god_info（此處當槽位＝種類）
0040f3dd  cmp  al, 0xa / jb  0x40f3ff                        ; < 10 → 只可能是 9
0040f3ea  cmp  al, 0xa / jbe 0x40f521                        ; == 10 惡魔
0040f3f2  cmp  al, 0xc / je  0x40f68b                        ; == 12 土地公
0040f3ff  cmp  al, 9   / jne 0x40f8b3                        ; 9 天使，其餘返回
```

## 六、`god_info` / `f64` / 物件表 的關係

1. **`god_info`（`player+0x3f`）= `objects_info` 的 1 基槽位**，不是種類。
   種類一律由 `objects_info[god_info-1].type`（`+0x00`）還原。
   `@source 0x40eb66`（寫入）、`0x444c78`/`0x444c93`（讀種類）。
2. **`f64`（`player+0x40`）= 另一個物件的 1 基槽位**，代表「跟在玩家身上的道具物件」：
   由使用道具時寫入（`0x41c001 mov byte [eax+0x496ba8], bl`，同時把該物件
   `槽+5 = 當前玩家+1`、`槽+4 = 0x26`），並由 `0x40e14d` 在種類 18 離場時清 0（`0x40e1b2`）。
   `0x40fc00(player)` 會把 `god_info` 與 `f64` 兩個物件的「所在格」（`槽+2`）
   同步成 `player+0x0c`（`0x40fc12..0x40fc4d`）。
3. **`{5,6,7,8,10,15}` 比對的含義**（唯一出現處 `0x444c9f..0x444cbb`）：
   送神符的「壞神白名單」＝ 窮神（小/大）、衰神（小/大）、惡魔、死神。
   與附身判定（`0x40ea62`，白名單 {1..10,12,15}）是**兩套不同的集合**，不要混用。
4. **種類 15（死神）的槽位陷阱**：種類 15 獨佔 1 基槽位 {15, 16}（§1.2）。
   而神明名稱查表用的是 **`god_info` 當索引**（`0x40f951 mov edx, [eax*4 + 0x47ed76]`）。
   若死神落在槽 16，名稱查表會得到 `0x47edb6 = 路障`，出現「路障顯靈」。
   其他以 `god_info` 為索引的地方同理。
   `[未决]`：需兩個死神同時存在才會踩到；未實機確認可達性。

#### 6b.4 第二參到底是什麼（本轮订正 + 一句要緊的推論）

我先把序言算清楚：`push ebx / push esi / sub esp,0x80` ⇒ 一共让出 `0x88`，
所以 `arg1 = [esp+0x8c]`、`arg2 = [esp+0x90]`、`arg3 = [esp+0x94]`。
对照入口 `0x419d70` 的压栈（自下而上 `push ebp` / `push [0x47517c]` / `push [0x49910c]`）：

| 位置 | 值 | 用途 |
|---|---|---|
| arg1 | `[0x49910c]` = **当前玩家** | `imul ..., 0x68` 后读 `+0x3f` ⇒ **取付款方身上的神明** |
| arg2 | `[0x47517c]` | 分支里被 `push edx / push 0x463c67 / … call sprintf` 当 **`%s` 的实参** ⇒ 是**文本** |
| arg3 | 调用点压在栈上的 `ebp` | **要调整的租金** |

★ 由此得出一条要緊的推論（**本条支持复刻现有做法**）：在 `0x419cbd`
`add ebp, edx` **之后**才把 `ebp` 交给本函数 —— 即
**神明是按「合并后的总额」加减的，不是只乘地主那一份**。
调用点紧接着 `fild edx / fild ebp / fdivp` 算出 `edx/ebp` 存进 `[esp+0xc4]`，
那是**显示用的比例**（先算总额、再拿比例去格式化），与本函数无关。

```asm
00437d62  imul ebx, ebx, 0x9c4                     ; × 2500
00437d68  add  esi, ebx
00437d6a  movsx ebx, word ptr [edx + 0x496bac]     ; ★ 神明修正 A（有號）
00437d71  mov  edx, ebx / shl edx,2 / add edx,ebx / add edx,edx   ; edx = 10*A
00437d7a  lea  ebx, [esi + edx]
00437d7d  mov  dword ptr [esp + eax*4], ebx        ; 各玩家倒楣值
```
之後（`0x437d99..0x437df2`）取最大值、把最大值者歸零後再取次大，若
`(max - second)/max > 0.4`（`fcomp qword [0x464d58]`，dump = **0.4**）則回傳最大值玩家索引，
否則回傳 -1。

```
倒楣值(player) = (本月意外損失 − 本月意外之財)
               + 本月倒楣天數 × price_index × 2500
               + 10 × 神明修正 A[種類]
```

**即：神明只透過 `player+0x44`（A 表）進入月度評分，權重 ×10。**
A 為正 = 倒楣（死神 +1000 → +10000；窮神/衰神 +100..+200）；
A 為負 = 福氣（土地公 −500 → −5000；財神/福神 −100..−200；天使 −100）。

### 7.2 這三個欄位在月底結算畫面上確實被標示出來

```asm
00438738  mov  eax, 0x464def                     ; 標籤「本月意外損失：」
0043875d  mov  ebx, dword ptr [eax + 0x496bc8]

004387bd  mov  al, byte ptr [eax + 0x496baa]

```
（標籤與同 y 座標的數值成對：`0x140/0x184`、`0x140/0x196`、`0x140/0x1a8`。）
