# 金钱与资产核算

> @source 全部实测自 `gen/db.txt`；公式已由 `tests/test_wealth.py` 用原版机器码验证（12/12）。

## 一、玩家结构中的金钱字段

@source 玩家数组基址 `0x496b68`，步长 **0x68**（由 `0x4239bd` 的 `imul eax,ebx,0x68` 实测）。

| 偏移 | 字段 | 说明 |
|---|---|---|
| `0x1c` | `cash` | 现金 |
| `0x20` | `money_in_bank` | 存款 |
| `0x24` | `loan` | 贷款（负债） |
| `0x28` | `special_finance` | 待确认 |
| `0x5c` | `monthly_paid` | 本月支出累计 |
| `0x60` | `monthly_received` | 本月收入累计 |

## 二、总资产 `calculate_player_wealth`（`VA 0x004239b9`）

```
wealth(player)                         ; player 为 **0 基下标**
    = cash + bank - loan
    + Σ_{s=0..11} round( stockAmount[player][s] * stockPrice[s] )   ; ★ x87 浮点
    + Σ_{owner == player+1 的住宅地}  land_price
                                      + (type != 0 ? house_price
                                                   : level != 0 ? level * house_price : 0)
    + Σ_{owner == player+1 的商業用地} level * w[+0x24] + w[+0x22]
```

### 关键实现细节（都踩过坑，逐条给证据）

1. **下标是 0 基**：`imul eax, ebx, 0x68` 直接以第 1 参为下标（`0x4239c0`）。
   而 `owner` 是 **1 基**，故比较用 `lea esi,[ebx+1]; cmp ecx,esi`（`0x423a3a`）。
   **两者编码不同，不能混用。**

2. **股票是浮点运算，且每步取整（已确认是向零截断）**：
   `fild [..+0x4971a0]`（整数装入）→ `fmul [..+0x496994]`（单精度乘）
   → `call 0x457dbc` → `fistp [esp]`，循环 **12 次固定**（`cmp edx,0xc`），
   与"本局开哪几只股票"无关。

   ★ `0x457dbc` 的语义**已解出**（@source `VA 0x00457dbc`，12 条指令）：

   ```asm
   00457dbc  push eax
   00457dbe  fnstcw word ptr [esp]        ; 读 FPU 控制字
   00457dc2  push dword ptr [esp]
   00457dc5  mov  byte ptr [esp + 1], 0x1f ; ★ RC 位设为 11 = 向零截断
   00457dca  fldcw word ptr [esp]          ; 装载新的舍入模式
   00457dcd  frndint                       ; 按当前模式取整
   00457dcf  fldcw word ptr [esp + 4]      ; 恢复原控制字
   ```

   即 **round-toward-zero（向零截断）**，不是就近舍入、也不是向下取整。
   实测 6 个 `.5` 边界用例（含负数）**全部吻合**：`3×0.5→1`、`7×2.5→17`、
   `−1×1.5→−1`、`−1×2.5→−2`。

3. **★ 股价表步长是 `0x24`（36 字节），不是 4**：
   ```asm
   004239ea  mov  eax, edx
   004239ec  fild dword ptr [ecx + eax*8 + 0x4971a0]   ; 数量：步长 8
   004239f3  shl  eax, 3
   004239f6  add  eax, edx                              ; eax = 9*idx
   004239f8  fmul dword ptr [eax*4 + 0x496994]          ; ★ (9*idx)*4 = idx*0x24
   ```
   我最初按"每项 4 字节"实现，结果**股票市值恒为 0**。
   实测确认：把 100×10.0 与 7×2.5 分别写在 `0x496994 + 0×0x24` /
   `+ 1×0x24`，原版返回 **1017**（= 1000 + 17，17.5 向零截断），与规格吻合。

4. **住宅取值分三种情况**（`0x423a4f`–`0x423a7a`）：
   `land_price` 总是加；`type != 0` 时加 `house_price`；
   `type == 0` 且 `level != 0` 时加 `level * house_price`；否则不加。

5. **商業用地**（`0x423a9a`–`0x423abb`）：`level * w[+0x24] + w[+0x22]`。
   其数组步长 **0x38**、基址指针 `0x498e88`、项数 `0x498e8c`，
   **同样从下标 1 开始**（循环前 `add eax,0x38`）。

@source 每一项的步长与起点均来自 `gen/db.txt` 中对应函数的寻址指令；`0x496994` 落在 `.bss`（运行时初始化，文件中无字节）。

## 三、已确认的数组基准

| 数组 | 基址指针 | 项数 | 步长 | 下标起点 | 备注 |
|---|---|---|---|---|---|
| 住宅地 | `0x498e84` | `0x498e98` | `0x34` | **1** | 见 `land-rent.md` |
| 商業用地 | `0x498e88` | `0x498e8c` | `0x38` | **1** | 字段 `+0x22`/`+0x24` |
| 玩家 | `0x496b68` | — | `0x68` | **0** | 本文件 |
| 玩家持股 | `0x4971a0` | — | 每玩家 `0x60`，每股 8 | **0** | 数量（int） |
| 股价 | `0x496994` | — | **`0x24`** | **0** | 单精度 |

> ⚠️ **上表是复刻时最容易出错的一张表**：三套数组的"下标起点"与"步长"各不相同，
> 且住宅/商業与玩家/持股的起点相反。每处都已用原版机器码验证。

## 五、未决

1. ~~`0x457dbc` 的舍入模式未确认~~ ✅ **已确认为向零截断**，见 §二 第 2 条与
   `tests/test_wealth.py` 的 6 个 `.5` 边界用例。
2. `special_finance`（`+0x28`）是否计入总资产**未确认** —— 上面的公式中**未出现**它，
   但它在其它地方有专门处理，可能通过别的路径计入。
3. ~~股票 `round` 的**溢出行为**未测（数量或股价很大时 `fistp` 的截断）~~
   ✅ **已测**（2026 本轮，`tests/test_inline_formulas.py`）：x87 的 `fistp dword`
   在结果超出 `int32` 时写入 **`0x80000000`（整数不定值）**，而不是饱和到
   `INT32_MAX`。实测边界（月息那支，结果为 `trunc(x × 1.1)`）：
   `bank = 1952257861 → 2147483647`（恰好放得下）；
   `bank = 1952257862 → -2147483648`（溢出）。
   ⇒ 凡 `fistp dword` 落盘的地方，**超过 `2^31−1` 会翻成负数**，复刻需照抄。

## 六、地产/設施「市价」与拍卖输入上限（`sub_004261bc` = 拍卖价格输入框的窗口过程）

**此前 PRD 未收录**（本轮补全）：拍卖时弹出的"输入价格"框把**市价**显示在提示串里，
该市价是一条独立的估价公式，与 §二 的总资产估价**同形但用途不同**。

```
市价(entity) =
    (地价 + 等级 × 房价) × 物价指数        ; entity <  4000（住宅地，步长 0x34）
    (底价 + 等级 × 单价) × 物价指数        ; entity >= 4000（設施，  步长 0x38）
```

| 字段 | 住宅地（步长 `0x34`） | 設施（步长 `0x38`） |
|---|---|---|
| 基准价 | `+0x1c`（u16 地价） | `+0x22`（u16 底价） |
| 单位价 | `+0x1e`（u16 房价） | `+0x24`（u16 单价） |
| 等级 | `+0x1a`（u8） | `+0x1a`（u8） |

| 事实 | 证据 |
|---|---|
| 分支：`cmp ebx, 0xfa0`（4000）→ `jge` 走設施支 | `0x42659e`、`0x4265a4` |
| 住宅支：`(id−2000)×0x34 + [0x498e84]` | `0x4265a6`..`0x4265b5` |
| 設施支：`(id−4000)×0x38 + [0x498e88]`（`shl 3`/`shl 3`/`sub` = ×56） | `0x4265cb`..`0x4265e1` |
| `房价 × 等级` 用 **u16 × u8 的无符号装入**（`xor ecx,ecx; mov cx,`…） | `0x4265b7`..`0x4265c2` |
| `and eax,0xffff` 之后才相加（基准价只取低 16 位） | `0x4265f5`、`0x4265fa` |
| **物价指数 `[0x4990e8]` 乘在最后**（整数 `imul`），不参与任何截断 | `0x4265fc`、`0x426602` |
| 提示串 **`0x463eb3` = `"請輸入欲拍賣的價格\n\n（市價：%d元）"`** | `0x426606` `push 0x463eb3` |
| 上限 = **市价 × 10**（`esi*10` = `shl 2` + `add` + `add`），作为参数传给输入框模态 `0x453544` | `0x426627`..`0x426631` |
| `0x453544` 把该参数存进全局 **`0x48ca98`** | `0x4535f8`（实参在 `[esp+0x24]`） |
| 输入框 WndProc `0x452c02` 读 `0x48ca98` 共 **4 处**（`0x4529ae`/`0x45347a` 走 `fild`，`0x4530f1`/`0x4531f0` 走整数比较） | 全库扫描 |
| **超上限的输入被就地改写成上限**：`atoi(buf)` → `cmp eax, edx(=[0x48ca98])` → `jle` 放行；否则把 `市价×10` 重新格式化写回同一缓冲 | `0x4531e3`..`0x453206` |
| 返回 0 视为取消（`test esi,esi; je`），否则带着价格去下单 `(2, entity, price, 0)` | `0x426640`..`0x42664c` |

> 验证：`tests/test_inline_formulas.py` 用 `Emu.eval_block(0x4265a6/0x4265cb, …)`
> 对两支公式各跑了包含**下标位移、u16/u8 边界、指数 0/1/3** 的用例（共 12 条），
> 与手算逐条一致。同时印证了 §二 的同式估价：**总资产不乘物价指数**
> （`calculate_player_wealth`，`test_wealth.py` 覆盖），**市价乘**物价指数。
