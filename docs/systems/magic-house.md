# 魔法屋

> 真值：`../Rich4/rich4.exe`（v3.11, ImageBase 0x400000）。本文件所有 `@source` 均为原版虚拟地址。
> 每一段汇编摘要都是从 exe 字节直接反汇编得到，未引用 `rich4-re` 的任何 C 代码。

## 本文件的验证方式与证据级别

| 级别 | 本文件中的用法 |
|---|---|
| **A** | `rich4.exe` 字节。所有表格（`0x4756b8`、`0x4756e4`、`0x47571c`、`0x474940`、`0x475150`）的数值都是直接 dump；所有跳表（`0x431812`、`0x431c7a`、`0x4325a2`、`0x4406ee`）的内容都已逐项读出。 |
| **A** | `DGROUP` 內的 Big5 字串（視窗訊息、道具名、等級名），作為語意旁證。 |
| **B** | `gen/functions.json` / `gen/jumptables.json`。**只用於定位**，凡結論都已回 exe 複核。注意該工具的函式邊界在此區被跳表目標切斷（例如 `0x431caa` 被切成 44 條），本文件改以線性反編譯取完整函式。 |
| **C** | `rich4-re`。**未使用**。 |

**本文件推翻的一处既有描述**：任务书与既有文档把「魔法屋表」记为
`0x475724`、12 项 × 16 字节。实测该 16 字节记录的**起始是 `0x47571C`**，
`0x475724` 只是记录内的 **`char *name` 字段（+8）**。
证据见 §三.2（反汇编直接以 `0x47570c + 16*k` 取 x、`0x475710 + 16*k` 取 y）。

## 一、入口与整体流程

### 1.1 入口 `@source VA 0x004339d9`（421 條，`gen/functions.json` 亦記 size 421）`[A]`

`0x4339d9` 由地圖格事件分派器呼叫：

```asm

00411b11  add  esp, 4
00411b14  test eax, eax / je 0x411b43      ; 回傳 0 → 沒事
00411b1e  dec  eax / mov [0x49910c], eax   ; 回傳值 n → 把當前玩家換成 n-1
00411b35  call 0x40e033                    ; spawn_object(15 死神, 0, 7, n)
```

`0x4339d9(player)` 的內部流程：


## 二、每個條件的精確判準（`@source 0x431842` 分派）`[A]`

分派器先把目標清單歸零，再按 index 跳表（`0x431842..0x431860`）：

```asm
00431849  xor  edx, edx
0043184b  mov  dword ptr [0x48c380], edx     ; ★ 清空 4 byte 目標清單
00431855  cmp  ecx, 0xb / ja 0x431c62
00431860  jmp  dword ptr [eax*4 + 0x431812]
```
每個處理常式都：走訪所有玩家 → 跳過 `player+0x15 == 0`（死亡）→ 判斷條件 →
若命中則 `byte [0x48c380 + esi] = 玩家編號 + 1`、`esi++`（最多 4 人）。
跳表（`0x431812`，12 項）：`0x431867, 0x4318b7, 0x431969, 0x431a23, 0x431a7d,
0x431ad2, 0x431b2c, 0x431b61, 0x431b99, 0x431bcf, 0x431c02, 0x431c31`。

## 三、兩個轉盤的結果映射與停留格判定

### 3.1 結果 index 如何產生

**(a) 互動路徑（當前玩家存活）** `@source 0x43381b..0x433906`：開窗並執行
`0x4018e7(0x4325c2, 0)`；`esi = 視窗回傳值` → 直接當**動作 index** 用（`0x4338b7`、`0x4339c5`）。

```asm
004338a8  push 0 / push 0x4325c2 / call 0x4018e7
004338b7  mov  esi, eax                     ; ★ 動作 index = 視窗結果
00433906  jmp  0x4339c5                     ; → push esi / call 0x431caa
```

**(b) 非互動路徑（當前玩家 `player+0x15 != 1`）** `@source 0x43390b..0x433980`：

```asm
0043390b  mov  esi, -1
00433910  call 0x456f2d                     ; rand
00433917  mov  ecx, 0xc / idiv ecx          ; ★ 轉盤 1：rand() % 12
00433921  mov  bl, dl                        ; 條件 index
00433928  call 0x431842                      ; 填 0x48c380 並回傳是否非空
00433932  je   0x433910                      ; 空 → 重擲
00433934  ...（走訪 0x48c380[0..3]）
00433956  cmp  edx, ecx / jne 0x43393e       ; 目標 == 當前玩家？
0043395a  mov  esi, 6                        ; ★ 命中自己 → 強制動作 6「得一張卡片」
00433961  cmp  esi, -1 / jne 0x433981
00433966  call 0x456f2d
0043396d  mov  ecx, 0xb / idiv ecx           ; ★ 轉盤 2：rand() % 11 → 0..10
00433977  mov  esi, edx
00433979  cmp  edx, 6 / jne 0x433981
0043397e  lea  esi, [edx + 1]                ; ★ 擲到 6 就換成 7
```

⇒ **動作 index 的可能值 = {0,1,2,3,4,5,7,8,9,10} ∪ {6（僅由「命中自己」強制）}，
永遠不會是 11**。這是「拍賣當格土地」未接線的直接原因（見 §五）。

**(c) 轉盤 1 在視窗內也會自己重擲** `@source 0x432707..0x43273f`（視窗程序狀態 4）：

```asm
00432707  mov  al, byte ptr [0x48c3a1] / dec al / mov [0x48c3a1], al
00432713  jne  0x432828                     ; 倒數未完 → 繼續
00432719  call 0x456f2d / mov ecx, 0xc / idiv ecx   ; rand() % 12
0043272a  mov  byte ptr [0x48c3a3], dl      ; ★ 轉盤 1 結果 index
00432735  call 0x431842 / test eax,eax / je 0x432719  ; 空 → 重擲
```

### 3.2 停留格判定（滑鼠 → 格號）

視窗程序（`@source 0x4325c2`，`ret 0x10` = 標準視窗程序）用**命中表**把滑鼠位置換成格號：

```asm
004326c9  mov  ebx, dword ptr [esp + 0x70]    ; hwnd
004325cd  mov  eax, dword ptr [esp + 0x74]    ; msg
004325d1  mov  edx, dword ptr [esp + 0x7c]    ; lparam（x 低 16 位、y 高 16 位）
...
00432b5d  mov  cx, dx                          ; x
00432b64  shr  eax, 0x10 / and eax, 0xffff     ; y
00432b73  shl  eax, 2 / add eax, edx           ; 5*y
00432b78  shl  eax, 7                          ; 640*y
00432b7b  add  eax, ecx                        ; ★ 640*y + x
00432b83  mov  al, byte ptr [edx + eax + 0]    ; edx = [0x48c394]，命中表
00432b8b  mov  dword ptr [esp + 0x58], eax     ; 該點所屬格號
00432b91  mov  al, byte ptr [0x48c3a1]
00432b96  cmp  eax, dword ptr [esp + 0x58] / je 0x4326ad   ; 沒變 → 不做
00432ca3  mov  al, byte ptr [esp + 0x58]
00432ca7  mov  byte ptr [0x48c3a1], al         ; ★ 目前高亮格 = 命中表值
00432cac  test al, al / je 0x432e4f            ; 0 → 非格
00432cb4  cmp  al, 0xd / je 0x432e4f           ; 13 → 非格
```

- 命中表 `0x48c394` 的索引 = **`640 * y + x`**（x、y 取自 `lparam` 的兩個 16 位欄）。
- 有效值：`0` 與 `0xd`(13) 視為「不在格上」（`0x432cac/0x432cb4`），其餘為格號。
- **座標表以 1 基索引**（`k = 1..12`），取用時：

```asm
00432d27  mov  dl, byte ptr [0x48c3a1]
00432d2d  shl  edx, 4                              ; 16*k
00432d30  mov  eax, dword ptr [edx + 0x47570c]     ; x（int32）
00432d3d  mov  eax, dword ptr [edx + 0x475710]     ; y（int32）
```

（同一支程式在 `0x432cc0` 也用 `[ecx*4 + 0x4756e4]` / `[ecx*4 + 0x4756e6]`
＝轉盤 1 的 int16 座標對，繪製 `0x40×0x40` 的圖示框；`0x432bd2..0x432c1a`。）

### 3.3 動作 index 回傳給呼叫者

```asm
00432a4c  ...（狀態 8）
00432a74  mov  al, byte ptr [0x48c3a1] / dec eax / push eax
00432a7a  call 0x401966                     ; ★ 以 0x402 訊息關窗，結果 = [0x48c3a1]-1
```
`0x401966` 是唯一的 `push 0x402` 送出點（`0x40196d`），`0x4018e7` 的訊息迴圈在收到
`0x402` 後 `dec [0x46cad8]` 並回傳該訊息的引數（`0x401957..0x401965`）。

⇒ **動作 index = 高亮格號 − 1（0 基）**，也就是 `0x475724 + 16*index` 的名稱與
`0x431caa(index)` 的動作。

**記錄基址 `0x47571C`，步長 16，共 12 項：**

## 五、「拍賣當格土地」的確切行為

### 5.1 接線狀況（實測）——與「未接」的既有說法**部分矛盾**

| 事實 | @source |
|---|---|
| 名稱在表中、座標有效（122, 154） | `0x4757d4`、`0x4757cc`/`0x4757d0` |
| 有實作：`0x43242b..0x4324f5`，呼叫 `0x43bde5(玩家, 土地編號, 1)` | `0x4324d5` |
| **非互動路徑**（當前玩家 `+0x15 != 1`）：動作 index = `rand() % 11 → 0..10`，擲到 6 換成 7；強制值固定為 6 ⇒ **不可能為 11** | `0x43396d..0x43397e`、`0x43395a` |
| **互動路徑**（當前玩家 `+0x15 == 1`）：動作 index = **玩家點擊的格號 − 1**，格號來自命中表且可為 1..12 ⇒ **11 可達** | `0x432a74`（`dec eax` 後 `0x401966`）、`0x432ece..0x432f19`（點擊格 1..12 時以 `[0x48c3a1]*16 + 0x47570c` 畫出被選中的動作圖示並進入狀態 8） |
| 兩條路徑的分岔 | `0x43381b cmp byte [eax+0x496b7d], 1 / jne 0x43390b` |

⇒ **修正既有說法**：
- 說「動作 index 永遠到不了 11」**只在非互動路徑成立**；
- 互動路徑是「玩家在 12 個圖示上點選」，點第 12 格（`[0x48c3a1] == 12`）即
  `index = 11` → 拍賣可達；
- 因此**「實作存在但根本走不到」不成立**，較精確的說法是：
  **`0x43380a` 的隨機選擇器不會選到 11，但互動選擇器可以選到。**
- `[未决]`：`player+0x15 == 1` 到底是什麼狀態（人類玩家？本回合可操作？），
  未確認 —— 這決定了**實際上哪條路徑會被使用**。若正常遊戲中互動路徑生效，
  則「拍賣當格土地」是**有效功能**。
- 附帶：`0x432ff7` 是**另一支**（點到 0 或 13＝非格時）的分支，進入狀態 6
  （顯示 `0x48c3a3` 對應的條件名），與動作 index 無關。§3.3 已記錄。

```
  標的[+0x19] = 得標者 + 1
```

#### 5.2.1 開拍時**消費全局隨機流**：心理價位的擲數（2026-09-16 補）

`0x43bde5` 在**建座位表**那一段會替「可出價的電腦」算心理價位，
而 `fcn_00439f0d` 內部就是 `_libc_rand` —— 故**開一場拍賣會推進全局隨機流**。
次數與順序由建表循環 `VA 0x0043c5d0..0x0043c680` 決定：

```asm
0043c5d0  cmp  ebx, 4 / jge 0x43c680      ; ★ 循環 4 個座位槽（ebx = 0..3，下標升序）
0043c5e3  ax = word [ebx*20 + 0x48c434]   ; 該槽的玩家號 + 1（0 = 空槽）
0043c5ea  test ax, ax / je  下一槽         ; ① 空槽 → 不擲
0043c5fa  test byte [player + 0x15], 6    ; ② who_plays 的 bit1|bit2
0043c601  je   0x43c624                   ;    真人（只有 bit0）→ **不擲**
0043c603  cmp  word [ebx*20 + 0x48c436], 0
0043c60b  jne  0x43c624                   ; ③ 座位狀態非 0 → 不擲
0043c60d  push 實體號 / push 玩家號 + 1
0043c616  call 0x439f0d                   ; ★ 算一次（內部開頭 call rand 一次）
0043c61e  [ebx*20 + 0x48c438] = eax       ; 存心理價位（座位 +8）
```

`fcn_00439f0d` 內部 `call 0x456f2d` 共 **3 處**：入口 `0x00439f1c`
（`rand/32767×0.3+0.5` 的那個係數）＋ **地塊支** `0x0043a015`
（`rand/65536+3.0` 乘地價）**或設施支** `0x0043a0fb`（同形，讀 `+0x22`）
—— 兩支互斥，故**每次調用恰好消費 2 個隨機數**。

⇒ **N 個「可出價的電腦座位」開拍時恰好推進 `2N` 步。**

三條容易漏的：
1. **真人座位不擲**（`test ...,6`）——他不是 rand 出來的價，是手點的，
   該座位心理價位停在 **0**；
2. **賣家（狀態 7）與出不起底價者（狀態 8）不擲** —— 建表寫狀態在
   `0x439f0d` **之前**，所以「出不起底價」的座位價位也是 0；
3. 順序是**座位槽下標升序**（= 玩家下標升序），不是「出價資格名單」的順序。

`[未决]`：拍賣窗口**動畫**另有 4 處 `rand`（`0x0043b5ff` `rand>>10`、
`0x0043b945` `rand>>11`、`0x0043b9d6` `rand&7+1`、`0x0043baa7` `rand>>11`，
四周全是貼圖／vtable 調用），它們**按幀**觸發 —— 屬表現層且時間相關，
無頭復刻不可能逐位對齊，故本規格只記錄「規則相關」的那 2N 步。
另一個好消息：AI **出價檔位**的挑選（`loc_0043b124` / `0x43b183`）
經查**不含** `rand`（那一段位址區間裡沒有 `call rand`），
所以「出價金額是確定的」這一條與原版一致。

✅ **本節的「心理價位」公式已由差分測試驗證**：`tests/test_auction_limit.py`
用 Unicorn 跑原版 `fcn_00439f0d`，與上面的式子逐次比對 —— **14/14 通過**
（地產 + 設施兩支、**兩次 `rand()`** 的取值、稀缺係數、同名數、
`⌊等級/2⌋`、**現金夾頂**全覆蓋）。⇒ 那不是讀出來的推斷，是**與真值比對過**的。
（`test_auction_limit.py` 的兩條做法見 `docs/verification.md` 通道 2：
PRNG 狀態打樁到暫存區、浮點邊界用例顯式讓開。）

`[未决]`：完整出價流程（出價順序、每次加價幅度、NPC 決策、流標處理、成交價是否等於
最高出價）**未逐條展開**；上述僅涵蓋估價、資格判定、成交與付款四個已驗證的端點。

### 6.1 五種建築

| 索引 `+0x18` | 名稱（`@source 0x475150`） | 等級上限（`@source 0x474940`） |
|---|---|---|
| 0 | 公　園 | **1** |
| 1 | 旅　館 | **5** |
| 2 | 購物中心 | **5** |
| 3 | 加油站 | **1** |
| 4 | 研究所 | **5** |

```asm
0040b1f9  xor  edx, edx
0040b1fb  mov  dl, byte ptr [ebx + 0x18]              ; 建築種類
0040b1fe  mov  cl, byte ptr [ebx + 0x1a]              ; 目前等級
0040b201  cmp  cl, byte ptr [edx + 0x474940]          ; ★ 上限表
0040b207  jae  0x40b21f                               ; 等級 ≥ 上限 → 不加蓋，回傳 0
0040b209  mov  eax, 1
0040b20e  mov  dl, cl / inc dl
0040b212  mov  byte ptr [ebx + 0x1a], dl              ; level++
0040b215  cmp  dl, 5 / jne 0x40b21f
0040b21a  mov  eax, 0x81                              ; 剛好到 5 → 回傳帶 bit7
```

同一張上限表也被「購買/興建」判定使用：`0x41a2c2`（`cmp bl, byte[edx+0x474940]`）、
`0x421c77`。名稱表的使用：`0x417a2d`（`mov al,[edi+0x18]; mov ebp,[eax*4+0x475150]`）。

### 6.2 這張表屬於「設施」陣列，不是 `land_info`

`0x40b110(編號)`（就地加蓋房屋的實作）分兩段：

| 編號範圍 | 陣列 | 步長 | 上限邏輯 | @source |
|---|---|---|---|---|
| 2000..4000 | `[0x498e84]` = `land_info` | `0x34` | **寫死**：`+0x18 == 0` → 上限 5；`+0x18 == 1` → 上限 1 | `0x40b138..0x40b15f` |
| 4000..6000 | `[0x498e88]`（任務書稱「商業用地」，既有文檔稱「設施」） | `0x38` | **`0x474940[+0x18]`** | `0x40b1f9..0x40b218` |

```asm
0040b138  cmp  byte ptr [ebx + 0x18], 0 / jne 0x40b149
0040b13e  cmp  byte ptr [ebx + 0x1a], 5 / jae 0x40b149    ; ★ land_info 住宅上限 5
0040b144  mov  eax, 1
0040b149  mov  cl, byte ptr [ebx + 0x18]
0040b14c  cmp  cl, 1 / jne 0x40b15d
0040b151  cmp  cl, byte ptr [ebx + 0x1a] / jbe 0x40b15d   ; ★ land_info type 1 上限 1
```

> **與既有結論的關係**：`docs/systems/land-rent.md` 對 `land_info` 的
> 「`+0x18`：0 = 住宅，非 0 = 商業用地」與這裡的 `0x40b138/0x40b149` 一致
> （住宅上限 5、type 1 上限 1）。但 **`0x474940` 這張 [1,5,5,1,5] 上限表
> 服務的是另一個陣列（`0x498e88`，編號 4000..6000）**，
> 兩者的 `+0x18` 語意不同（前者：0 = 住宅；後者：0 = 公園）。
> 任務書把五種建築叫「商業用地」，本規格保留其名稱但標明這點。

### 6.2.1 設施等級 0 時「種類」是怎麼決定的 `@source 0x40b1a0..0x40b1f8` `[A]`

等級 0（空地）時**不是**先有種類再升級，而是**加蓋的同時決定種類**：

```asm
0040b1a0  cmp  byte ptr [ebx + 0x1a], 0 / jne 0x40b1f9   ; 已有等級 → 走一般加蓋
0040b1a6  imul eax, dword ptr [0x49910c], 0x68
0040b1ad  test byte ptr [eax + 0x496b7d], 6 / je 0x40b1e2 ; 當前玩家旗標 & 6
0040b1b6  xor  edx, edx
0040b1b8  mov  dl, byte ptr [ebx + 0x19]      ; 地主 + 1
0040b1bb  mov  eax, dword ptr [0x49910c] / inc eax
0040b1c1  cmp  edx, eax / jne 0x40b1dc
0040b1c5  call 0x456f2d / mov ecx, 4 / idiv ecx
0040b1d6  inc  edx
0040b1d7  mov  byte ptr [ebx + 0x18], dl      ; ★ 種類 = rand()%4 + 1 → 1..4（不含公園）
0040b1dc  mov  byte ptr [ebx + 0x18], 0       ;   地主不是自己 → 種類 = 0（公園）
0040b1e2  push 0 / call 0x440aac
0040b1ec  mov  byte ptr [ebx + 0x18], al      ; ★ 由 0x440aac 選單決定（玩家自選）
0040b1ef  mov  eax, 1
0040b1f4  inc  byte ptr [ebx + 0x1a]          ; 等級 = 1
```

三條分支（**順序照程式；`0x40b1e2` 是 `0x40b1b4` 的跳躍目標，位址上落在 `0x40b1dc` 之後**）：
1. `(player+0x15 & 6) == 0` → `je 0x40b1e2`：由 `0x440aac(0)` 開**選單讓玩家選**
   建築種類（`0x440aac` 開資源 `0x10` 的視窗、字串 `0x465289`，回傳選擇的種類）。
2. 否則（`& 6 != 0`）且 `地主+1 == 當前玩家+1` → `種類 = rand() % 4 + 1`
   （**旅館/購物中心/加油站/研究所，不含公園**）。
3. 否則（地主不是自己）→ `種類 = 0`（公園）。

`[未决]`：`player+0x15 & 6` 的語意（可能是「人類玩家 / 託管 / 可操作」）未確認；
因此「什麼情況下會彈出選單」未定。


### 6.3 等級 → 倍數

**唯一找到的「倍數」是拍賣估價用的 `1 + 0.5 × level`**（`@source 0x4650b0 = 0.5f`，
使用於 `0x43be48` 與 `0x43bf8c`，見 §5.2）。

```
估價倍數 = 1 + 0.5 × level        （level = 0..5 ⇒ 1.0 / 1.5 / 2.0 / 2.5 / 3.0 / 3.5）
基準價   = round(單價 × 估價倍數) × price_index
```

**未找到任何「轉盤 × 等級上限」的數量關係**：
- 12 項動作記錄的第 `+0x0C` 欄（值 10/7/7/7/7/7/6/6/6/6/9）在全檔內**沒有任何讀者**（§4.1），
  故它不是倍數。
- `0x475150`（名稱）與 `0x474940`（上限）都由 `+0x18` 索引，與魔法屋轉盤無資料關聯；
  魔法屋的「就地加蓋房屋」（#5）只是**呼叫** `0x40b110`，不帶任何倍數參數
  （`0x432051`，僅傳土地編號）。
- `[未决]`：若任務書的「转盘倍数」另有所指（例如某一版曾使用的 `+0x0C` 欄），
  v3.11 的 exe 中找不到對應程式碼，**無法證實**。
