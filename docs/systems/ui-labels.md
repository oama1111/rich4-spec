# UI 标签表与文本指针表

> 目的：补上「表 → 界面元素」的映射。覆盖审计发现这些表的**字符串内容**虽被零散引用，
> 但**表结构本身**（按什么顺序、用在哪个界面、被哪个函数以什么索引取用）没有文档记述。
> 对 1:1 复刻来说这是真实缺口：知道有哪些文字，却不知道它们怎么被用。
> @source 全部来自对 `../../Rich4/rich4.exe` 的反汇编。

## 〇、读表口径（先看这一段）

1. **表头是机器读的，不是抄的。** 本文所有条目表（如 `0x476028`、`0x474a54`）由脚本从 `rich4.exe` 的 DGROUP 直接读出
   （`img.u32(table + i*4)` → `gen/strings.json` 的 `text`），并**断言每条 `sec == "DGROUP"` 且
   `trusted == true`**；任何一条不满足就中止生成。因此本文的「第 n 项是什么」不会有人工转录错误。
2. **「字符串指针表的起点」不等于「连续 ≥3 个指向字符串的 dword 的起点」。**
   `strings.json` 只收录它识别为串首的位置，指针若指向一个较长串的**中段**，该位置就不在表里，
   于是「连续串指针」扫描会从下一项才开始，把表的项数报少。本文用**代码里的实际基址**校正，
   共修正 3 张表的起点/项数（见 §一 `备注` 列与各表小节）。
3. 每个结论都带 `@source 0xADDR` 与汇编原文；无法坐实的写「**未决**」。

## 二、逐表详录

### 1. `0x476028`（99 项）+ 分组表 `0x4761b4`（8 条）

**用途**：这是**「說明 / help」界面的两级选单**。8 个主题分组，每组一页最多 8 项；
组标题取自池中的某个标签，正文来自 `help.mkf`（资源号 = 标签的 **1-based** 序号）。
`@source 0x44eb3c : push 0x466096 "help.mkf"`。

**语义已由「分组表字段全部在代码里被读到」坐实**：

```asm
; 分组记录 = 20 字节 { +0 标题, +4 标签表基址, +8 1-based首项号, +12 项数, +16 滚动偏移 }
; @source 0x44e0a3 —— 画组标题（只画一次）
0044e0a3  mov     ecx, dword ptr [eax*4 + 0x4761b4]   ; eax = 分组号×5，+0 = 标题
; @source 0x44e2d2 —— 画第 ebx 行标签
0044e2d2  mov     edx, dword ptr [0x476018]           ; 当前分组号
0044e2da  shl     eax, 2
0044e2dd  add     eax, edx                            ; eax = 分组号×5
0044e2df  mov     eax, dword ptr [eax*4 + 0x4761b8]   ; +4 = 标签表基址
0044e2e6  mov     edx, dword ptr [eax + esi*4]        ; 标签[esi]，esi = 滚动 + 行
; @source 0x44e30e —— 翻页判定
0044e30e  mov     esi, dword ptr [eax*4 + 0x4761c4]   ; +16 = 滚动偏移
0044e315  add     esi, ebx
0044e317  cmp     esi, dword ptr [eax*4 + 0x4761c0]   ; +12 = 项数
; @source 0x44e0fd —— 项数 > 8 才画卷动箭头
0044e0fd  cmp     dword ptr [eax*4 + 0x4761c0], 8
; @source 0x44e18d —— 正文资源号 = 1-based首项号 + 组内当前项
0044e18d  mov     eax, dword ptr [eax*4 + 0x4761bc]   ; +8 = 1-based 首项号
0044e194  add     eax, dword ptr [0x47601c]           ; 组内当前项
0044e1a1  call    0x450441   → mkf_read_resource
```

绘制宿主为 `sub_0044dfb4`（`@source 0x44dfb4`），重绘判定用 `0x476020`/`0x476024`
（上一帧的分组号/项号），`@source 0x44dfc7 : cmp eax, dword ptr [0x476024]`。

**项数与「101」的差异**：池真起点 `0x476028`，紧接 8 条记录（`0x4761b4 + 8×20 = 0x476254`）。
`0x4761b4` 是记录 0 的**标题字段**，`0x4761b8` 是记录 0 的**标签基址字段**（其值恰好 = `0x476028`）。
扫描器把这两个字段误算成池的第 100、101 项。池的**真实长度 = 99**，与分组表项数之和
`1+6+12+3+16+18+30+13 = 99` 完全吻合。

#### 3.1 星期段（池第 0–6 项）：索引 = `sub_004520a6` 输出的**星期几**

`sub_004520a6(打包日期, &星期几, &该月天数)`：

### 4. `0x475988`（24 项 = 两组各 12 项）

### 5+6. `0x475b38`（7 项状态标签）与 `0x475b54`（12 项购地播报）

**5. 状态标签（7 项）**：`索引 = 玩家结构 +0x0C 的状态码`（1..7）。
