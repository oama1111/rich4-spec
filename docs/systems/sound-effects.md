# 效果音（Sound Effects）

> @source 全部来自对 `../../Rich4/rich4.exe` 的实际反汇编（`gen/db.txt`）+ 对
> `Effect.mkf` 的机械扫描。可复核：`python3 tools/rich4strings.py find <VA>`、
> `grep -n '<VA>' gen/db.txt`。
>
> **本模块 100% 是机械可得的**：音效表、编号、播放调用点全部可从 exe 直接读出，
> 不依赖观感判断。这与「动效」「UI 布局」不同（那两者必须靠实机截图）。

## 一、数据结构：音效集（sound effect set）

音效**不是**按"编号→资源"的直接映射，而是分成若干**音效集**，
每个集合是一张 **8 字节记录**的表：

```
struct sound_entry {          // 8 字节
    uint32 mkf_resource_id;   // Effect.mkf 里的资源号
    uint32 dsound_buffer;     // 运行时填入的 IDirectSoundBuffer*（文件中为 0）
};
// 表以 mkf_resource_id == 0xFFFFFFFF 结尾
```

**证据**（`VA 0x00454186`，载入循环）：

```asm
00454186  mov  ecx, dword ptr [ebx]      ; entry.mkf_resource_id
00454188  cmp  ecx, -1                   ; ★ 终结符
0045418b  je   0x4541bd
0045418d  push 0 / push 0 / push ecx
00454192  mov  edi, dword ptr [0x48a058] ; _rich4_effect_mkf
00454199  call 0x450441                  ; read_mkf
004541a0  ...
004541a0  call 0x453dcf                  ; 建 IDirectSoundBuffer
004541a9  mov  dword ptr [ebx + 4], eax  ; ★ 写入 buffer 指针
004541b0  add  ebx, 8                    ; ★ 步长 8
004541b3  jmp  0x454186
```

载入后，该表的指针被登记进 **`_rich4_effect_slot_table`（`0x48cae8`）**，
共 **16 个槽**（`VA 0x004541c1`：`inc eax / cmp eax,0x10`），供退出时释放。

## 二、播放接口

### `play_sound_effect`（`VA 0x004542ce`，被调 **151 处**）

```asm
004542ce  push ebx
004542cf  mov  eax, dword ptr [esp + 8]    ; 第 1 参 = sound_entry*
004542d3  mov  edx, dword ptr [esp + 0xc]  ; 第 2 参
004542d7  push edx
004542d8  mov  ecx, dword ptr [eax]        ; entry.mkf_resource_id
004542da  push ecx
004542db  mov  ebx, dword ptr [eax + 4]    ; entry.dsound_buffer
004542de  push ebx
004542df  call 0x4540d8                    ; internal
004542e4  add  esp, 0xc
004542e7  pop  ebx
004542e8  ret
```

```
play_sound_effect(sound_entry *e, int arg)
    → internal_play(e->buffer, e->mkf_resource_id, arg)
```

**内部播放**（`VA 0x004542e9`）取 **COM 虚表偏移 `0x48`** 并调用 ——
即 `IDirectSoundBuffer::Play`：

```asm
004542e9  mov  eax, dword ptr [esp + 4]
004542ed  cmp  dword ptr [0x47e748], 0     ; _rich4_dsound_ptr
004542f4  je   0x454303
004542f7  mov  ecx, dword ptr [eax + 4]    ; entry.dsound_buffer
004542fa  test ecx, ecx
004542fc  je   0x454303
004542ff  mov  edx, dword ptr [ecx]        ; ★ COM 虚表
00454301  push ecx
00454302  call dword ptr [edx + 0x48]      ; ★ IDirectSoundBuffer::Play
```

> ⚠️ 与 `render-api.md` 记载的表面 blit 一样，这是 **COM 虚表调用**，
> 静态只能确定**偏移**（`0x48`），方法名按 DirectSound 7 的顺序推定。

### 另一条路径：运行时从 mkf 建 buffer

`VA 0x00454304`（`fcn_00454304(资源号)`）：`read_mkf(effect_mkf, 资源号)` →
`0x453dcf` 建 buffer → 存入 `_rich4_command_sound_effect_buffer`（`0x47e754`）
→ 释放原始数据。用于**按需播放单个音效**（而非预载整套）。

### 载入点核对（★ 已机械复核：19 张里 **16 张**有载入点，**3 张**没有）

**判定方法（可与 `gen/db.txt` 复核）**：`0x454176`（载入）与 `0x454240`（释放）
把**表基址当参数**收下，即 `push <表基址>`。于是「有载入点」等价于
「该基址作为立即数出现在某条 `push` 里」。一次性扫描即可复现：

```python
import struct, sys
sys.path.insert(0, 'tools'); import rich4dis as R
img = R.Image(R.EXE_DEFAULT); data = img.data
pushed = set()
for off in range(R.CODE_OFF, R.CODE_OFF + R.CODE_SIZE - 5):
    if data[off] == 0x68:                       # push imm32
        pushed.add(struct.unpack_from('<I', data, off + 1)[0])
# 然后逐个判断 19 个表基址是否 in pushed
```

### 属"内容推断"而非"代码证实"的 3 个基址

这 3 个不是代码 `push` 出来的，而是 §三 的扫描方法
（找 `0xFFFFFFFF` 终结符并回溯 `{id, 0}` 对）**推断**出来的，要区别对待：

**(a) `0x4754ba` —— ★ 确认是假阳性。** 该地址在代码里被当作**标量全局 dword 变量**
读写，**不是表基址**：

```asm
@source 0x00424b49
00424b49  mov  dword ptr [0x4754ba], ebx    ; 写入
00424b51  mov  eax, dword ptr [0x4754ba]    ; 读出
00424b78  mov  dword ptr [0x4754ba], eax
00424b91  mov  edx, dword ptr [0x4754ba]
```
⇒ §三 表里的「`0x4754ba` / 1 项 / 音效 0」**应从音效表清单中剔除** ——
它只是一块与终结符模式**凑巧同形**的普通数据。

**(b) `0x46cce0` —— 形状与已确认的 `0x46ccd0` 完全一致且紧邻其后**，是表的可能性较高，
但没有任何指令引用它：

```asm
; @source 0x0046ccd0（已被引用，确认是真表）
0046ccd0: 05 00 00 00 | 00 00 00 00 | ff ff ff ff | 00 00 00 00
          ↑ id=5        ↑ 0          ↑ 终结符      ↑ 补齐
0046cce0: 08 00 00 00 | 00 00 00 00 | ff ff ff ff | 00 00 00 00
          ↑ id=8   ← 形状完全一致，但**没有任何指令引用它**
```

**(c) `0x4762ec` —— 大片 0 字节中的孤立 `0xffffffff`**，极可能是误报：

```asm
; @source 0x004762e8 附近
004762e8: 00 c8 02 00 | 00 00 00 00 | 00 00 00 00 | ff ff ff ff
```
`0x4762f4` 处的 `0xffffffff` **确实被引用**（由 `0x004502fe` / `0x00450404` / `0x00450441` 读写），
但 `0x4762ec` 只是它前面 8 个 0 字节 ⇒ 扫描方法的**假阳性**。

**结论（不作猜测地陈述）**：音效表清单应记为 **18 张 / 63 项**
（从 19 张 / 64 项里剔除假阳性 `0x4754ba`），其中
**16 张有代码证实的载入点**；`0x46cce0` 与 `0x4762ec` 两张
**仅由内容推断、存在性未证实** —— 复刻时**不要**据此实现任何音效预载。

## 五、素材：`Effect.mkf`（★ 本轮已完全解明）

| 项 | 值 |
|---|---|
| `Effect.mkf` 大小 | 3,897,646 字节 |
| 解出资源数 | **115**（编号 **0..114**；`extracted/Effect/meta.json` 的 `nchunks = 115`） |
| 格式 | **PCM WAV，单声道、8 位、22,050 Hz（**99 个非空文件**全部一致）** |

### ★ 资源号 0..115 的完整分布（A 级，逐文件核对）

| 资源号 | 数量 | 内容 | 是否被音效表引用 |
|---|---|---|---|
| **0..63** | 64 | 真实 WAV | ✅ 60 个被引用；**6 / 30 / 42 / 59 未被引用** |
| **64..79** | **16** | **0 字节空资源（占位）** | ❌ 空，不可能播放 |
| **80..114** | 35 | 真实 WAV | ❌ **未被任何静态音效表引用** |

> ★ **计数修正**：早期写「116 个资源 / `64..80` 共 17 个空位」。实测（逐文件复核
> `extracted/Effect/`）应为 **115 个资源（0..114）**、空资源 **`0064..0079` 共 16 个**、
> 非空 **99 个**（64 + 35 = 99 ✓，64 + 16 + 35 = 115 ✓）。
> 差一的根因与 `speaking.mkf` 同型：**把解包产物 `meta.json` 也数成了资源**
> （目录下共 116 个文件 = 115 个 `.bin` + 1 个 `meta.json`）。
> 产物自带权威计数：`extracted/Effect/meta.json` 的 `nchunks = 115`。
> 复算命令：`ls extracted/Effect/*.bin | wc -l` → 115；
> `find extracted/Effect -name '*.bin' -size 0 | wc -l` → 16。

**这彻底解答了「115 个资源为何只用到 0..63」**：
- `64..79` 是**空占位**（文件长度 0）—— 原版预留但未填入；
- `80..114` 是**真实但未静态引用**的资源 —— 要么经**运行时计算的编号**播放，
  要么是残留资源。本文件只扫描了**静态表**，未穷尽动态路径。

> ⚠️ 早期版本在这里写"64..115 未被任何音效表引用，可能经动态编号"
> —— 方向对，但**漏了 64..80 是空文件**这一关键区分。现已逐文件核实。

### 音效编号 → 资源号是**恒等映射**（A 级）

`VA 0x00454186` 的载入循环里，`entry.mkf_resource_id` **直接**作为
`read_mkf` 的第二个参数（`push ecx`），故**编号就是资源号**，无偏移换算。

## 七、复刻要点

1. **音效集是"按界面预载"的**，不是一次载入全部。复刻若改成"用哪个载哪个"，
   行为上可能听不出差别，但**内存占用与首次延迟**会不同；
   若改成"全部预载"，则 99 个非空 WAV 全进内存（原版不是这样）。
2. 每张表**以 `0xFFFFFFFF` 结尾**，载入循环靠它停 —— 复刻不可用固定项数替代。
3. `entry.dsound_buffer` 字段在**存档与文件中恒为 0**，是运行时填充的；
   任何"从文件读表"的路径都必须重新建 buffer。
4. 音效**没有音量参数**：`play_sound_effect` 只传 entry + 一个未定语义的参数，
   音量由 DirectSound 全局控制（`0x4548ef` 的 `auxSetVolume`/`midiOutSetVolume`）。
