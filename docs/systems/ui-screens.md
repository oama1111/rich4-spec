# 各屏内部绘制函数（表现层 · 阶段 1 收口）

`@source` 本文件全部结论以 `Rich4/rich4.exe` 反汇编（`gen/db.txt`）为准；每条结论的地址都可用 `grep -n '<VA>' gen/db.txt` 复核。

> **这份文件回答什么**：`ui.md` 讲的是输入架构、窗口消息路由、模态界面与导航；
> 本文件补齐**每一屏内部**那些绘制 / 版式 / 命中函数——它们在原版里是
> `0x40xxxx`–`0x44xxxx` 段里成百上千个小函数，此前 PRD **一次都没提**，
> 知识只存在于复刻代码的注释里。
>
> **为什么现在补**：阶段 1 的收口工作单 `tools/audit_prd_gaps.py` 曾报出
> **106 个函数 / 13,861 字节**属于「remake 已经引用过、PRD 未收」。本文件收掉其中
> **103 个**（全部在 `client/`），另外 3 个分别落进 `game-loop.md`（`0x40d4e5`）
> 与 `cards.md`（`0x446457` / `0x4464c3`）。收完后该工作单应为 **0**。

## 证据等级（本文件统一口径）

| 级 | 含义 |
|---|---|
| **A** | **exe 逐字**：结论能指回 `gen/db.txt` 里该地址的指令，或能指回一张表 / 全局的地址 |
| **B** | 由 A 级事实**直接推出**（括注推的是哪条 A 级事实）|
| **C** | 只有 remake 侧注释转述、**本轮未回 exe 复核**——当真值用之前必须复核 |

> ⚠️ 真值只有 `Rich4/rich4.exe`。`rich4-remake` 的注释是**线索**，不是真值；
> 本轮已抓到 **多处**「remake 注释与 exe 冲突」，全部记在各自小节的未决里，
> **没有替 remake 圆场**。

## 方法（可复算）

1. 工作单：`python3 tools/audit_prd_gaps.py`（按「提到它的 remake 文件」归组）。
2. 逐函数档案：`python3 tools/scratch/prd_gap_pack.py` —— 每个 VA 一段：
   汇编前 40 条 + callees（带名）+ `push` 的字符串 + 触碰的全局 + remake 引用上下文。
3. 分组：`python3 tools/scratch/split_gap_groups.py` → `tools/scratch/gap-g*.txt`。
4. 复核：本节所有地址都能用 `grep -n '<VA>' gen/db.txt` 在 `db.txt` 里找到
   （例：`grep -n '0x42d977' gen/db.txt` → 第 53864 行的函数头 + 176 条指令）。

`@source` 本文件的代码地址全部落在 `0x401000`–`0x462000`（AUTO 段），
数据表地址落在 `0x463000`–`0x48A000`（DGROUP 段）；两者边界见 `gen/layout.json`。

> **权威副本**：本文件。各节的初稿（并行子代理产出）留在
> `tools/scratch/drafts/`（`_head.md` / `g1.md`…`g5.md` / `_tail.md`），
> 仅供追溯「哪一段是谁写的、当时的未决是什么」，**内容以本文件为准**
> （初稿落盘后本文件又补过 `@source` 段落，两者已不逐字相同）。

#### `0x42d977` 定时器：变脸 / 气泡 / 窗口状态机（656B）

- 入口第一笔就是一次 `blitRect`（`0x4563f5`）——remake 记作「那几张变脸帧走 `fcn_004563f5`，
  **不带透明**，所以换一张就等于把上一张盖掉」（@source 0x42d977；remake 注见 `shop-screen.ts:337`，C）。
  它跑在跳表 `0x42d36b` 的落点上（`loc_0042d87e` 那 5 项，remake 注，C），窗口过程本身是 `0x0042d37f`（`shop-screen.ts:8`）。
- 之后 `[0x48a0e0]` 的 vtbl `+0x80`，接 `push 0 / lea eax,[esp+0x44] / push eax / push edi`（BeginPaint 口径），
  再 `InvalidateRect`（`cs:[0x4622f8]`）。
- `add dword ptr [0x48c32f], 0x10`：**相位推进 16**。remake 把 `[0x48c32f]` 的 bit 8–11 当「上一帧画的脸」
  （`shop-screen.ts:345`，C）；A 级可见的是「每拍 +0x10」。
- `call 0x44ee18`（气泡；同一个 VA 在 pack 里能看到 `timeGetTime` 与 `0x7d0`=2000ms 的比较，说明它就是气泡的到点判断）
  → `test eax,eax / je 0x42dc36`：**返回 0 就直接走出口、不跑下面的状态机**，非 0 才继续。
- 状态机读 `[0x48c318]`：`cmp eax,2 / jb`、`jbe`、`cmp eax,4 / je` —— 可用值 **0 / 2 / 4**：
  `0` → `PostMessageA(hwnd, 0x40c, 0, 0)` 且 `[0x48c318] = 1`；`2` → `[0x48c318] = 3`、
  `byte ptr [eax + 0x48c349] = 1`（eax = `[0x48c310]`）、`push 1 / call 0x402460`；`4` → `loc_0042dc0f`。
  callee 里另有 `USER32!KillTimer`、`rand15`、`sub_0044ef3b`、`sub_00402460`（@source 0x42d977 的 callee 表）。
- remake 补的第二处动画（C；remake 记 `loc_0042dc4c` —— **该地址在 pack 的 callee 表里**，`[0x48c314]` 在 globals 表里）：
  由 `[0x48c314]` 那个倒数器驱动，倒到 0 先画基准帧（图 9 / 图 25），
  随后有 `rand()>>11 < 4`（约 1/4）的机会换成图 10/11 或 26/27，并把倒数重置成 `rand()&7`（抽到 0 就取 1）。
- 落点（C，`shop-screen.ts:355-363`）：卡片页脸 `0x195/0x3c`、嘴 `0x195/0x5b`；道具页 `0x1a1/0x32`、`0x1a1/0x59`
  （remake 记 `loc_0042d911` / `loc_0042dcc0` / `loc_0042d9c6` / `loc_0042dd6e`；其中**只有 `loc_0042dcc0` 与
  `loc_0042dd6e` 在 pack 的 callee 表里**，另两个本轮没有 exe 依据）。

#### `0x44e668` 右列 8 行的逐行命中（131B）

- `[0x476018]` → `eax = 20*章号`（`shl 2 / add / shl 2`），项基址 `0x4761b4`。
  `edx = [eax+0x4761c4]`（= `entry+0x10`，当前偏移）`+ 8` 与 `ecx = [eax+0x4761c0]`（= `entry+0x0C`，资源数）比：
  够 8 则 `ebp = 8`，否则 `ebp = 资源数 − 偏移` —— **可见行数上限 8**。
- 循环（`eax` = 行号 i）：`cmp esi,0x6c / jl` → `esi` 是**局部 x**，须 ≥ 108；`cmp esi,0xc1 / jge` → 须 < 193；
  `edx = 34*i`（`shl 4 / add / add edx,edx`）；`ecx = 34*i + 0x4e`、`cmp ebx,ecx / jl`、`edx += 0x6f`、`cmp ebx,edx / jge`
  → `ebx` 是**局部 y**，须落在 **[78+34i, 111+34i)**。
- 命中即 `[0x47601c] = i + [entry+0x10]`，再 `jmp 0x44e65e`（重画）；没命中 `inc eax` 看下一行。
- 与 remake 的数据模型对得上（C/B 交叉，@source 0x44e668 的 `0x4e`/`0x6f`/`0xc1`）：右列 8 行格图的行距 **34**、落点 `(108, 78+34i)`、
  分项名 `(150, 94+34i)`（`help-screen.ts:44`）——命中框 x∈[108,193) 正是那张 85 宽的格图那一列。
- ⚠️ 本条与 remake 注释「条目 1（上一章 / 下一章）= `loc_0044e668` / `loc_0044e881`」**不符**：asm 里这是
  位置命中 + 写行偏移，没有碰 `[0x476018]`。见「未决」。

#### `0x44e6eb` 共用「贴按下图」+ `0x44e881` 退一屏（182B / 195B）

- `0x44e6eb` 开头：`[entry+0x0C] <= 8` 就 `jle sub_0044e586`（**一章不足两屏就没有可滚的**）。
- 然后 `eax = [0x48c5fc] << 4`，四次「`[0x48c5e4/0x48c5e8] + [eax+0x476254..0x476260]`」取

#### `0x4312d8` / `0x431383` —— 槽 3 / 槽 4 贴片（**2026-09-19 新增，A 级**）

这两支是 `0x4300f8` 表的第 3 / 第 4 项（= 槽 3 / 槽 4）。
`docs/coverage-by-function.md` 只收过 `0x431383` 一条（并把它记作「脸的**第 5 槽**」

逐条读完后确认它们与前两支**同族但机制不同** —— 不是"照抄槽 1/2"，所以单列：


**三条与槽 1/2 的实质差别**（都影响复刻）：

1. **不查帧表、不推进帧**。槽 1/2 是 `图号 = byte[0x475663 + 帧段]` / `byte[0x475667 + 帧段]`
   再 `[0x48c350] += 0x10` / `+= 0x100`；槽 3/4 **直接**用 `9+硬币` / `14+硬币` 当图号，
   **且一个字节都不加**。
   ⇒ ★ 这同时**结清了旧的「未决 #2」**：remake 记的「槽 3 = `+10` → `9,10`、槽 4 = `+12` → `14,15`」
   **是对的**，而且它根本不是"查表"结果，是**字面图号**；旧表以为要去 `0x475660` 里找，
   才会看到 `+10` 处是 `15,31` 而对不上。
2. **帧段只有 1 位**。槽 1 = bits[7:4]、槽 2 = bits[11:8]（各 4 位），
   而槽 3 = **bit 12**、槽 4 = **bit 13**（`and 0x1000 / sar 0xc`、`and 0x2000 / sar 0xd`）。
   ⇒ ★ 部分结清「未决 #1」的位布局一侧：**14 位**用完（bits[3:0] 槽号 + bits[13:4] 帧），
   `[0x48c350]` 的高 18 位未用。
3. **不置播完位**。槽 1 收尾 `or byte [0x48c351],0x10`、槽 2 `or ...,0x20`
   （⇒ ★ 播完位在 **`0x48c351`**：槽 1 = bit 4、槽 2 = bit 5）；槽 3/4 **没有这一步**，
   两支都直接落进公共尾 `0x43142a`。语义：槽 3/4 是**持续掷硬币换贴片**的展示，
   没有"播完"这个状态。

**关于低 nibble 的表示（是表示差异，不是行为偏离）**：remake 的 `FACE_SLOT_BIT = [0,1,2,4,8]`
把低 nibble 当成**位掩码**，而 exe 的 `0x431117` 四处写的是
`or al,1` / `or al,2` / `or al,3` / `or al,4`
@source 0x43112c / 0x43113d / 0x431146 / 0x431153 ——
**存的是槽号 1..4 本身，不是位**（槽 3 在 exe 里存 `3`、remake 存 `4`）。
但两者**用途一致**：这个 nibble 的唯一读者是分派器
`0x431104 and eax,0xf / cmp eax,4 / jmp [eax*4+0x4300f8]`，
它要的正是「槽号 0..4 当数组下标」。
⇒ 复刻没有照抄这个 nibble，而是**自己维护槽号**；若将来要逐位复现原版内存，
才需要改成"存槽号"。**当前不是行为偏离**。

叙述：

- **四个「逐槽停」的状态（`0x43f55f` / `0x43f57f` / `0x43f59f` / `0x43f5bd`）是同一张模板**，
  只有两个操作数不同，把它们并排看就一眼看穿：

  ```asm
  ; 0x43f55f（状态 4 → 5）        0x43f57f（状态 5 → 6）        0x43f59f（状态 6 → 7）        0x43f5bd（状态 7 → 8）
  0043f55f push 1                 0043f57f push 2                 0043f59f push 3                 0043f5bd push 4
  0043f561 push 0xf               0043f581 push 0xe               0043f5a1 push 0xc               0043f5bf push 8
  0043f563 push ebp               0043f583 push ebp               0043f5a3 push ebp               0043f5c1 push ebp
  0043f564 call 0x43ef3e          0043f584 call 0x43ef3e          0043f5a4 call 0x43ef3e          0043f5c2 call 0x43ef3e
  0043f569 cmp eax, 1             0043f58c cmp eax, 1             0043f5ac cmp eax, 1             0043f5ca cmp eax, 1
  0043f56f jne 0x43f709           0043f58f jne 0x43f709           0043f5af jne 0x43f709           0043f5cd jne 0x43f709
  0043f575 mov esi, 5             0043f595 mov esi, 6             0043f5b5 lea esi,[ebp+7]        0043f5d3 mov esi, 8
  ```

  ⇒ 每个状态的三个实参就是 **`(槽号, 剩余位数的掩码, 第几槽)`**：`(1, 0xf)` → `(2, 0xe)` → `(3, 0xc)` → `(4, 8)`，
  掩码从 `0xf` 逐次抹掉一个 bit（`0xf → 0xe → 0xc → 8`），**这就是「从左往右逐槽停」的写法**。
  `cmp eax,1 / jne 0x43f709` 是「**这一槽没停稳就直接回主循环**（不改状态）」，
  停稳才把下一状态写进 `esi` 并同样跳 `0x43f709`（本帧末尾统一提交）。
  @source `0x43f55f`、`0x43f57f`、`0x43f59f`、`0x43f5bd`、`0x43f56c`、`0x43f58c`、`0x43f5ac`、`0x43f5ca`；

  ```asm

  0041e15a mov edx,[0x48be4c]                        0041e191 mov edx,[0x48be4c]
           shl eax,2 / sub eax,edx / add eax,eax              shl eax,2 / sub eax,edx / add eax,eax
  0041e169 mov cl,[eax+0x48be38]                     0041e1a0 mov dh,[eax+0x48be38]
  0041e16f cmp cl,0xa       ; > 10 才减              0041e1a6 cmp dh,0x5a      ; >= 90 即跳
  0041e172 jbe 0x41e184     ; ≤ 10 → 走归 0 那一支   0041e1a9 jae 0x41e1bb     ; ≥ 90 → 走归 100 那一支
  0041e174 mov dl,cl / sub dl,0xa                    0041e1ab mov bh,dh / add bh,0xa
  0041e179 mov [eax+0x48be38],dl                     0041e1b0 mov [eax+0x48be38],bh
  0041e17f jmp 0x41e2a8                              0041e1b6 jmp 0x41e2a8
  ```

  ⇒ 两条是**互补的、互相封顶的**：左边 `≤ 10` 直接写 0，右边 `≥ 90` 直接写 100；

  注意**原版没有用 clamp，是两条非对称的哨兵分支**（`≤10`/`≥90` 时直接归 0/100）——
