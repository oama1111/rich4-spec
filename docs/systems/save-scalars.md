## 二、逐个说明

### 2.1 定名的钥匙：`0x406de7` = 新局/读档后的全局初始化

`0x406de7` 被 `0x401cd0` 在「开始游戏」分支里调用（`0x401cbf mov word[0x4991b6],1` 之后），
函数内先读设置缓存 `0x46cb3c`，再弹设置对话框 `0x404e44`，最后把设置摊平成运行时全局。
**30 个地址里有 13 个在这一处定名。**

```asm
; @source 0x406de7 —— 读档分支先把存档里的设置搬进设置缓存
00406f6b  mov     eax, dword ptr [0x499118]
00406f70  mov     dword ptr [0x46cb44], eax
00406f75  mov     eax, dword ptr [0x499110]
00406f7a  mov     dword ptr [0x46cb48], eax
00406f81  mov     edi, dword ptr [0x49911c]
```

### 2.2 `0x49908c` / `0x499108` / `0x499110` / `0x499118` / `0x49911c` / `0x499114`
#### —— 六个「开局设置」，由设置界面文字 + 3 张数值表双重锁定

**决定性证据是设置界面的绘制代码**：6 行标签和 6 个取值一一对应，行号（y）与取值表都写在同一条指令序列里。

```asm
; @source 0x40458c..0x404631 —— 设置界面的 6 个标签
00404595  push    0x463138   "遊戲人數"
004045b2  push    0x463141   "總 資 金"
004045cf  push    0x46314a   "行進方式"
004045ec  push    0x463153   "土地權限"
00404609  push    0x46315c   "遊戲時間"
00404625  push    0x463165   "勝利條件"

; @source 0x4046f5..0x40478c —— 6 个取值（y 与标签同排）
004046f7  push    0xe4                          ; y=遊戲人數
00404701  mov     eax, dword ptr [0x46cb3c]
00404706  mov     ebp, dword ptr [eax*4 + 0x46cb88]   ; 0x46cb88 -> "二人/三人/四人"
00404746  push    0x150                         ; y=土地權限
00404750  mov     eax, dword ptr [0x46cb48]     ; = [0x499110]
00404755  mov     ebx, dword ptr [eax*4 + 0x46cbb8]   ; "無限期/二年/一年/六個月/三個月/一個月"
0040476e  push    0x174                         ; y=遊戲時間
00404778  mov     eax, dword ptr [0x46cb4c]
0040477d  mov     edi, dword ptr [eax*4 + 0x46cbd0]   ; 同一组 6 个字符串
0040471e  push    0x12c                         ; y=行進方式
00404728  mov     eax, dword ptr [0x46cb44]     ; = [0x499118]
0040472d  mov     edx, dword ptr [eax*4 + 0x46cbac]   ; "步行/機車/汽車"
```

字符串取自 exe（CP950，用 `../tools/rich4strings.py` 之外的直接解码复核）：

| 表 | 内容 | 对应全局 |
|---|---|---|
| `0x46cb88` | 二人 / 三人 / 四人 | `0x499114`（人数） |
| `0x46cb94` | 300000 / 200000 / 100000 / 50000 / 30000 / 10000 | `0x49908c`（开局资金） |
| `0x46cbac` | **步行 / 機車 / 汽車** | **`0x499118`（行进方式）** |
| `0x46cbb8` | 無限期 / 二年 / 一年 / 六個月 / 三個月 / 一個月 | **`0x499110`（土地权限）** |
| `0x46cbd0` | 無限期 / 二年 / 一年 / 六個月 / 三個月 / 一個月 | `0x49911c`（游戏时间，表 `0x46cbe8` = 0/730/365/182/91/30 天） |
| `0x46cc00` | 0 / 100 / 50 / 10 / 5 / 3（× 开局资金） | `0x499108`（胜利条件金额） |

* **`0x499118` = 行进方式**。旁证：`0x406de7` 把它写进 `player[].+0x11 (0x496b79)`，
  即 `news.md`/`fortune.md` 已独立命名的 `traffic_method`（"步行"=0 才命中的新闻、
  "降级为步行"的命运事件都读这个字节）：

  ```asm
  ; @source 0x407219 —— 行进方式 → player[].+0x11，非步行还要扣一个库存
  00407219  mov     dl, byte ptr [0x46cb44]
  0040721f  mov     byte ptr [eax + 0x496b79], dl
  00407225  test    dl, dl
  00407227  je      0x407236
  00407229  mov     al, dl
  0040722b  and     eax, 0xff
  00407230  dec     byte ptr [eax + 0x497323]        ; 0x497320[3+档位] -= 1（機車/汽車 库存）
  ```
  非零档位对应 `0x497320[4]`/`0x497320[5]` —— 正好是「機車 / 汽車」两种道具的库存。

* **`0x499110` = 土地权限（地契年限）**。它在 4 处被用来算「土地权限到期日」，
  偏移表 `0x4751f0` = `{0, 2年, 1年, 6個月, 3個月, 1個月}`（打包日期，与 `0x46cbe8` 的天数同义）：

  ```asm
  ; @source 0x44244b（同样的三处：0x40f718、0x4198b9 内、0x43c788）
  0044244b  mov     edx, dword ptr [0x499110]
  00442451  test    edx, edx
  00442453  je      0x44246f                   ; 0 = 無限期 → 不写到期日
  00442455  mov     ecx, dword ptr [edx*4 + 0x4751f0]
  0044245c  push    ecx
  0044245d  mov     ebp, dword ptr [0x497160]
  00442463  push    ebp
  00442464  call    0x4521cb                   ; date_today(今天, 期限) → 到期日
  0044246c  mov     dword ptr [ebx + 0x30], eax ; 写进地产记录 +0x30
  ```

* **`0x49911c` = 游戏时间上限（天）**，`0` = 无限期。`0x41d89e` 用它做**游戏结束判定**：

  ```asm
  ; @source 0x41d8ed..0x41d915
  0041d8ed  mov     edx, dword ptr [0x49911c]
  0041d8f3  test    edx, edx
  0041d8f5  je      0x41d8ff
  0041d8f7  cmp     edx, dword ptr [0x4990e4]    ; 期限 ≤ 已过天数 ⇒ 强制结算
  0041d8fd  jle     0x41d915
  0041d8ff  mov     ebx, dword ptr [0x499108]    ; 胜利条件金额
  0041d905  test    ebx, ebx
  0041d907  je      0x41da5a                     ; 0 = 无限 → 不因钱结束
  0041d90d  cmp     edi, ebx                     ; edi = 全场最高总资产（0x4239b9 求得）
  0041d90f  jl      0x41da5a
  0041d915  mov     dword ptr [0x49910c], esi    ; 结束：定位到获胜者
  ```
  `edi` 的来源见同函数 `0041d8d6 call 0x4239b9`（取该玩家总资产）与 `0041d8e2 mov edi,eax`（取最大）。

* **`0x499108` = 胜利条件金额**（= 开局资金 × 100/50/10/5/3，`0` = 无限）。
  `0x4046a2 imul eax, dword ptr [edx*4 + 0x46cc00]` 是设置界面里对同一公式的复算，
  金额为 0 时显示字符串 `0x463171 "無限"`。

* **`0x499114` = 玩家人数**。`0x406f44 sub eax,2 / 0x406f47 mov [0x46cb3c],eax` 与
  `0x40715c add eax,2` 互为逆运算，锁定「设置缓存 = 人数 − 2」。

### 2.3 `0x499104` = **人类玩家数**

```asm
; @source 0x407166..0x407250 —— 新局时统计
00407166  mov     dword ptr [0x499104], edi     ; edi=0，先清零
...
00407247  test    byte ptr [eax + 0x496bcc], 1  ; player[i].+0x64 为奇
0040724e  je      0x407265
00407250  inc     dword ptr [0x499104]          ; ★ 计数
; @source 0x4072ec —— +0x64 的赋值：1 = 人类(值≥0)，2 = 非人类(值<0)
004072ec  mov     eax, dword ptr [edi + 0x48a35c]   ; edi = i*12，角色选择结果
004072f2  sar     eax, 0x1f
004072f5  and     eax, 1
004072f8  inc     eax                                ; 0→1 / -1→2
004072f9  mov     byte ptr [esi + 0x496bcc], al
```

行为旁证（三处互相独立，都与「人类玩家 ≥ 2 才需要交接」一致）：

```asm
; @source 0x4061fa —— 派生出「多人」标志
004061fa  mov     edi, dword ptr [0x499104]
00406200  cmp     edi, 1
00406203  setne   al
00406206  mov     byte ptr [0x48a435], al
; @source 0x411ae0 —— 回合结束后把控制权交给下一个人类玩家
00411af1  cmp     dword ptr [0x499104], 1
00411af8  jle     0x411b43                      ; 单人 ⇒ 不交接
00411b1f  mov     dword ptr [0x49910c], eax     ; eax = 0x4339d9(当前玩家)-1 = 下一个
; @source 0x41d96e —— 单人局的结算分支
0041d96e  cmp     dword ptr [0x499104], 1
0041d975  jne     0x41da3c
```

> ⚠️ **`[0x499104]` 与 `player+0x64` 的一致性在 Save0 上不成立**（2026-09-17 实测）：
> Save0 的 `[0x499104]` = **2**，但四名玩家 `+0x64` 里只有 **1** 个奇数（`0,1,0,0`）；
> SAVE1 两者都是 1（`1,2,2,2`）。⇒ 要么游戏中途有人改过 `+0x64`
> （只有 `0x4072f9` 一处绝对写者，扫 `[reg+0x64]` 形式也未命中玩家记录），

### 2.17 玩家记录里三个「派生 / 瞬时」字段：`+0x00`、`+0x04`、`+0x1b`、`+0x4a`、`+0x64`

复刻写档器在玩家块 `0x0010`（4 × 0x68）上最后剩下五个「状态里没有对应字段」的字节组。
逐个查清后分成**三类**（这决定了它们在复刻里该不该成为 `GameState` 字段）：

#### (a) `+0x00`、`+0x04` = **角色表的常量**（不是状态）

```asm
; @source 0x4072c3..0x4072e9 —— 新局：整条玩家记录 = 角色表项的拷贝
004072cf  mov  eax, dword ptr [edi + 0x48a35c]  ; [0x48a35c + 玩家×12] = 角色选择记录
004072d5  and  eax, 0xff                         ; 低字节 = 角色编号
004072da  imul eax, eax, 0x68
004072dd  add  eax, 0x47e80c                     ; &character_profiles[角色]
004072e4  call 0x456de8                          ; ★ memcpy(player, &profiles[ch], 0x68)
```
```asm
; @source 0x402b9a..0x402bae —— 读档：+0x00 由角色编号重新推导，文件里的值被丢弃
00402b9f  mov  dl, byte ptr [eax + 0x496b7b]     ; player.character (+0x13)
00402ba8  mov  edx, dword ptr [edx + 0x47e80c]   ; profiles[ch].+0x00 = 名字串指针
00402bae  mov  dword ptr [eax + 0x496b68], edx   ; ★ 覆盖
```

- `+0x00` = **名字串（Big5）的 4 字节指针**。它是**进程地址**，存档里的值跨进程无意义，
  原版自己读档后就用 `character` 重算。⇒ 复刻**不应**把它当状态字段。
- `+0x04` = **代表色**（`0x00RRGGBB`）。全 exe 的绝对写者**为空**
  （`0x496b6c` 只被 `0x40829d` / `0x40a4e1` / `0x415f69` / `0x4166f8` 读），
  来源就是上面那次整记录 memcpy。⇒ 同样由 `character` 查表得出。
- **两份真实存档 8/8 逐位吻合**（Save0/SAVE1 × 4 名玩家），见
  `rich4-remake` 的 `save-writer.test.ts`「carry 清零后玩家块 +0x00/+0x04 仍与原文件相等」。

#### (b) `+0x1b` = **移动前的朝向备份**，`+0x4a` = **本次移动的目标节点**

```asm
; @source 0x40d5a5 —— 签名是 (玩家, 原节点, **設施号**)：把住店的玩家挪到**旅館設施**上
;   （全 exe 唯一调用点 0x41a85e，就在旅館落点那一支；第三参不是"目标节点"—— 见下）
0040d61b  mov  byte ptr [ebx + 0x496b83], cl    ; ★ +0x1b ← 移动前的 +0x10（朝向）
0040d643  mov  byte ptr [ebx + 0x496b78], al    ;    +0x10 ← atan2(設施−自己)（新朝向）
0040d6b3  mov  word ptr [eax + 0x496bb2], dx    ; ★ +0x4a ← **設施号**
; @source 0x40d68e —— 另一支（瞬移）：+0x1b ← 当前玩家的朝向
```

★★ **第 88 条把 `0x40d5a5` 整支跑通了**（`rich4-spec/tests/test_relocate_to_facility.py` 22/22），
两条分支与三处以前写错/没写的地方：

| 条件 | 做什么 |
|---|---|
| **支 A**：`nodeId == 原节点` **且** 他就是当前玩家 | `+0x15 \|= 0x20`（`WHO_PLAYS_RELOCATED`，回合推进函数 `0x418f07` 见到就**整回合跳过**）；`+0x1b ← 原 +0x10`；`+0x10 ← atan2(設施x − 玩家x, 設施y − 玩家y)`；`call 0x40dd1f`（**真正的挪动/动画在它里面**）⇒ 本函数**一个字都不写 x/y/nodeId** |
| **支 B**：其余（不是当前玩家，或已不在原节点上） | **原地瞬移**：`x/y ← 設施记录 +0x00/+0x02`、`nodeId/lastNodeId ← **当前玩家**的`、`+0x1b ← 当前玩家的 +0x10`，随后 `call 0x40b93b`（重画）与 `call 0x40fc00`（跟班物件同步所在格）|
| 两支都做 | 清**旧格**的节点占用位（`~(0x100<<idx)`）＋ 公共尾 `+0x4a ← 設施号` |

⚠️ 由此订正两处旧说法：
① `+0x4a` 不是"目标**节点**"，而是**設施号**（`0x40c101` 那个读者拿它去查設施表）；
② `x/y` 在住店期间同样**不等于所在格坐标** —— 与关押是同一种机制
（原版 `x/y` 是**贴图位置**，`nodeId` 才是逻辑所在格，见 `rules/position.ts` 的例外）。
- `+0x1b` 紧挨着 `+0x10`（朝向）被读写，且**被关押/住院路径写成 `0x0f`**
  （`@source 0x43d637` / `0x43ece3`：`mov byte ptr [ebx + 0x496b83], 0xf`），
  读者只有 `0x418f2e`（`mov bl, byte [eax + 0x496b83]`）。
- `+0x4a` 的唯一读者是行走函数 `0x40c101`（`movsx edx, word [eax + 0x496bb2]`）。
- 两者都是**一次移动内的瞬时量**：remake 的移动是**原子**的（没有"动画中途"这一状态），
  故它们在复刻里**没有对应的持久字段**，写档时保持 carry 是诚实的。

#### (c) `+0x64` = 新局时的「人类 / 非人类」标志 —— 但**样本与不变量冲突，未决**

`@source 0x4072ec` 的赋值式（见 §2.3）是 `((选择记录 >> 31) & 1) + 1`，即
**奇数 = 人类**；`0x407247 test al,1` 正是用它数人类数。但实测：

| 存档 | `[0x499104]`（人类数） | `+0x64` 各玩家 | 奇数个数 |
|---|---|---|---|
| Save0 | **2** | `0, 1, 0, 0` | **1** |
| SAVE1 | 1 | `1, 2, 2, 2` | 1 |

⇒ **Save0 上两者不一致**（`[0x499104]`=2 而只有一个奇数）。只有 `0x4072f9`
一处绝对写者，扫描 `[reg+0x64]` 形式的写也未命中玩家记录，所以「谁在游戏中途改了它」
**未决**。⇒ 复刻**不写** `+0x64`（保持 carry），也不允许用 `+0x64` 反推 `[0x499104]`。

★ 顺带把**旁边两格**查清了（第 36 条，同一轮）：`+0x66`/`+0x67` 是
**夢遊卡的「睡前移动方式 / 骰子数」备份**（`@source 0x4441dc` 的两条

## 三、仍未定名的（明确列出，附已排除哪些可能）

### 3.1 `0x499078` / `0x49907c` 的**用途**未决

> @source `0x4294bc`、`0x4294c7`、`0x40746d`、`0x407478`；读者清单取自 `gen/xrefs.json` 的 `read_by`（已用 `gen/db.txt` 逐条复核）。

* 已确认（数值层面）：`0x499078 = trunc(Σ12 支现价 × 10.0f)`（`0x4294bc`/`0x4294c7`），
  `0x49907c = trunc(Σ12 支初始价 × 10.0f)`（`0x40746d`/`0x407478`）。
* **未决**：谁消费它们。全库对这两个地址的引用只有
  `0x402ac5`（读档）、`0x402fd1`（存档）、`0x44808a`/`0x448544`（快照/还原）
  —— **没有任何逻辑读取**。
* 已排除的可能：
  1. **不是**「股市指数显示缓存」—— 全库找不到「指數/大盤」字样的股市 UI 字符串
     （只有 `0x4638f5 "物價指數  %d"` / `0x465de4 "物價指數"`，对应的是 `0x4990e8`）。
  2. **不是**涨跌停判定输入 —— 涨跌停用的是 `stock+0x10/+0x14` 与 `0x463fe8` 等常量，
     不读这两个地址。
  3. **不是**分红/企业总值的输入（`0x42f000`~`0x431000` 区间不读它们）。
* 需要 Unicorn 差分（改这两个值看渲染/逻辑是否变化）才能定案。

### 3.2 `0x4990f4` 的值 `4` 的精确时序未决

* 已确认：`0`＝未參戰、`1`＝人類玩家、`2`＝電腦/已出局（`0x40423c` 的三分支 + `0x40cf30`）。
* **未决**：`4` 到底是「角色選擇畫面裡『已確定參戰』」還是「電腦已預定」。
  依据是 `0x404340 mov byte[ebx+0x4990f4], 4` 位于 `dl==2`（電腦）分支的末尾，
  而 `0x406de7` 又把 `4 → 2`。两种读法都与现有指令吻合，静态不可裁决。
* 已排除：`4` **不是**「未使用槽」—— `0x404f65` 把**非 0** 一律记为「已占用」，
  若 `4` 表示空槽则角色数永远算错。

### 3.3 `0x4991b6` 的精确编码未决（「剧本/阶段」的取值域）

* 已确认：它是 word，且与 `0x4991b8` 合成资源索引 `4 × b6 + b8`
  （`0x406e3a`、`0x4075f6`、`0x407af0`），并且 `0x401cbf` 在一种开局模式下写 1。
* **未决**：除 0/1 外是否还有其他取值，以及它到底是「第幾套地圖」还是「遊戲模式」。
  `fortune.md` §5 的「`0x4991b8 != 0` 会越界」之所以不成立，是因为
  **越界只发生在 `b6`，与 `b8` 无关**：`0x475ef0`/`0x475fb4` 两张表有 49 项（0..48），
  而 `v + 4×b8`（`v ≤ 36`，`b8 ≤ 3`）最大 48，正好落在表内 —— 见 §四。

### 3.4 已排除的「伪未决」

任务背景里把 `0x44808a` 当成「新游戏/重置全部状态」，实测是**状态快照到 `0x48cb80`**
（§一 末尾的注释）；它只搬运、不给初值，因此**不能**用它定名。真正的初始化是 `0x406de7`。
